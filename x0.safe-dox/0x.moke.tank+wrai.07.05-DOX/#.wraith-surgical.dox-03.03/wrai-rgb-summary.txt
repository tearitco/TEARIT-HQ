# WRAITH RGB MIRROR: THE REALITY REPORT
Date: 2026-06-17
Status: VERIFIED REALITY (V1)

## "IS IT REAL OR TOO GOOD TO BE TRUE?"
It is **100% Real**. There is no "smoke and mirrors" or hardcoded overlay. The pixels you see in the GL window are being generated char-by-char from the ASCII shell.

## HOW IT WORKS (THE PLUMBING)
The magic happens in the **Middle Fork (wraith_rgb_daemon)**. Here is the step-by-step reality:

1.  **Sovereign Assets**: The daemon loads 95 individual `.txt` character pieces from `assets/fonts/ascii/`. Each file (like `65/glyph.txt`) is a simple grid of `#` and `.` characters.
2.  **CPU Rasterization**: 
    - The daemon clears an 8.1MB memory buffer (`1024x640x4` bytes) to a solid Dark Blue.
    - It reads the standard `current_frame.txt` (the same one you see in the terminal).
    - For every letter it finds, it lookups the corresponding `.txt` glyph and "paints" (blits) those `#` pixels into the memory buffer at the correct X/Y coordinates.
3.  **The Bridge**: The daemon flushes this entire memory buffer to `projects/wraith-alpha/session/rgb/current_frame.rgba32`. This is a raw binary file containing nothing but 2,621,440 bytes of pixel data.
4.  **GPU Presentation**: The `wraith_gl` app (The "TV") is a pure consumer. It watches for a pulse, reads that raw file directly into its texture memory, and tells the GPU to draw a single rectangle with that texture.

## WHY IT LOOKS "TOO GOOD"
- **Nearest Filtering**: We used `GL_NEAREST`. This ensures that every pixel blitted by the daemon remains a sharp, perfect square, preventing the "blur" usually associated with scaling.
- **Font Parity**: The font was generated from `DejaVuSansMono.ttf`, so the character shapes perfectly match a high-quality terminal.
- **Speed**: Since the CPU is only doing simple byte-copies for the characters, it can render the frame in a few milliseconds, making the 60FPS feel "alive."

## CURRENT LIMITATIONS (THE "NOT TOO GOOD" PARTS)
- **Simplified Color**: V1 currently uses a "Smart Approximation." It colors the focused line (`[>]`) in Cyan and everything else in Light Gray. It is NOT yet reading the full chromatic metadata from `current_frame.objects.pdl`.
- **Placeholder Chrome**: The borders and buttons are still just the ASCII characters (`+`, `-`, `|`). We haven't enabled the "Real UI Rectangles" yet.

## VERDICT
The pipeline is **Live and Sovereign**. It proves that the TPMOS "Middle Fork" architecture can produce high-fidelity graphics from raw text files without needing a complex GPU engine.
