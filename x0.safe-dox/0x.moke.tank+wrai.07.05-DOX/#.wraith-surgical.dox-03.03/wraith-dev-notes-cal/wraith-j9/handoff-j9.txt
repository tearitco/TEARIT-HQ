WRAITH MOUSE HANDOFF (J9) - UPDATED
Date: 2026-06-09
Status: SUCCESSFUL INTEGRATION / READY FOR UI REFINEMENT

1. What is working now
----------------------
- **Parser-Side Hit-Testing:** The parser now tracks character offsets for all interactive elements. Mouse clicks (btn 0) are mapped to UI elements by scanning the last rendered frame.
- **Click-to-Action:** Clicking taskbar buttons or window controls (o, -, x) now correctly triggers the corresponding `SET_ACTIVE` actions.
- **Redraw Stability:** Mouse movement no longer triggers frame redraws. Only click transitions (press/release) mark the frame dirty, significantly reducing CPU load.
- **Expanded Registry:** The window limit was increased from 10 to 20 to prevent "registry full" silent failures.
- **Taskbar Capacity:** The taskbar layout was expanded to support 20 restore slots.
- **Diagnostic Logging:** `debug.txt` now logs all click hits/misses and command injections for easy debugging.

2. Major Fixes applied
----------------------
- Fixed a bug where Enter/Button launch stopped working because the manager's registry was full.
- Replaced unstable dynamic frame snapshots with a fixed `MAX_BUFFER` array to prevent crashes.
- Decoupled mouse motion from rendering to stop frame spam.

3. Current architecture intent
------------------------------
- **One Frame Owner:** The parser/composer owns `pieces/display/current_frame.txt`.
- **Stateless Mouse Logic:** The parser handles the coordinate-to-element mapping, keeping the manager focused on high-level state.
- **Semantic Inbox:** All actions (mouse or keyboard) route through `projects/wraith-alpha/session/history.txt`.

4. Known risks / open problems
------------------------------
- **Single Presenter:** Currently only one "open" window is rendered at a time (multi-window tiling is not yet implemented).
- **Debug Noise:** Detailed logging is still active in `debug.txt`; it should be pruned once UI behavior is fully validated.
