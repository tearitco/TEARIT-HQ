1. EXISTING PATTERNS
--------------------
- Input Flow:
  1. Input Daemon (`pieces/keyboard/plugins/keyboard_input.c`) reads raw terminal input.
  2. If a project-specific lock file (e.g., `projects/mouse-test/session/mouse_enabled.lock`) exists, the daemon enables SGR mouse reporting.
  3. Daemon writes `KEY_PRESSED: <code>` or `MOUSE_EVENT: btn x y` to `pieces/keyboard/history.txt`.
  4. Project Manager (`wraith-alpha_manager.c`) tails the history file and updates internal state (e.g., `g_active_gui_index`).
  5. Manager writes updated state to `gui_state.txt` and `alpha_state.txt`, then pulses `pieces/display/frame_changed.txt`.
  6. Parser (`wraith_parser_alpha.c`) wakes up on the pulse, reloads variables, and renders the frame to `current_frame.txt`.

- UI Rendering:
  - Layouts (`alpha-shell.chtpm`) use `${var}` substitution for dynamic content.
  - Interactive elements (buttons) use `onClick="SET_ACTIVE:n"` which the manager parses to execute actions.

7. PITFALLS & IMPLEMENTATION NUANCE
-----------------------------------
- Pitfall #46 (Dual Ownership): Mouse clicks should be the SOLE trigger for an action when clicking. Do not "fake" a keyboard press (`KEY_PRESSED: 13`) if the manager is already handling the `MOUSE_MOVE` command, as this can cause double-execution or race conditions between the parser and manager.
- Pitfall #35 (One Input History Rule): The manager must continue to tail `projects/wraith-alpha/session/history.txt` as its primary semantic inbox. The parser's `handle_mouse` already routes mouse events here as `COMMAND: MOUSE_MOVE btn x y`.
- SGR Mouse Codes (Nuance):
    - Terminal coordinates (x, y) are typically 1-based, starting from top-left.
    - Button codes (btn) in SGR mode:
        - 0: Left Button Press
        - 1: Middle Button Press
        - 2: Right Button Press
        - 3: Release (any button)
        - 32+: Motion with button held (e.g., 32 is Left Drag)
    - Recommendation: Log the raw `btn` value to `alpha_manager.log` during initial development to confirm terminal-specific behavior.
- Coordinate Mapping (Specific to Wraith-Alpha):
    - Taskbar Row: Typically rows 15-18 in a standard terminal view (needs verification via `alpha_manager.log`).
    - Titlebar Row: Typically rows 4-6 when a window is open.
    - Columns: Buttons like [x] are usually in the far right (columns 70-80).
- State Sync: Ensure `mouse_x`, `mouse_y`, and `mouse_btn` are updated in `gui_state.txt` on EVERY move to ensure the "Manager Mouse" debug section feels responsive (60 FPS).
- Marker Discipline: Every mouse-driven state change MUST append to `pieces/display/frame_changed.txt` to trigger a parser refresh.
