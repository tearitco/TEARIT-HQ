Symptom:
- some Wraith projects appear to open in the GL/Wraith desktop window
- but the ASCII "mother terminal" / desktop shell does not show the expected project body

==================================================
ROOT CAUSE FOUND IN CURRENT EPOCH
==================================================

The Wraith ASCII shell reads project-owned session files for non-terminal project windows:

- `session/wraith_body.txt`
- `session/state.txt`
- `session/scene.objects.pdl`

The manager path is in:
- `projects/wraith-alpha/manager/wraith-alpha_manager.c`

Relevant behavior:
- `project_probe_body_lines(...)` reads `session/wraith_body.txt`
- `append_project_scene_objects(...)` reads `session/state.txt` and `session/scene.objects.pdl`

If these files are missing, the project may still launch as an active Wraith window, but the ASCII shell degrades to fallback text such as:
- `Missing project body file: session/wraith_body.txt`

So this is not primarily a launcher-dispatch bug.
It is a project-ownership / session-file completeness bug for ASCII frame-debug rendering.

==================================================

### A. Why ASCII and GL disagree on row `1`

Current understanding:
- GL selector state comes from `current_frame.objects.pdl` written directly by `wraith-alpha_manager.c`
- ASCII shell rendering depends on parser-composed `current_frame.txt` from `desktop_shell_markup`

Likely issue:
- the manager-owned semantic object path marks row `1` selected correctly
- but the shell-markup path is not faithfully reflecting that same nav-selected state for the title button in the mother terminal

This means the two surfaces are not deriving the selector glyph from the same final truth.

### B. Why row `1` disappears after clicking `ASCII`

This one is not random.

The screenshot shows:
- `Idx:8`

So after the user clicks or navigates to `ASCII`, focus genuinely moves to the debug selector control.

FOURTH BUG IN SAME AREA
==================================================

Symptom from live `fs` launcher test:

- `fs` now correctly labels hosted projects as `PROJ:...`
- selecting a project emits a launch command
- but pressing Enter on a `PROJ:` row does nothing in live Wraith

Observed live evidence:

- frame/receipt rows carried actions like:
  - `DESKTOP_ACTION:launch_piececraft-wraith`
- manager log showed:
  - `Command received: DESKTOP_ACTION:launch_piececraft-wraith`
- but no follow-on launch window creation occurred

Root cause:

- `fs` launcher ids were sanitized with hyphens preserved:
  - `piececraft-wraith`
- Wraith manager launcher discovery sanitizes launcher ids to underscore form:
  - `piececraft_wraith`
- `find_launcher_by_command(...)` was doing an exact string compare, so:
  - `DESKTOP_ACTION:launch_piececraft-wraith`
  - did not match
  - `DESKTOP_ACTION:launch_piececraft_wraith`

Expectation vs live outcome:

- expectation:
  - once `fs` detected a Wraith project and rendered `PROJ:...`, selecting it would launch the hosted project window
- live outcome:
  - project detection/rendering worked
  - dispatch failed at the manager command-normalization seam

Fix rule:

1. project launch commands should use the canonical Wraith launcher id format
2. project-owned command dispatch should normalize project ids before writing `DESKTOP_ACTION:launch_*`
3. redraw-sensitive projects should use project-owned marker flow instead of depending on incidental second clicks

For filesystem-style browser projects in Wraith:
- utility controls may share the same scene `y`
- ASCII shell should mirror same-`y` scene objects onto one rendered line

  - `^_UP`
  - `v_DOWN`
  - thumb/range indicator on the same row
  - then content rows below, one selectable item per row

==================================================
PROPOSED `grid` PAYLOAD FORMAT
==================================================

Status:
- proposed contract
- intended for reusable ops, Wraith shell, and later GL reuse

Primary file location:
- `session/*.grid.pdl`

Suggested first concrete filename for current case:
- `projects/wraith-alpha/wraith-projects/chtmgl-video-isolate/session/poster_preview.grid.pdl`

Why `*.grid.pdl`:
- consistent with TPMOS structured file habits
- easy for ops/managers/parsers to discover
- no hardcoded filename list required if we later allow `source=` references

--------------------------------------------------
TOP-LEVEL RECORDS
--------------------------------------------------

1. Header/config lines:
- `GRID id=<grid_id>`
- `rows=<int>`
- `cols=<int>`
- `cell_w=<int>`
- `cell_h=<int>`
- `default_fg=<hex>`
- `default_bg=<hex>`
- `default_border=<hex>`
- `nav_mode=<none|cell|row|custom>`
- `source_ref=<path-or-ref>`
- `title=<token_or_underscored_text>`

2. Cell lines:
- `CELL row=<int> col=<int> ch=<char_or_hex> fg=<hex> bg=<hex> border=<hex> nav=<int> action=<token> label=<token_or_single_char>`

3. Optional row metadata lines:
- `ROW row=<int> label=<token> nav=<int> action=<token>`

4. Optional block metadata lines:
- `META key=<token> value=<token>`

--------------------------------------------------
MINIMUM REQUIRED FIELDS
--------------------------------------------------

Required header:
- `GRID id=...`
- `rows=...`
- `cols=...`

Required cell fields:
- `row`
- `col`

Everything else may inherit defaults.

--------------------------------------------------
CHAR ENCODING RULE
--------------------------------------------------

Preferred:
- `ch=<single_ascii_char>`

For whitespace or awkward symbols:
- `ch_hex=<two_digit_hex>`

Examples:
- `ch=:`
- `ch=*`
- `ch_hex=20` for space

Reason:
- avoids parser ambiguity for literal spaces
- cleaner than overloading `label= `

--------------------------------------------------
COLOR RULE
--------------------------------------------------

Accepted color form:
- `#RRGGBB`

Inheritance:
- cell missing `fg` inherits `default_fg`
- cell missing `bg` inherits `default_bg`
- cell missing `border` inherits `default_border`

--------------------------------------------------
NAV RULE
--------------------------------------------------

Default:
- `nav_mode=none`

If interactive grid is needed later:
- `nav_mode=cell`
  - each `CELL` may provide `nav` and `action`
- `nav_mode=row`
  - each `ROW` may provide `nav` and `action`
- `nav_mode=custom`
  - manager/parser delegates to an explicit mapping op or companion metadata

For poster previews:
- use `nav_mode=none`

--------------------------------------------------
RENDERING RULES
--------------------------------------------------

Shell / mother terminal:
- parser reads grid payload directly
- renders a stable fixed-size rectangular block
- no inline `<text fg= bg=>` explosion
- each grid row becomes one terminal row

GL / Wraith RGB:
- optional later reuse of the same payload
- each cell may map to one semantic text cell or one colored tile
- should not require a second formatter contract

--------------------------------------------------
SUGGESTED SHELL TAG
--------------------------------------------------

Suggested future CHTPM/Wraith usage:

- `<grid source="session/poster_preview.grid.pdl" />`

Optional attributes:
- `x`
- `y`
- `rows`
- `cols`
- `nav_mode`
- `fallback`

Example:
- `<grid source="session/poster_preview.grid.pdl" />`

Reason:
- shell markup stays small
- grid content lives in a project-owned payload file
- ops can rewrite payload without rewriting layout markup
