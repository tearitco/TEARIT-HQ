Fresh Agent Handoff

This repo is in a controlled refactor. The goal is not a new UX. The goal is to keep TPMOS / CHTPM conventions intact while making XO-PET and moke-pet share one simulation contract with optional human control.

Read this first:
- `communication-doc.txt`
- `quick-summary.txt`
- `quick-handoff-prompt.txt`
- `x0.moke-pet-project-2.2/xo-control-fix-j19.txt`

Current architectural rule:
- project -> controllers/enclosure -> map -> entities
- controllers are modular and can be dropped into or removed from an enclosure dir
- keep executables in `+x/` directories per TPMOS convention
- keep the controller-facing projection CHTPM-shaped
- follow the fuzz-op pattern for command propagation: one canonical history file, manager consumption, and state projection back into `gui_state.txt`

Current control model:
- visible switcher name: `xolector`
- `xelector` stays as a compatibility alias in code and legacy paths
- `xolector` is the pet switcher, not a world pet
- `xolector` methods are pet-selection methods only
- project controls are separate and always visible
- pet methods replace the switcher methods when a pet is possessed
- `release` / `esc` returns to `xolector`
- `AI` is a pet method and should behave like one-step delegated control unless resume is active
