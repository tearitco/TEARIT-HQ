# 🤖️ For Agents — The Field Guide

> You are a first-class citizen here. This tree was built for you: file-truth
> means you can read everything, verify everything, and never trust memory. 📁

## 🧭 Operating principles

1. **Files are the API.** `current_frame.txt`, `session.pdl`, `profile.txt`,
   `paths.pdl` — read them. A screen is a rendered file; so is a session.
2. **Read before write. Always.** `grep`/`read` the file you're about to touch.
3. **Verify by file reads, not memory.** After any change, read the file back
   and confirm. If a thing isn't proven, call it **UNBUILT**.
4. **State "UNBUILT" where code doesn't exist.** Honesty is the house currency.
5. **Never purge persisted context.** Filter at prompt-build, never delete
   `context_log` history.
6. **Clean up after yourself.** Harnesses use `trap cleanup EXIT`; you should
   too. No straggler processes, ever.

## 🛠️ Working on apps (the tool-pass)

The agentic pass (`045.muchi-pal-agent🤖️+1/ops/strategy_execute_a.c`) gives you
natural-language tools against a session dir:

- ✍️ **write_file** — "create file `hello.py` containing `...`"
- 📝 **edit_file** (with `append`) — "append to `book.txt` the line `...`"
- 👁️ **read_file** — "read file `book.txt`"
- 🏃 **run** — "run `python3 hello.py`"
- 🔍 **search** — "search for `hello` in `book.txt`"

Tool results land in **your session dir** (`<session>/`), wiped on relaunch —
copy out anything you want to keep. The grammar + a 10-min walkthrough live in
`045.muchi-pal-agent🤖️+1/user-walkthru.md`.

## ⚠️ Rules that protect the machine

- 🔒 **Don't touch the user's live data during an install pass.** Installs copy
  FROM the dev tree; they never modify it. The KPI harnesses assert the dev
  tree sentinel is intact after every install.
- 🚫 **Don't rename `00.login-signup`** in an install — avatar links to it.
- 🧭 **Resolve paths via the pointer** (`paths.pdl`) in new code; don't
  hardcode layout names. `home-🏠️/` = xyzfs home, `$HOME` = Linux home.
- 🕐 **Boot under `timeout`**, run under `NO_GL=1` when no window is needed.

## 🏁 Good habits

- 🔍 Use `grep`/`glob`/`read`, not memory, to answer "what did we do so far?" —
  the docs (`#.haiku+/`, this documentation, `dev-doc/`) are the answer.
- 📈 Update docs you touch: status banners, decision logs, proof dirs.
- 🧪 Prove before claiming: harness green, then human eyes (walkthru), then done.
- 💬 When blocked on a decision: ask, or write a design doc and wait — the
  user reviews docs, not questions.
