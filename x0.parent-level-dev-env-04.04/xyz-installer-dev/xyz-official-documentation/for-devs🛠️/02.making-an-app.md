# 🛠️ For Developers — Making an App (the recipe)

> Reference implementation: `0.user-pal👤️/00.login-signup/` (harness-proven).
> Follow this exactly; do not improvise the skeleton.

## 🥣 Step 0 — the checklist

- [ ] Emoji name (`0X.app-name👤️/` style), leading zero-index for order
- [ ] `button.sh` with `compile|run|help` (copy login's, adapt names)
- [ ] `scripts/build.sh` → compiles `system/*.c` + `ops/*.c` into `ops/+x/`
- [ ] `system/` — chtpm_parser_pal, keyboard_input, renderer, prisc+x (.c + bin)
- [ ] `ops/` — self-contained C ops, one per action, `+x` output
- [ ] `default_op.txt` — dispatch: menu method → `ops/+x/<op>.+x`
- [ ] `pieces/<app>/...` — chtpm layout + session-scoped state
- [ ] `projects/<app>/pieces/` — durable project state
- [ ] `test-harn-same/` — tk ops + scenarios (see the harness doc)
- [ ] Shared durable state OUTSIDE sessions: `users/`, `xyzfs/`, `current_login.txt`

## 🏗️ Step 1 — the ops

Each op is one self-contained `.c` (no shared headers — copyable anywhere):

```c
/* <name> - what it does. Self-contained, no shared headers. */
#define _GNU_SOURCE
#include <stdio.h>
...
int main(int argc, char **argv) { ... }
```

Write files, print results. The chat/app reads files, not return codes.

## 🖥️ Step 2 — the screen

`compose_frame`-style op writes `pieces/display/` state and pings
`frame_changed.txt`. The renderer produces `current_frame.txt` — **that** is
what humans (and harnesses) look at.

## 🔐 Step 3 — identity (if your app has users)

Read identity from the sibling login app, never invent your own:

1. `current_login.txt` → `current_user_id` / `current_user_uuid` / `current_xyzfs`
2. `xyzfs/session.pdl` → mode/user_id/user_uuid/xyzfs_path/active_avatar
3. Fallback: guest branch `xyzfs/users/guest-<uuid>/`

See `ops/ensure_user_identity.c` in `01.avatar-creation👤️` for the exact
resolve chain (env `USERPAL_LOGIN_ROOT` → sibling glob → fallback).

## 🧪 Step 4 — prove it (harness before hype)

Every feature ships with a key-injection scenario + a `proof/` dir. Details in
`03.harness-and-proof.md`.

## 🚢 Step 5 — ship it

App goes in `@.app-store/` (dev catalog) → install op copies it into
`~/xyzos/apps/<name>/` → registered in `~/xyzos/app-store/installed_apps.pdl`.
Versioning/rollouts: see `../dev-doc/`.
