# 🛠️ For Developers — App Architecture

The reference app is `00.login-signup` (harness-proven). Copy its shape, not
its soul. This is the pattern every app follows.

## 🧬 The app skeleton

```
apps/00.login-signup/
├── button.sh              ← the ONLY entry point: compile | run | help
├── default_op.txt         ← prisc+x op dispatch (menu → op binary)
├── scripts/build.sh       ← compiles system/ + ops/ into +x (warnings-free)
├── system/                ← long-lived processes (chtpm_parser_pal, renderer,
│                            keyboard_input, prisc+x) + their .c sources
├── ops/                   ← op binaries in ops/+x/*.+x (self-contained C)
├── pal/                   ← pal program text (prisc+x reads it)
├── pieces/                ← UI/session state tree (see below)
├── projects/<app>/pieces/ ← app-managed project state
├── users/  xyzfs/  current_login.txt   ← SHARED, DURABLE, never session-scoped
├── test-harn-same/        ← key-injection harness (tk ops + scenarios)
└── proof/                 ← harness proofs, timestamped dirs
```

## 🔁 The boot flow (`button.sh run`)

1. **Make a throwaway session**: `pieces/sessions/<timestamp>-<pid>/`.
2. **Symlink in the durable truth**: `system/`, `ops/`, `pal/`, `users/`,
   `xyzfs/`, `current_login.txt` — shared, NEVER session-copied.
3. **Blank the session-scoped files**: keyboard `history.txt`,
   `interact_relay.txt`, `gui_state.txt`, `quit_flag.txt`.
4. **Launch the processes** (chtpm parser, keyboard, renderer, prisc+x).
5. **Render the login screen** into `pieces/display/current_frame.txt`.

A *screen* is just a rendered file. 🖼️

## 🧪 The UI loop (chtpm)

```
keyboard history.txt ─► chtpm_parser_pal ─► piece.pdl (menu + fields)
                                            │
prisc+x ◄── dispatch (default_op.txt) ◄────┘
   │
   └─► ops/+x/<op>.+x   (reads/writes files, prints result)
                        └─► compose_frame writes view.txt + pings frame_changed.txt
```

- `pieces/keyboard/history.txt` — strict format: `[ts] KEY_PRESSED: <code>`
- `pieces/display/current_frame.txt` — the composed screen (harnesses assert on it)

## 🗝️ Conventions that will save you

| Rule | Why |
|---|---|
| 🏷️ Emoji names are idiomatic (`00.login-signup`, `01.avatar-creation👤️`) | Skimmable, memorable, honest |
| 📁 Files are the API | No sockets soup; state is greppable |
| 🔗 Session dirs symlink, never copy, durable state | Logout ≠ data loss |
| 🔒 Never session-scope `users/`, `xyzfs/`, `current_login.txt` | USER-PAL-STANDARD sec. 2 |
| 🧱 Ops are self-contained C, no shared headers | Compile anywhere, copy anywhere |
| 🧭 Resolve paths via `$SCRIPT_DIR`, never absolutes | Apps run from any location |
| ⚙️ Compile in place (`button.sh compile`) | Binaries are NOT committed |
| 🚦 No `#` comments unless asked | The house style is lean code |

## 📍 Naming: `home-🏠️/` vs `$HOME`

- `home-🏠️/` = a user's **xyzfs home** (physical dir `home` in v1, under
  `xyzfs/users/<uuid>/`).
- `$HOME` = the **Linux home** (where `~/xyzos/` itself lives).
- The pointer `paths.pdl` maps these; apps read the pointer, they don't
  hardcode. 🎯

## 🏚️ What NOT to do

- ❌ Rename `00.login-signup` after install — avatar's `button.sh` globs
  `../00.login-signup*` and `ensure_user_identity.c` falls back to it.
- ❌ Symlink `~/xyzos` back into the dev tree — installs are one-way copies.
- ❌ Hardcode layout paths in new ops — use `paths.pdl`.
- ❌ Ship binaries in the repo — `button.sh compile` is the build.
