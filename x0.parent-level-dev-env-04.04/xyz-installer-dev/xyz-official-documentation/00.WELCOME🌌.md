## 🧭 What is xyzos?

**xyzos** is a local operating *culture* for building and running programs:

- 🕹️ **Games & makers** — maps, entities, worlds
- 📝 **Tools** — editors, loaders, harnesses
- 👤 **Identity** — login, per-user filesystem (`xyzfs`), avatars
- 🧩 **Widgets** — small programs that command big ones
- 📦 **Apps** — a *recipe*: project + widgets + toolbar, distributed through an app-store

Everything important is **files on disk**. Processes are thin. UIs are
**renderings of state**, never the source of truth. A "machine" here means one
`~/xyzos/` install; an "OS" is the launcher, the app store, and the per-user
filesystem working together.

```
👤 you
  │
  ├─► 🖥️ GL window / ASCII terminal
  │
  ▼
  pal / chtpm / ops (+x)          ← programs, compiled in place
  │
  ▼
  xyzfs/ · users/ · app-store/    ← the filesystem: the truth
```

## 🗺️ Where things live (file-truth map)

| Path | What it is | Never |
|---|---|---|
| `~/xyzos/` | The OS install (one per Linux user) | symlink it to the dev tree |
| `~/xyzos/apps/` | Installed apps, names preserved (`00.login-signup`, `01.avatar-creation👤️`) | rename login — avatar links to it |
| `~/xyzos/xyzfs/` | The per-user filesystem: `session.pdl` + `users/<uuid>/` | session-scope it |
| `~/xyzos/app-store/` | This user's ledger: `catalog.pdl` + `installed_apps.pdl` | edit by hand casually |
| `~/xyzos/paths.pdl` | **The pointer**: logical name → real path | hardcode the layout in apps |
| `xyz-installer-dev/` | The installer package (`xyzos-starter-install.sh` + `pointers.pdl`) | hardcode the dev-tree path |

**Naming rule:** `home-🏠️/` = a user's xyzfs home (physical dir is `home` in
v1). `$HOME` = the Linux home. They are different. Always. 🎯
