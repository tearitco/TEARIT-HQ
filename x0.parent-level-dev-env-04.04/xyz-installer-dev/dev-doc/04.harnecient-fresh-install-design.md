# 04. HARNECIENT — Fresh-Install Design (khtpm/livedesk era)

> **Product name (provisional):** HARNECIENT
> Previously called: "livedesk-xyz" → "HQ" → "HAI-Q"/"hi-iq"/"haiku" — all taken.
> **Date:** 2026-08-12
> **Status:** DESIGN (docs first, code second — written offline so work survives a disconnect)

---

## 1. What we are doing (one line)

Make it so an end user runs **ONE script** and gets a completely fresh,
fully self-contained install of the HARNECIENT desktop — the current
khtpm/livedesk taskbar + user-pal account system + entity windows — with a
terminal shortcut to open it.

---

## 2. The old installer is obsolete (why we're rewriting, not patching)

`xyzos-starter-install.sh` (install v1) predates the khtpm taskbar:

| v1 assumed | Today's reality |
|---|---|
| The product is two apps: `00.login-signup` + `01.avatar-creation👤️` | The product is the whole **khtpm livedesk desktop** (parser + manager + layouts + user-pal + entity window + xyzfs) |
| Taskbar was `tp_taskbar.c` | `tp_taskbar.c` is **retired/archived** (`LEGACY-ARCHIVE-20260811.zip`). The real taskbar is now `*.monads/*.livedesk-taskbar/ops/` — a **two-process** pair: `khtpm_strip_parser.c` (Xlib) forks `khtpm_taskbar_manager_main.c` (pure logic) |
| Pointers point at `44.xyz❤️‍🔥️00.10` | House is now `44.xyz❤️‍🔥️00.17` — `pointers.pdl` is stale |
| User creation is an app you open | User creation lives inside the **USER header cell** (`ACTIVATE:2` submenu, 2-stage cli-io) |
| Installed layout: `apps/`, `app-store/` | Right shape is: preserve the **house-relative layout** the C code expects |

So: keep the spirit of v1 (read FROM dev tree, never write; non-destructive;
compile in place; KPI harness), but rebuild the payload around the khtpm
desktop.

---

## 3. Scope decision (locked by owner)

- **Install target:** Full desktop — taskbar + user-pal ops + entity window +
  xyzfs skeleton + config, all self-contained under one root.
- **Self-contained:** copies everything it needs; works even if dev tree moves.
  `house_root` is passed as argv / derived from self-exe (portability rule §7 of
  `03.hardcoded-path-fragility-and-portability.md` — no fixed-depth `../..`
  climbs in the installer).
- **Install root:** flag-able (`--dest`, default `$HOME/harnecient`).
- **Boot:** `<root>/button.sh` (launch khtpm parser with install root).
- **Terminal shortcut:** `~/.local/bin/harnecient` (and `~/.local/bin/livedesk`
  alias) opens it from a terminal.
- **Testing:** relay-only KPI harness (no direct CLI), per house testing rules.

## 4. The installed layout (why it looks like the dev tree)

The C code resolves paths relative to **one `house_root`** passed to the parser
(`argv[1]`) or recovered from `/proc/self/exe` (tile-picker). Verified in source:

- `khtpm_strip_parser.c` line 1415: `g_house_root = argv[1]`, then joins
  `#.desktop/*`, `*.monads/*.livedesk-taskbar/...`, plus rel paths.
- `khtpm_taskbar_manager.c`: `house_root/#.desktop/livedesk_taskbar.pid`,
  `.../livedesk_shortcuts.pdl`, `.../livedesk_theme.pdl`,
  `.../livedesk_open.txt`, `.../livedesk-nav-claims/livedesk_nav_claims.txt`.
  Reads login via `house_root/0.user-pal*/00.login-signup`.
  Sessions at `house_root/xyzfs/users/<uuid>/home/livedesk/sessions`.
- `tp_desktop_window.c` (`resolve_livedesk_paths`): hardcoding is **fixed-depth
  from its own exe**, expecting `<root>/&.widgits/tile-picker/ops/+x/` — so the
  tile-picker ops dir MUST sit at that same house-relative depth in the install.
- `layout_path()` in parser: `*.monads/*.livedesk-taskbar/khtpm_strip_{header,bottom}.chtpm`
  — layouts must sit at that same relative depth.

**Consequence:** the install root IS a mini "house". We copy the needed
subtrees preserving their house-relative dir names (emoji dirs included):

```
<dest>/harnecient/                            <- install root = house_root
├── button.sh                                 # boot HQ (launch parser, verify pid)
├── paths.pdl                                 # pointer map (logical name -> real path)
├── *.monads/*.livedesk-taskbar/              # taskbar: sources + layouts + build
│   ├── khtpm_strip_header.chtpm
│   ├── khtpm_strip_bottom.chtpm
│   └── ops/                                  # parser/manager .c + build_khtpm_strip.sh
├── &.widgits/tile-picker/ops/                # entity window + emoji/asset ops
│   └── +x/                                   # tp_desktop_window.+x etc. (compiled in place)
├── 0.user-pal👤️/00.login-signup/            # account system (fresh users/)
│   ├── ops/                                  # userpal_*.c, build via its own scripts/build.sh
│   └── system/                               # prisc+x, chtpm_parser_pal, renderer...
├── #.desktop/                                # fresh config + runtime state
│   ├── livedesk_taskbar.pdl
│   ├── livedesk_theme.pdl
│   └── livedesk_shortcuts.pdl
└── xyzfs/                                    # guest session.pdl + empty users/ + bin/
```

## 5. What gets copied (payload), and what's regenerated fresh

### 5.1 Copy FROM dev tree (read-only)
- `*.monads/*.livedesk-taskbar/` — whole tree (sources, layouts, build script,
  design docs). Excludes nothing critical; small (~920K).
  **Note (2026-08-12 dedup pass):** `khtpm_css_parser.{c,h}` and
  `lib/stb_image_write.h` inside this tree are now BUILD ARTIFACTS, synced
  from `&.widgits/_shared-lib/` by `build_khtpm_strip.sh`/`build_db_hq.sh`
  themselves before compiling (not hand-maintained copies anymore — see
  `&.widgits/_shared-lib/README.md`). As long as the installer builds
  in place per §5.4 (it does), this needs ZERO installer changes — the
  synced files are already sitting in the tree by the time anything
  gets copied/zipped. Only matters if a future install path ever skips
  the build step (doesn't today).
- `&.widgits/tile-picker/ops/` — .c sources + stb_image.h/khtpm_core.h etc.
- `&.widgits/tile-picker/system/` — the shared system binaries the login app's
  build.sh produces/copies (prisc+x, chtpm_parser_pal, renderer, keyboard_input,
  gl_mirror, default_op.txt).
- `0.user-pal👤️/00.login-signup/` — app tree (ops sources, system sources,
  pal/default_op/pieces). Dev state inside it is STRIPPED (5.3).

### 5.2 Regenerated fresh (NOT copied — would carry dev identity)
- `#.desktop/livedesk_taskbar.pdl` — config. Written fresh so hq-menu commands
  point at install-local paths (restart = `sh button.sh restart`, dir = xdg-open
  `#.desktop`, quit). `strip_y_offset` 50, `datetime_lang`. No dev-only
  `$.crypts/...` commands.
- `#.desktop/livedesk_theme.pdl` — fresh defaults (bg #000000, fg #00ff00).
- `#.desktop/livedesk_shortcuts.pdl` — empty.
- `xyzfs/session.pdl` — guest session (mode guest, no user), the same shape
  the login app's own `button.sh` seeds.
- `0.user-pal👤️/00.login-signup/current_login.txt` — empty.
- `0.user-pal👤️/00.login-signup/xyzfs/session.pdl` — guest.
- `0.user-pal👤️/00.login-signup/users/` — empty dir.
- `<root>/xyzfs/users/` — empty dir. `<root>/xyzfs/bin/` — empty dir.

### 5.3 Dev-only state stripped right after copy (mirror v1's "stripping dev-only state")
- login app: `pieces/sessions/`, `proof/`, `test-harn-same/` removed; `users/*`
  removed; `current_login.txt` emptied; `xyzfs/users/*` removed.
- tile-picker: `scenarios/`, any proof/session junk removed (check on build).

### 5.4 Compile in place (uses each component's own real build script)
- Taskbar: `cd <root>/*.monads/*.livedesk-taskbar/ops && sh build_khtpm_strip.sh`
- Tile-picker: compile `tp_desktop_window` (+ friends) in place:
  `gcc -Wall -Wextra -O2 -o ops/+x/tp_desktop_window.+x ops/tp_desktop_window.c -lX11 -lXext -lGL -lGLX`
  (needs X11 + GL dev headers; present on this machine).
- Login: `cd <root>/0.user-pal👤️/00.login-signup && bash scripts/build.sh`
  (builds system processes + userpal ops).

## 6. Runtime truth (what the installed desktop reads/writes)

All paths relative to install root `house_root`:

| Program | Reads/Writes |
|---|---|
| parser | `#.desktop/khtpm_strip_frame_history.txt`, `#.desktop/livedesk_theme.pdl`, `#.desktop/livedesk_taskbar.pdl`, `#.desktop/livedesk_agent_relay.txt` (input), `#.desktop/strip_state.txt`, `#.desktop/strip_var_*.txt`, layouts |
| manager | `#.desktop/livedesk_taskbar.pid`, `#.desktop/livedesk_shortcuts.pdl`, `#.desktop/livedesk_open.txt`, `#.desktop/livedesk-nav-claims/`, `#.desktop/strip_history.txt`; login via `0.user-pal*/00.login-signup`; sessions via `xyzfs/users/<uuid>/home/livedesk/sessions`; entities via `&.widgits/tile-picker/ops/+x/tp_desktop_window.+x` |
| tp_desktop_window | `&.widgits/tile-picker/ops/+x/` for own location + emoji/asset ops; stores positions/packages in session dirs |

Account creation shells out to `0.user-pal👤️/00.login-signup/ops/+x/userpal_*.+x`
with `cd "<login_root>"` + `PRISC_PROJECT_ROOT` (the `cd` is REQUIRED — real bug,
see `USER_CREATION.md`).

## 7. Boot / launcher design

`<root>/button.sh` (self-contained; MUST NOT reuse run_khtpm_strip.sh's global
`pgrep -f` kill — that sweeps OTHER installs' khtpm processes too):

```
actions:
  start   (default)  build-if-stale? (no — installer already built), launch parser:
                     setsid env DISPLAY=... <root>/*.monads/*.livedesk-taskbar/ops/+x/khtpm_strip_parser.+x <root>
                     write <root>/#.desktop/harnecient.pid, depend on parser's own pidfile
                     pgrep-confirm real pid, print log path
  status              show installed parser/manager pids for THIS root only
  stop               TERM the parser (+ its child manager), then KILL fallback; cleanup entities?
  restart            stop + start
  help
```

Terminal shortcut script `~/.local/bin/harnecient` (and `~/.local/bin/livedesk`):
`exec <root>/button.sh` (foreground, shows live logs in the terminal).

Note: `khtpm_strip_parser.c` writes its own pidfile
`#.desktop/livedesk_taskbar.pid` (per-house-root) and tp_desktop_window's
`ensure_taskbar_running()` checks the same — so multiple installs coexist; any
"which taskbar is this" helper must match cmdline + house_root, NOT bare pgrep.

## 8. KPI harness — relay-only (house testing rule)

New harness `%.harnesses/install-harnecient/` (live in house root, next to the
existing `install-xyzos`), driving the INSTALLED copy only through
`<root>/#.desktop/livedesk_agent_relay.txt` via prov nav.sh, i.e. the same
bare-decimal contract as `#.desktop/harnesses/khtpm-livedesk-taskbar/nav.sh`.

KPIs:
- **K1 — clean install:** run installer with dest=/tmp temp home → assert layout
  exists (`button.sh`, `*.monads/*.livedesk-taskbar/`, `&.widgits/tile-picker/ops/+x/tp_desktop_window.+x`,
  `0.user-pal*/00.login-signup/`, `#.desktop/*`), binaries compiled,
  `current_login.txt` empty, guest session.pdl.
- **K2 — boot + signup via relay:** `esc` → `nav 2` (USER) → Return (New User…) →
  Return (arm typing) → `type alice` → Return → `type Alice` → Return. Assert:
  `0.user-pal👤️/00.login-signup/users/alice/profile.txt`, `xyzfs/users/<uuid>/`
  (meta.txt, home/, projects/), `current_login.txt` auto-login, header shows
  `username` label.
- **K3 — persistence/shutdown:** stop cleanly; restart; user still there,
  frame renders.

Harness output: `proof/k1-…/`, `proof/k2-…/`, frame-history excerpts, relay log,
filesystem proof (same format as `install-xyzos`).

## 10. Risks / things to verify while building (not assumed)

1. **Parser pidfile/`ensure_taskbar_running` interplay** — entity window may
   auto-launch the taskbar; ensure installed launcher doesn't conflict with a
   running dev-instance on the same DISPLAY (per-house pidfile should isolate;
   verify two installs coexist on one display).
2. **GL/GLX dev headers** required to compile tp_desktop_window — present here,
   must be documented as a build dependency.
3. **Login `system/prisc+x.c` etc.** only exist as SOURCE in the login app;
   `scripts/build.sh` compiles them locally (no shared-ops download). Coping
   whole login subtree then building must work offline.
4. **Emoji dir names in bash** (`0.user-pal👤️`, `❤️‍🔥️`, `*.monads/*.livedesk-taskbar`)
   — always quote; use robust globs; never hardcode these in the installer
   beyond what source code already requires.
5. **`run_khtpm_strip.sh` global kill** — DO NOT reuse for the installed
   launcher; scope stop/status/pgrep to this root's own cmdline + pidfile.
