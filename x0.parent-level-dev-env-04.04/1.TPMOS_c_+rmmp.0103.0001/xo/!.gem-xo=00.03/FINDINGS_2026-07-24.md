# Investigation Findings: INTERACT Mode Architecture

**Date**: 2026-07-24  
**Status**: Previous handoff was INCOMPLETE — core Manager loop was never implemented

## What the Previous Handoff Got Wrong

The HANDOFF_INTERACT_MODE_FIXED.md claimed the system was "fixed" but was only a partial band-aid solution that **missed the core architecture**.

### What Was Attempted
1. ✓ Fixed chtpm_parser_pal.c to inject arrow keycodes to `interact_relay.txt`
2. ✓ Copied prisc+x.c locally
3. ✓ Created default_op.txt with operation definitions
4. ✗ **MISSING**: No Manager polling loop was created

### The Root Problem
Arrow keys ARE reaching `interact_relay.txt` but **nothing is reading from it in the game cycle**. The previous handoff tried to:
- Use PAL conditionals to convert keycodes to actions
- Call `game_turn_input` directly
- Record moves to `master_ledger.txt`

This bypassed the proper architecture entirely.

## The Correct Architecture (Per Blueprint)

Reference: `fo-map_interact-blueprint.md` (lines 4-90)

**Required Flow:**
1. **Input** → Appended to `session/history.txt` with timestamp: `[YYYY-MM-DD HH:MM:SS] KEY_PRESSED: 1002`
2. **Manager Thread** (MISSING!) → Polls history.txt every ~16ms (60 FPS)
3. **Route Input** → Converts keycode to action (arrow keys → move)
4. **Execute Op** → Calls `move_entity.+x xlector up` (or left/right/down)
5. **Update State** → Op modifies `pieces/xlector/state.txt` (pos_x, pos_y)
6. **Render** → Call `render_map.+x` to read all pieces and write `current_frame.txt`
7. **Signal UI** → Append marker to `frame_changed.txt` to wake the UI
8. **Interact Check** (Optional) → If something is at new location, call `interact.c`

### What interact.c Does (Correct)
- File: `pieces/apps/player_app/world/plugins/interact.c`
- Finds pieces at same location as active target
- Reads their `on_interact` script from state.txt
- Executes via prisc+x with player_ops.txt
- **This is only called AFTER movement completes**, not during input

## The Missing Core: Manager Loop

**Status**: Does NOT exist for the xo project.

A proper Manager needs:
- Background polling thread (usleep 16ms between polls)
- Track last file position in history.txt
- Parse timestamped KEY_PRESSED or COMMAND lines
- Convert codes to operations:
  - 1000 (left arrow) → move_entity xlector left
  - 1001 (right arrow) → move_entity xlector right
  - 1002 (up arrow) → move_entity xlector up
  - 1003 (down arrow) → move_entity xlector down
- After op completes:
  - Sync state to mirror files
  - Call render_map.+x
  - Pulse frame_changed.txt marker
- Handle ESC key to exit INTERACT mode

- Shows polling loop at line 886, route_input() at line 539
- Sync patterns in sync_focus(), perform_mirror_sync(), write_gui_state()
