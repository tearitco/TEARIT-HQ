# Topic: HARNECIENT Training Session

**TOMO:** Component by component. The live, working reference is `@.apps/my-lawyer` — that's where the Boss and I proved gemma 3:270m can read and write real legal case documents. Every rule below comes from code that ran, on disk.

**TOMO:** We call `POST /api/chat` with *exactly* {"model":"anything","stream":false,"messages":[...]}. No tools. No format. No schema. The API thinks it's just chatting. That is what makes the product model-agnostic — it works on literally any model, because we're not asking for any special capability.

**TOMO:** A system persona lives on disk (`pieces/registry/personas/lawyer_researcher.txt`, judge.txt). It actively forbids structure: You are a legal research assistant in a game. Give short, direct, plain-text answers - one sentence or a single case name, never a list, never markdown, never JSON. If you don't know, say "unknown" plainly. Then we ask a simple question: "Name one plausible legal precedent relevant to <angle. Just the case name, one line, no explanation." Never demand structured output from a small model — that is the original sin. 🙅

**TOMO:** The model's reply is treated as *text that may arrive wrapped in anything*. Our jsonparser.+x strips  json  fences defensively, walks dot-notation paths, and unescapes. Whatever mess comes back, we try to read it. Tolerance is not a luxury — it's the interface.

**TOMO:** THE key sentence: **the model never picks a tool.** The app does. mylawyercaseworker.c picks the angle, greps the corpus first (no network!), calls the model ONLY if the corpus has nothing, and writes to the real case file itself. This is the same pattern as agent-45's gemmastrategy.c: keyword match → run tool → fold result back in. The model's job is to be a cheap text generator, never a router.

**TOMO:** The "tool" writes **REAL files** — `data/cases/<id>/<side>_case.txt` — that grow turn by turn and can be opened directly. The audit trail is the artifact. No hidden state, no ghost writes. If it's not in a file, it's a lie.

**TOMO:** Every single step has a non-LLM fallback. Precedent empty? → *"General principle of %s applies to this dispute." Judge text empty? → score argument counts, then document length, then a default. And noisy output is tolerated, not rejected — real gemma 270M output included Precedent:  Habeas Corpus and The Mill Case, and we formatted them into [Argument N] lines anyway. The hack never depends on the model being clean.

**MAXINE:** So the user experiences "the AI read my document, wrote my case file" — but the model never did any of it. The harness did. And the model just... talked.

**TOMO:** Exactly. And because *we* did the tools, we can do them **deterministically**, verifiably, and on any model. The user sees magic. The competitor sees nothing to copy. 🕶️

**RAHWEH:** Why do you keep saying "the API never finds out"? Like it's a spy movie.

**TOMO:** *grins* Because it is the whole business model in one sentence. Everyone else is fighting to get tool support into models. We don't need it. We make tool support a front-end problem. That's cheaper, more reliable, and works everywhere. Our product works on models that literally cannot do tools.
