## Editor Save/Load Status
**YES — save/load works.** The editor has `editor_widget_cmds.c` handling:
- `SAVE` — saves current buffer to file_path in editor_state.txt
- `SAVE_AS:<path>` — save buffer to arbitrary path
- `LOAD:<path>` — load file into buffer
- `NEW` — clear buffer

Harness `%.harnesses/file-menu+editor/button.sh demo` is **ALL PASS** (proven 2026-07-28).

## File-Menu Widget & Editor Cooperation
Works at ops level. file-menu ops write to `pieces/system/widget_cmds/inbox.txt`, editor drains on idle/tick and writes status to `status.txt`. **GL widget chrome not built** — currently ops-only.

## Ready for "App Store" Packaging?
**Not yet.**
- Editor + save/load works at ops/harness level ✓
- But: file-menu GL chrome is NOT built (ops-only); widgets need `run-widget` GL launch profile
- House philosophy (explicit in README + `#.notes/AFTER-widgets-apps-store.txt`): **"Don't build the store before the desk"** — must live the combo first
- `@.app-store/` is empty; `@.apps/` exists but not populated
- Goal: first make project+widgets painful to relaunch manually, *then* bottle as @app

## Bottom Line
Editor+save/load is functionally complete and harness-proven. GL widget chrome is the missing piece before it feels like an "app" you'd put in a store. The architecture is ready; the UX polish (GL windows) is not.
