# 🏦🌾 Business Sim Game Starter (banks/stores/farmers/scientists) — delegation map

**Your plan:** banks + stores on a board trading stocks/bonds, players work for salary or trade
goods with farmers/miners/scientists doing R&D (my-bio/Mars-Street-Racer style progression).

## 🗂️ Segregation via `3.file` — how to keep this from bloating the shared framework

The taskbar's real HQ header cell 3 is **"file"** (new/save/save-as/load — confirmed from the
real header-cell numbering: `1=HQ, 2=USER, 3=file, 4=desks, 5=pals...`). **Each save-slot under
the file cell IS your project boundary** — your business-sim game lives entirely inside its own
file/session, with its own desks (maps: the trading board, farms, labs) and its own pals (banks,
stores, farmers, players). Nothing about it needs to touch shared `&.widgits/`/`@.apps/` code
UNLESS you're adding a genuinely new, reusable capability (e.g. a generic "stock ticker" widget
worth sharing) — that's the one signal to promote something OUT of your file's own scope into a
shared location. Default to keeping it local; only promote deliberately.

## ✍️ Starter prompt shape (use this as your actual first prompt to the browser agent)

```
CONTEXT: [platform-primer + collaborative-entity-games + data-storage-ledger]
CODE: [an existing multi-pal desk, as reference - find one via au11-hq/livedesk-dir-map.md]
PROMPT:
  "New game, file-scoped (session under HQ's file cell). Board = a desk. Entities: banks and
  stores (pals) as shared-state owners for prices/inventory (one writer each, per the ledger
  pattern in context), farmers/miners/scientists and the player as pals that READ bank/store
  state and submit trade/work actions. Start with ONE mechanic only: [pick one - e.g. 'player
  sells 10 wheat to a store for gold']. Don't build the full economy in one pass."
```

**Build order recommendation** (for your own planning, not the agent's prompt): (1) one static
desk + one bank pal with a real price-list state file, (2) one player pal that can buy/sell
against it, (3) THEN add farmers/salary/R&D — verify the core trade loop works before adding
entity variety.
