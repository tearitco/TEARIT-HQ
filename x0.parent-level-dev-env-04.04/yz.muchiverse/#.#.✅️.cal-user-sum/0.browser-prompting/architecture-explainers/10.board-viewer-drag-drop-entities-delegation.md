## 🧠 Real shape to reuse, not reinvent

- Board-viewer already has SOME piece-placement/rendering logic — a drag-drop feature is an input
  extension (mouse-drag → piece placement), not a new rendering system.
- Look at how mutaclysm's own `system/keyboard_input.c`+`ops/move_player.c` split works (capture
  vs. mutation) — dragging is conceptually the same shape: capture the drag gesture, then a
  SEPARATE op mutates the target desk's piece-placement state, one-writer-rule intact.
- Events attached to a dropped entity should follow file 4's real event-runtime shape (relay-
  driven activation, not automatic-on-drop unless that's a deliberate new trigger type).
