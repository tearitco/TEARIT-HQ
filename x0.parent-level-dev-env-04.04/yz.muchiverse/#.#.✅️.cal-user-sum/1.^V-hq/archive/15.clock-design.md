## 🎯 TL;DR

Build out taskbar **cell 15 (date-time)** 🕒 from a dead `${datetime}` label 💀 into a real **clock menu** 🕹️:

- 🗓️ Clocks & calendars under the clock: **realclock** (wall clock, always exists 🧱) + **game clocks** (`gameclock0000`, `gameclock0001`, … — user-creatable, per-session/desk/world, or tied to switches/events 🎚️).
- 🔔 **Reminders** on a real clock or a game clock.
- 🎬 A reminder can fire an **event** (`.pal`, event-ez authored) or a **common event** — "clock is like an event: it doesn't have to be common but can still be common." 🤝
- ⏩ Game clocks advance by **ticker** (continuous, like `pc_clock_daemon` ⏱️) and/or **endturn** (telescope plan, fake time starts 0 A.D. 🌄).
- 🕶️ Firing is done by a **headless daemon**; the menu mostly just updates-on-check (the "least-priv" ask = no always-on popup UI, no extra privileges 🔒).
- 📜 Scripts/jobs are **events only** — no new scripting language. We reuse event-ez / common events infra. *(User decision 2026-08-13.)* 🧩

## 4. 🗄️ Data Model

### 4.1 Clock registry — `#.desktop/clocks/clocks.pdl` 📋

One line per clock. Same `SECTION | key | value` shape as `livedesk_taskbar.pdl` for consistency with `read_key_value()`. 🗂️

```
SECTION | clock_id        | realclock
SECTION | clock_kind      | real
SECTION | clock_id        | gameclock0000
SECTION | clock_kind      | game
SECTION | clock_scope     | session        (session | desk | world | user)
SECTION | clock_start     | 0              (game epoch ms at creation; 0 = 0 A.D. / new game 🌄)
SECTION | clock_tick_ms   | 60000          (game-ms advanced per real-second at rate "min" — see table)
SECTION | clock_rate      | min            (off | cent | sec | min | hour | day)
SECTION | clock_watch     |                (optional switch/event id this clock tracks; empty = plain 🎚️)
SECTION | clock_desc      | main campaign
```

- **realclock** 🧱 is synthetic, always present, never stored — it IS the wall clock.
- **gameclock0000** 🎮 = first game clock, created by default at session creation. Subsequent = `gameclock0001…` (auto-numbered like the common-event `event_N` loop in `khtpm_taskbar_manager.c:2464`). 🔢
- **Rate table** ⚡ — copy `pc_clock_daemon.c:308-313` verbatim (game-centiseconds per real-ms): `cent=36000, sec=360, min=6, hour=0.1, day=0.004166…`.

### 4.2 Game clock state — `#.desktop/clocks/<clock_id>.pdl` 🎮

Owned/written **only by the daemon** (flock-protected 🔒, same as `pc_clock_daemon`'s `write_kv`).

```
SECTION | game_time_epoch_ms | 0
SECTION | game_time_epoch_sec| 0
SECTION | tick               | 0          (world tick / endturn counter 🔢)
SECTION | running            | 1          (0 = paused via menu ⏸️)
SECTION | last_checked_ms    | <real monotonic ms>   (daemon bookkeeping 📝)
```

Calendar display derives from `game_time_epoch_ms` via a shared helper (see §6.5). **0 A.D. anchor:** 🌄 `epoch_ms = 0` ⇒ year 0, month 1, day 1, 00:00 (proleptic Gregorian, no year-0 edge cases — it's the "fake time" telescope calendar 🕰️).

### 4.3 Reminders — `#.desktop/clocks/reminders.pdl` 🔔

```
SECTION | reminder_id       | r1
SECTION | reminder_clock    | realclock      | gameclock0000 (or any clock_id)
SECTION | reminder_at_ms    | 0              (real: epoch ms / "when"; game: game_time_epoch_ms target)
SECTION | reminder_at_text  | 08:30          (human string for the menu + the popup 🧾)
SECTION | reminder_repeat   |                 (empty = once; else "daily"|"hourly"|game-interval-ms 🔁)
SECTION | reminder_event    | common:greet_player | pkg:/abs/path | (empty = popup only)
SECTION | reminder_note     | water the plants 🪴
SECTION | reminder_enabled  | 1
SECTION | reminder_fired_at | 0              (last time it fired — for once-only + repeat logic ✅)
```

### 4.4 🏡 Where it lives (scoping)

- **Clocks/reminders are USER-level by default** (`#.desktop/clocks/`), but a clock's `clock_scope` can bind it to a **session/desk/world** so a session switch shows that session's clocks. Per-session clocks may also be stored under `sessions/<user>/<session>/clocks.pdl` — decided at implementation; default v1 keeps everything under `#.desktop/clocks/` with a `scope` tag (matches "per session/desk, or w/e u want" 🎯).
- `realclock` always exists regardless. 🧱

## 5. 🕹️ The Clock Menu (Cell 15 UI)

### 5.1 Layout change — `khtpm_strip_header.chtpm:116` 🔧

```
- <button label="${datetime}"/>
+ <button label="${datetime}" onClick="ACTIVATE:15">
+   <row>${strip_hq_items}</row>
+ </button>
```

(Exact same ACTIVATE-with-child-row shape every other menu cell uses; parser + `is_descendant()` handle it — no parser change needed for the shell. 🛠️)

### 5.2 Menu levels (all built by `livedesk_build_clock_menu()` in `khtpm_taskbar_manager.c`) 📂

**Level 0 — clock root (`which==15`):** 🕰️
1. `clocks & cals` 📅 → level 1a
2. `reminders` 🔔 → level 1b
3. `game clocks` 🎮 → level 1c
4. `clock as event…` 🎬 → open this clock's event package in event-ez
5. `cancel` ❌

**Level 1a — clocks & calendars** (one row per clock + calendar view) 📅:
- `realclock` 🧱 → row opens a **calendar view** (level 2: today + weekday, current time, next N reminders on this clock)
- `gameclock0000` 🎮 → same calendar view but for the game calendar (derived from epoch_ms)
- `new game clock…` 🆕 → cli_io flow (name → scope)
- `cancel` ❌

**Level 1b — reminders:** 🔔
- `new reminder…` 🆕 → cli_io flow: `clock id` → `when` → `event (common:<name> | <pkg dir> | empty)` → `note`
- one row per existing reminder: `<enabled?> r<N>: <clock> @ <at_text> → <event/note>` ✅
- `cancel` ❌

**Level 1c — game clock controls:** 🎮
- `gameclock0000` rows: `advance (endturn)` ⏭️ / `ticker on/off` ⏱️ / `rate: cent|sec|min|hour|day` ⚡ / `pause/resume` ⏸️ / `delete` 🗑️
- `cancel` ❌

### 5.3 Commands (dispatch in `ktb_hq_activate()`) 🎯

```
livedesk:clock:new-clock          → cli_io (2-stage: id → scope)
livedesk:clock:open:<id>          → clock calendar view (re-open menu at level 2)
livedesk:clock:new-reminder       → cli_io (4-stage: clock → at → event → note)
livedesk:clock:endturn:<id>       → write one endturn advance (daemon also honors it ⏭️)
livedesk:clock:ticker:<id>:on|off  → ⏱️
livedesk:clock:rate:<id>:min|hour|… → ⚡
livedesk:clock:delete:<id>        → 🗑️
livedesk:clock:reminder-del:<rid> → 🗑️
livedesk:clock:event-ez:<id>      → open_event_ez.sh on this clock's event package 🎬
```

`livedesk:clock:*` writers only touch `#.desktop/clocks/*.pdl`; the daemon does the same flock-protected read-modify-write so both sides are safe (exactly the `pc_clock_daemon` + `pc_menu_input` coexistence that already works in piececraft 🤝).

### 5.4 ⌨️ cli_io flows

- **new-clock:** 🆕 stage 1 `clock id` → stage 2 `scope` (session|desk|world|user). Creates `<id>.pdl` + `clocks.pdl` row.
- **new-reminder:** 🔔 4 sequential stages (`clock` → `when` → `event` → `note`), reusing the `new-user-id`→`new-user-name` sequential pattern (`khtpm_taskbar_manager.c:2656,2709`). Stage 3 accepts `common:<name>` or a package path; empty = popup-only.

## 6. 🧩 Components

### 6.1 🤖 `lc_clock_daemon` (new) — the only writer of clock state

Location: `xyzfs/bin/livedesk-clock/ops/` (+ build script + `+x/`), following the shared-ops pattern. 📍

Behavior (ported shape from `pc_clock_daemon.c`):
- `CLOCK_MONOTONIC` delta loop, 300ms cadence, `signal(SIGTERM/SIGINT)`. 🔄
- Launched `setsid nohup` once per session (via the clock menu's first use or the taskbar startup); writes `#.desktop/clocks/daemon.pid`. 🚀
- **Ticker:** ⏱️ for each game clock with `running=1` and `rate != off`, advance `game_time_epoch_ms` by `rate_table × real_elapsed`, with the ms-accumulator fix (`pc_clock_daemon.c:315-341`) so slow rates never stall. Bumps `tick` every crossed game-minute. ➕
- **Endturn:** ⏭️ a `#.desktop/clocks/endturn.txt` "mailbox" the menu writes; daemon consumes → adds one discrete advance (telescope's "time moves when the world takes a turn"). Endturn advance amount = configurable (default 1 game-hour). 📬
- **Reminder poll:** 🔔 every loop, for each enabled reminder compare target against its clock's current value (realclock → wall `time()` ⏰; gameclock → `game_time_epoch_ms` 🎮). On due:
  1. Launch `lc_reminder_popup` (setsid) — non-blocking. 🪟
  2. Run the attached event if any (see 6.3). 🎬
  3. Write `reminder_fired_at`; clear for once-only, reschedule for repeat. ✅
- **Watch (R3):** 🎚️ `clock_watch` — optional; v1 = informational field + future hook so a clock can advance/trigger off game switches or events (documented, not built).

### 6.2 🪟 `lc_reminder_popup` (new) — small X11 reminder window

**HOUSE WINDOW STANDARD (recorded 2026-08-13 for future agents — the popup was built once the wrong way and the user pushed back twice: "its still a gl window", "just follow standard dont waste time"):** every popup/dialog/hq window in this house is an **X11 RGB window + CSS (khtpm_css_parser)**, NOT a GL window. It opens exactly like db-hq / events-hq / ai-cell / context-menu: own detached process via `setsid nohup <bin> <house> <payload>`, CSS from a `.css` file beside the bin, font scale from `#.desktop/hq_ui.pdl` (`font_scale=1.25`), WM-managed but **title-bar-less** (the killer detail: `_MOTIF_WM_HINTS` `decorations=0`, NOT `override_redirect` — override_redirect makes Mutter exempt the window from real focus policy; the 2026-08-12 fix in `khtpm_hq_render.c:1189-1229` is the canonical reference), own drawn chrome bar (`#2b2b2b` + DejaVu Sans bold scaled(10) + `[x]` close), Escape/click/`[x]` closes, class `MuchiverseLivedesk` (xwayland grab allowlist). GL is only for `gl_mirror`-style RGB mirrors (muchi-pals/egg_window/mutaclysm), never for house popups. Canonical implementations to copy from: `khtpm_hq_render.c` (window creation `:1197-1251`, chrome bar `:838`, alloc_pixel/xft_color/font_for `:594-630`) + `lc_reminder_popup.c` (this file, built 2026-08-13 to match).

Shows: clock 🕰️, `reminder_at_text` 🧾, note 📝, event name 🎬. Simple OK/Clear. No new privileges — just an X window + reads a text file. 🔐
- Location: `xyzfs/bin/livedesk-clock/ops/lc_reminder_popup.c`, styled by `xyzfs/bin/livedesk-clock/reminder.css` (`window`/`.title`/`.note`/`.meta` rules), launched by the daemon's `fire_reminder()` via `setsid nohup '<popup>'+x <house> <fired_<rid>.txt>`. Agent relay for harnesses: `<house>/#.desktop/lc_reminder_relay.txt` (decimal ASCII per line, e.g. `27` = close).

### 6.3 🎬 Event firing (R5: `.pal`/events only)

- `reminder_event = common:<name>` 🏠 → run `play_event.sh <house>/common_events/<name> <house>` (session-level common events verified working, `EVENTS_RUNTIME.md`).
- `reminder_event = <package dir>` 📂 → `play_event.sh <package_dir> <house> [on-click]`.

It doesn't *have* to be a common event — but common events work too, because event packages are fully generic (`EVENTS_RUNTIME.md` 2026-08-12). 🤝

## 9. ⚠️ Risks / Open Questions

- **Manager↔daemon writes:** 🤝 both must use the same flock protocol (piececraft's `write_kv` precedent) — a mismatch recreates the documented lost-update race. 🏁
- **Process lifecycle:** 🤖 daemon must survive taskbar restarts (setsid) but die cleanly on session quit; use the same pidfile pattern as `pc_clock_daemon.pid`.
- **Where per-session clocks live:** 🏡 default `#.desktop/clocks/` + `scope` tag in v1; revisit if session isolation demands per-session dirs.
- **Endturn amount** ⏭️ & calendar anchoring (365-day years vs Gregorian) — user-preference, defaults proposed in §4.2/§6.1.
- **`clock_watch`** 🎚️ (clock tied to switches/events) is deliberately deferred — schema field now, logic later.
- **Header width:** 📏 adding a submenu to cell 15 may need `strip_x_offset`/y re-check; verify with a frame read, not assumption.
