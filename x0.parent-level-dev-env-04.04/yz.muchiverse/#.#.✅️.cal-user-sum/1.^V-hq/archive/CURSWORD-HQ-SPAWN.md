Rebuilt via `sh build_khtpm_strip.sh` (clean, pre-existing warnings only), restarted

| `4001 56 13` again | still exactly 1 desk row / 1 pal dir / 1 process |

### Relay contract gotcha (cost real debug time — do not relearn this)
The parser (`khtpm_strip_parser.c`) forwards only **4000-range header codes,
Enter, Escape, Backspace, and printable ASCII** from `livedesk_agent_relay.txt`.
**5000-range HQITEM codes are mouse-click-only** (generated by `dispatch_onclick`)
and are silently DROPPED if injected into the relay. To activate an HQ popup row
from an agent: `4000+cell` to open, printable digit(s) to move focus, `13` to activate.

### Relay gotchas learned today (cost real debug time)
- Injecting immediately after taskbar restart races the parser's "never replay
  backlog" cursor seed - codes get eaten. Wait a few seconds after restart.
- Enter is resolved by the PARSER too: with its popup active it sends
  `5000+its_own_focus`. Rapid blind injections desync the two focus trackers
  and can activate the WRONG row ($.restart = taskbar self-restart mid-test!).
  Safe procedure: send one code, VERIFY strip_state.txt (hq_open=1, then
  hq_focus=7), only then Enter.
- pgrep/pkill -f patterns match the probing shell's own cmdline: split one
  char out (`"curs""word"`) or better use `ps -eo args | grep '[c]har'`.
- Killing an entity with SIGKILL leaves its DESK row behind (only graceful
  paths clean state); dedupe now makes stale rows harmless on next spawn.

## 2026-08-24 (later) — Chat option: DONE (open-hai shared binary, per-instance)

User chose chat-first over events work. Built exactly per the shared-binary rule
(AU24 §4.3.1 amendment): same open-hai interface/binaries, separate session data.

### How it works
- `--data-root <dir>` flag added to BOTH `khtpm_open_hai_render.c` and
  `khtpm_open_hai_manager.c`: redirects sessions/state/audit/pidfile under one
  self-contained dir. Plain launches (no flags) are byte-for-byte unchanged.
  Emoji tile registry stays house-shared (assets, not data).
- render forwards the flag to its manager child (`launch_module()` now execv's
  with args); `--title <label>` names the X window; `--dump-and-exit` prints
  resolved paths and exits (flag-parse smoke test, touches nothing).
- `&.widgits/open-hai/chat_button.sh` (new): scoped single-instance launcher —
  kills ONLY instances bound to ITS data root (/proc cmdline match), never
  plain open-hai or another entity's chat. POSIX-clean (no bash arrays; house
  scripts run under dash).
- `button.sh` scoped in turn: its kill-all now SKIPS any instance carrying
  `--data-root`, so restarting plain open-hai can't murder entity chats.
- meta.pdl row (template + owned pal):
  `METHOD | Chat | sh -c 'exec sh "$1/&.widgits/open-hai/chat_button.sh" "$1" "$0/chat" cursword-chat'`
  → dispatch_action passes $0=pal dir, $1=house_root; data root = `<pal>/chat`.
  No `|` chars in the action string (meta.pdl is pipe-delimited). Menus re-read
  meta.pdl on every right-click — no respawn needed after edits.

### Verified live
- flag resolution (--dump-and-exit), manager boot on temp data root (dirs +
  state files + timestamped session created; clean SIGTERM)
- chat_button.sh end-to-end: launch → 1 render + manager w/ forwarded flag;
  re-run → TERM old + relaunch, still exactly 1; isolation both ways (plain
  filter sees nothing, chat launcher doesn't touch plain instances)
- exact-dispatch replica of the real meta.pdl row (two-shell-level quoting)
  launched the pair on `<pal>/chat` successfully.
