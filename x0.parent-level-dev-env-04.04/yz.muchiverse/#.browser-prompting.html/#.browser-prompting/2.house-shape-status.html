🏚️➡️🏡 Is The House In Shape?

Honest status report, not a delegation map.

What's genuinely solid right now

Verified this session
  • Taskbar terminal ASCII mirror — new, real, built + live-tested. Matches TPMOS's real renderer.c/keyboard_input.c split exactly in form after fixing a real staircase bug caused by combining them.
  • Taskbar input/dispatch architecture — cutover complete (2026-08-19). The feature-flag dual path (KHTPM_NEW_DISPATCH_MODE) is gone; old inline dispatch was deleted outright. Capture-only-writers + one-read-back-dispatcher, matching mutaclysm's real x11_mirror.c/game_dispatch.c shape, is now the only path — live-verified with genuine X11 input, bottom tab bar confirmed fully covered. A same-day frame-unification pass (strip_frame.cells.pdl) introduced and then fixed a real bug (arrow-key submenu nav wiped every tick by a change-signal filename collision) — see tb-bugfix-au19.txt and au11-hq/TASKBAR-FRAME-UNIFICATION-HANDOFF.md.
  • open-hai + free-tier OpenRouter — confirmed working live, real conversations and real tool calls (list_dir) both verified. See the open-hai page.

Taskbar vs TPMOS — spirit, form, and the honest gap

  • Spirit: very close now for the ASCII-mirror slice. Same "capture writes, dispatch reads, render displays" philosophy, same marker-pulse discipline, same dual-rate (60Hz active / 10Hz idle) poll standard.
  • Form: necessarily different — TPMOS's real shape is N independent sibling processes under one orchestrator; the taskbar is still mostly ONE process with Xlib event-loop dispatch, now with an opt-in alternate path rather than a true multi-binary split. Deliberate, acknowledged, still under evaluation.
  • Not yet TPMOS-shaped: bottom-tab-bar activation via relay (renders, doesn't activate yet), cli_io typing support, and real X11 capture is still the default (new mode is opt-in only).

Documentation organization

Sprawled, not stale

Direct count: au11-hq/ alone has 36+ files, spanning 1.8KB to 172KB, on topics from taskbar architecture to chat-hai memory design to event runtime mechanics. INDEX.md (157 lines) is the one genuinely reliable routing layer — kept current, not stale.

Honest characterization: not wrong, but excessive in volume relative to any one task's real need — exactly the problem this browser-prompting/ directory (and this HTML doc) exists to solve.

Where to actually look, as a human

  • au11-hq/INDEX.md — the master router. Always start here.
  • au11-hq/HANDOFF.md — living architecture + status snapshot.
  • Anything else in au11-hq/ — task-specific deep dives, only relevant when INDEX.md points you there.
  • This browser-prompting doc set — the purpose-built layer for browser-AI-sized bites.

Not independently re-verified

Bottom line

The house is NOT in disrepair — what got directly tested this session worked, and worked well, after real debugging. The two honest gaps: (1) breadth — lots of subsystems, each individually solid-ish but not all re-verified recently, and (2) documentation VOLUME outpacing any single task's real need.
