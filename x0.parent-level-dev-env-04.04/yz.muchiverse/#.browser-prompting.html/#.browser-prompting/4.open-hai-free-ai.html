Real, concrete gotcha found live

Unresolved

Asking the model to read a path containing special characters (&.widgits/open-hai/README.md) produced a WRONG path in its tool call — the & got dropped. Root cause not yet isolated to a specific layer (model-side JSON re-emission is the most likely culprit given list_dir path="." worked fine with no special characters).

Mitigation

Give free-tier models SIMPLE, unambiguous paths, or resolve the path yourself and hand it a value with no punctuation-heavy directory names when precision matters.

Real bug status correction

README.md's own "nav items beyond index 9 unreachable via relay digit-jump" warning was STALE — the actual code already has correct greedy multi-digit accumulation, ported from chtpm_parser.c's real house standard. Corrected in the README this session.

Recurring pattern

If you see other "known bug" notes in this house's docs, verify against the live code before assuming they're still true.

Best prompts to give it

SEND|Use your read_file tool to read the file at path <FULL, UNAMBIGUOUS PATH RELATIVE TO
HOUSE ROOT>, then <specific, bounded ask - e.g. "summarize in one sentence">.
  • Always give a full path relative to house root — tool paths resolve relative to house root, not to open-hai's own directory.
  • Keep asks narrow and single-purpose per message — matches the house-wide relay-only, one-action-at-a-time testing discipline.
  • For write/edit/run, expect to manually APPROVE each action — plan for a human in the loop.

Real quota mechanics

OpenRouter's real, publicly documented free-tier policy depends on whether you've EVER purchased $10+ of credits (even if at $0 now): ~1000 free-model requests/day if you have, ~50/day if you never bought credits. Check https://openrouter.ai/settings/credits to see which bucket you're in — not verified against this specific account this session.

Separately, individual free models get rate-limited minute-to-minute regardless — a shared pool across every OpenRouter user, not a personal quota. That's the real 429 hit in testing.

Other free APIs worth knowing about

  • Google AI Studio (ai.google.dev, direct) — generous native Gemini free tier, not sharing OpenRouter's congested pool.
  • Groq (groq.com) — fast, free, real tool-calling on open models.
  • Mistral — small free tier too.

None of these are wired into open-hai yet.

Honest bottom line

Yes, open-hai + free-tier OpenRouter is usable for nontrivial prompting right now — real conversations and real read-only tool use both confirmed live. Two real caveats: (1) pick a model that isn't currently congested, and (2) write/edit/run actions need a human to approve each one — not yet a "let it run unattended" tool beyond read-only exploration.
