# data/goods_kind.txt - how each good leaves an owner's hands.
#
# Format: <GOOD>|<KIND>|<RATE_PER_PERIOD>
# RATE is optional; each KIND has a documented default. RATE is the fraction of
# units held that the sink removes in ONE goods period.
#
# THREE KINDS, and they are three different MECHANISMS, not three rates:
#
#   CONSUMABLE    destroyed by USE. Fuel, food, raw materials, components
#                 consumed in production, and SERVICES - a service is consumed
#                 the moment it is performed, which is why banking, insurance
#                 and telecom sit here rather than under technology.
#                 Removes units. Demand is continuous and fast-cycling.
#
#   DEPRECIATING  still works, but physically wears out. Machinery, buildings,
#                 equipment. Removes units on a SLOW schedule, so replacement
#                 demand lags capital formation by years. That lag is what makes
#                 capital-goods markets cycle in lumps instead of pulsing.
#
#   OBSOLESCENT   not worn out at all - still physically fine - but worth LESS
#                 because a better generation exists. A chip is not consumed; it
#                 is displaced.
#
#                 This is why obsolescence cannot be modelled as "a faster
#                 depreciation rate". Depreciation removes QUANTITY gradually.
#                 Obsolescence destroys VALUE suddenly, and a seller still has
#                 the units to dump.
#
#                 OBSOLESCENT goods carry NO RATE, deliberately. Obsolescence is
#                 not a schedule and not a drip - it is an EVENT caused by R&D.
#                 A corporation that spends on R&D accumulates a pool; when the
#                 pool crosses a threshold its good's generation advances and
#                 the previous generation is obsoleted. A good nobody researches
#                 never gets obsoleted, which is exactly right and is also how
#                 a firm can be stranded holding an obsolete generation forever.
#
#                 Ops that implement this: ops/goods_sink.c (detects the
#                 breakthrough from each corp's rd_pool and publishes the price
#                 multiplier) and ops/goods_quote.c (applies it to ask prices).
#                 Cascade inputs: data/goods_input.txt.
#
# Ordering by obsolescence risk follows the real curve: shortest for
# semiconductors and software, longest for heavy machinery.
