# board-hq — the ONE generic board window (quests, ghost roster, phone directory, ...)

Quest: `^.grave/quests/Q006-one-board-layout` (built and scored; not yet linked from the h-ai menu). Written 2026-10-06 by claude (hai manager).

## What it is

A board is "a list of rows on the left, a detail pane on the right, action buttons, an optional text field". The quest board, the ghost roster and the phone directory are all that shape.
There is **one layout template** (`board.xhtpm` + `board.css`) and one small compiled op (`ops/board_vars_op.c`); each board is an **instance** = a stamped copy of the template + a data-source file
`state/<name>/board.pdl`. The window is rendered by the shared renderer (no per-project renderer code); the op is the window's `<module>`: it reads `board.pdl`, publishes `state/<name>/ui.txt` (plain `key=value`,
only when it changed) and the layout renders that through `vars=`.

## Files

| File | Role |
|---|---|
| `board.xhtpm`, `board.css` | THE template. Edit these to restyle/re-layout every board. |
| `board-<name>.xhtpm/.css` | Generated by `sh ops/new_board.sh <name>` (template with `@NAME@` replaced). Committed because the renderer opens them; do not hand-edit, re-stamp instead. |
| `state/<name>/board.pdl` | The data source (format below). Re-read every second: edits apply live. |
| `state/<name>/ui.txt`, `selected.txt`, `window.pid` | Runtime, gitignored. |
| `ops/board_vars_op.c` -> `ops/+x/board_vars_op.+x` | Build: `sh ops/build_board_vars_op.sh` (`-Wall -Wextra`, 0 warnings). |
| `ops/new_board.sh <name>` | Stamp an instance (and a starter `board.pdl` if missing). `BOARD_TEMPLATE=<file>` overrides the template (used by the selftest). |
| `ops/open_board.sh <house_root> <name> [close]` | Open (or close) one board window. One instance per board (pid in `state/<name>/window.pid`, also in the proc ledger so a taskbar quit reaps it). `BOARD_RENDERER=<path>` uses another renderer binary. Never `pkill -f`. |
| `verify.sh [--selftest]` | The scorer (below). |

## board.pdl format (`#` comments; fields separated by ` | `)

```
BOARD  | title    | Quest board
BOARD  | subtitle | ^.grave quests
SOURCE | md-table   | ^.grave/quests/INDEX.md | cols=0,4        rows = data rows of the first markdown table; cell 0 like [Q001](dir/QUEST.md) gives id Q001 + a link; text = cols joined
SOURCE | pipe-index | ^.hai-server/phones.index | cols=0,2     rows = lines of number|uid|label|entity_dir|phone_dir; id = field 0, link = LAST field (a folder)
SOURCE | dirs       | ^.ghost/roster                          rows = sub-folders (names starting with _ or . are hidden: templates)
DETAIL | link-tail | 14                                         detail pane = last N lines of the selected row's linked file (md-table)
DETAIL | dir-file-tail | history.txt | 14                      detail pane = last N lines of <selected folder>/<file>
ACTION | <label> | <shell command>                              a button; {id} {dir} = the selected row; commands run from the house root
CREATE | New quest | sh ^.grave/ops/quest_new.sh | New quest (rename me)
        a "+ New quest" button (creates with the default title at once) AND a text field at the bottom of the detail panel; what is typed reaches the command ONLY as "$1" (never interpolated into a shell)
DELETE | sh ^.grave/ops/quest_delete.sh | Delete {id}? It moves to _deleted/ and can be restored.
        Backspace on a row asks that text in the renderer's confirm popup (Enter/y = yes, anything else cancels), then runs the command with the row id as "$1"
```
Paths are relative to the house root (`44.xyz.01.00`) unless absolute. A source/detail the pdl does not declare simply shows nothing.

## Behaviour worth knowing

- **Selection**: a row click (or Enter on a focused row) runs `board_vars_op.+x <state> --select N`, which saves `selected.txt` and republishes. Backspace needs focus only, not selection.
- **Nav numbers**: the text field/"+ New" item take the first nav numbers; rows start after them. Tests read the real number from the frame (never assume it).
- **Module launcher**: the renderer prefixes every module argument with the house path and appends `<house> <package_dir> <module id>`; the op accepts the word `watch` by its last path component and ignores the extras in one-shot modes.
- **Orphan hygiene**: the watch loop exits when its parent (the window) or its `board.pdl` is gone.
- **Quest scripts** (`^.grave/ops/quest_new.sh`, `quest_delete.sh`): next id = highest ever seen (index, folders, `_deleted/`) + 1, so ids are never reused; delete MOVES the folder to `quests/_deleted/` and saves the row; hostile titles (quotes, `|`, `$()`, backticks, newlines) are data.

## Verifying (house rule: fresh build + fresh run + evidence)

```
sh ops/build_board_vars_op.sh
bash verify.sh --selftest   # a template with no rows must FAIL, the real one PASS
bash verify.sh              # 24 checks, HEADLESS (real renderer --headless, no window, no display), sandbox data in /tmp, real quests untouched
```
It covers: title, row count, nav-numbered rows, chosen columns, detail tail, action button, keyboard select, second/third source (roster, phone directory), instances differ only by name, one css edit restyles all,
create field present, no popup until Backspace, Backspace opens the popup naming the row, nothing deleted while it is open, another key cancels, Enter deletes reversibly, board refreshes, typed text is data, create adds a row.
`BOARD_RENDERER=<path>` scores a renderer built elsewhere (the confirm popup needs the renderer built 2026-10-06 or later).
