=== REAL ARCHITECTURAL FINDING (before implementing step 3) ===
active_target_id (pieces/apps/player_app/state.txt) is NOT a free-standing
"possession pointer" in this project's current real implementation -
tactics_menu_input.c's own key==0 idle branch auto-derives it from
current_layout.txt's own FILENAME every tick (get_current_piece_id()) and
overwrites it back if it ever differs. Manually retargeting active_target_id
to a unit's own piece_id while STAYING on roster.chtpm (no layout change)
would get stomped back to "roster" on the very next idle tick.

ADAPTATION (pragmatic, not fighting this real, working, load-bearing
navigation mechanism): roster.chtpm's own compose op tracks a simple
`selected_unit_id` field in tactics_menu's own state.txt. When unset, roster
shows the numbered unit list (SELECT_UNIT:<id> commands). When set, roster's
own DYNAMICALLY REGENERATED piece.pdl merges in that unit's real methods
(read from the unit's own separate piece.pdl file) instead of the plain
list - functionally the same outcome (select a unit, see ITS real methods,
dispatch them) without touching the active_target_id/layout coupling at
all. Noted here so a future agent doesn't "fix" this into a literal
active_target_id retarget without first re-deriving why it wasn't done
that way.

=== 2 REAL BUGS FOUND + FIXED DURING THIS PASS ===
1. pieces/battle_01/ was never symlinked into the session by button.sh -
   CONFIRM_START's own newly-added unit-directory writes went into the
   ephemeral session dir and vanished (same bug class as my-chara-txt's
   plots.txt / civ-txt's board.txt, found again here). Fixed: button.sh
   now does `mkdir -p pieces/battle_01/units` + symlinks the WHOLE
   directory (not individual files, since unit subdirs are created
   dynamically at runtime, not pre-existing).
2. Own testing mistake (not a code bug, but easy to repeat): calling an
   op binary directly with a literal small integer as argv[1] (e.g. "2")
   does NOT simulate real dispatch - argv[1] must be the STRING FORM OF
   THE RAW ASCII DECIMAL CODE (e.g. "50" for the character '2'), matching
   exactly what a real PAL loop's read_history+exec actually passes.
   Cost real time re-diagnosing what looked like a dispatch failure but
   was actually just a wrong test harness call. Noted here so a future
   agent doesn't repeat it.
