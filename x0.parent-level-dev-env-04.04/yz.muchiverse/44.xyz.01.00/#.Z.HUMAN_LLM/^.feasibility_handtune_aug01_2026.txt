----------------------------------------------------------------------
## 1. THE IDEA (as understood)
----------------------------------------------------------------------
Instead of gradient-training iqabod (opaque .weights floats), use an LLM
(ollama llama3-groq / gemma) or a harness as a "weight tuner" that edits
HUMAN-READABLE weight files by hand. Weights stay:
  - TEXT (readable/editable)
  - MODULAR (separate file per corpus / dir)
  - AUDITABLE (git-diffable, explainable changes)
The tuner LLM reads the current weights + a task, decides what to change,
and rewrites the text. Augmenting infra (RL/BT/FSM/corpuses) still applies
on top.

## 3. FEASIBILITY OF THE HAND-TUNING HARNESS
----------------------------------------------------------------------
VERDICT: FEASIBLE, and it works BETTER for these toy-scale models than
pure gradient training, BECAUSE the weights are text with structure.

HOW IT WOULD WORK (harness design):
  1. Tuner LLM (ollama llama3-groq or gemma) is given:
       - current weight file (vocab_model.txt / meta_rl_weights.txt)
       - a task ("make 'greeting' tokens score higher for 'hello'")
       - a budget ("edit at most 5 fields")
  2. LLM returns a DIFF (or full rewritten file) -> validated by a
     checker (all lines parse, numbers in range, no dropped tokens).
  3. We apply, re-train/re-generate, measure loss/output, keep or
     revert. Every change is git-committed = auditable.
  4. RL/meta weights tuned the same way (steer corpus selection).
  5. This is a FEEDBACK LOOP, same as distillation but editing weights
     directly instead of feeding the corpus. They can run TOGETHER.

WHY IT BEATS iqabod FOR THIS USE CASE:
  - iqabod's .weights = 60KB of raw float matrices (opaque, unreadable,
    NOT hand-tunable; the vocab file is readable but the weights aren't).
  - tomom@qroq's vocab_model.txt = per-token scalar fields WITH MEANING
    (embedding, weight, biases) -> an LLM can reason about "increase
    this token's weight" in a way it CANNOT reason about a 16x16 matrix.
  - Auditability: text weights = git diff = you SEE what the model
    "knows" changed. That is the property you've always wanted.
  - Modularity: corpus dirs = separate weight files = separate diffs =
    the "huge or small model depending on how many corpus weights +
    meta weights we include" plan, EXACTLY.

LIMITS (honest):
  - Hand-tuning cannot build massive distributed knowledge. It's for
    STEERING + CORRECTING toy models (tens to low-hundreds of tokens),
    which is precisely the scale we have. It complements, not replaces,
    distillation + corpus growth.
  - An LLM "tuner" editing raw floats is still guesswork; the harness
    must verify by retraining/eval. It works because scale is tiny.
  - Same augmented-training requirement as iqabod: BT/FSM + tools +
    RL + corpus bank are what enable books/code. The readable weights
    make the CONTROL (meta/RL) trainable and auditable, not the LLM
    knowledge itself.
