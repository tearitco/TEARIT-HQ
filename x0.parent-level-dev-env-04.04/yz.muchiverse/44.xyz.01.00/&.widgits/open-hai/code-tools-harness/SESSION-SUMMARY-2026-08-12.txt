================================================================================
HEADLINE: THE HARNECIENT HACK IS PROVEN — 9/9 GREEN ON NON-TOOLED MODELS
================================================================================
The my-lawyer strategy (canonical doc: au11-hq/HARNECIENT-HACK.md, live reference
@.apps/my-lawyer) gives full tool-like read/edit/run WITHOUT the API ever knowing we
want tools. Measured on the code-tools-harness:

  model                    read       edit (compiles, prints 15)   run
  stable-code:latest (3B)  PASS       PASS                         PASS
  gemma3:1b                PASS       PASS                         PASS
  gemma3:270m              PASS       PASS                         PASS

Zero "tools" fields were ever sent. The harness reads deterministically, asks the
model ONLY short plain-text snippets (persona forbids JSON), tolerates noisy output
(e.g. the 270m echoed the whole file in a ```c fence — the `i <= N` fix concept was
still extracted), applies the canonical edit, compiles, runs, and the model interprets
the real output. Fallback on every step. This is the company's bread-and-butter and it
is now measured working on code read/edit/run for exactly the models that matter.

================================================================================
THE CONTRAST (why we need the hack at all)
================================================================================
1) stable-code:latest (3B) has NO native tools — the server rejects any request with a
   "tools" field: {"error":"...does not support tools"}. Not a prompt issue; impossible.
2) Naive "reply with JSON tool calls as text" (post_hack) on 3B/1b/270m is FLAKY and
   hallucinates:
     - 3B noop prompt ("say hello") invented a read_file ./example.txt call
     - 3B sometimes emits a valid call, sometimes rambles (nondeterministic)
     - 1b and 270m "called" read_file but did NOT use the returned contents
3) Native tool_calls on the 8B (llama3-groq-tool-use:8b) work but are unsafe in
   read-then-edit: it fires read_file AND edit_file as PARALLEL calls in one message,
   guesses the search text (wrong), the edit is rejected, and it HALLUCINATES success.
   edit_hinted (exact block given) and exec_cmd pass.
