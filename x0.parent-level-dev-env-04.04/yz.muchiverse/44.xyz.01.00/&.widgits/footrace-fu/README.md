# footrace-fu - Footrace Fu / Time Fu RACE MODE v0 on the ring-board engine (template files, not a live entity)

Built 2026-10-07 in alpha (step 3 of `OWN-GAMES-REFERENCE-SUITE-DESIGN.md`: "ninja race first"). The owner's own game: 2-4 players, an army of 3-5 ninjas each, a race to the Finish with action tokens, a combat roll-off and four magic abilities. **Every number is data** (`entity/*.pdl`, read at run time, "make them fluid, pdl read"); a rule variant is a different set of `.pdl` rows; a number the source draft does not give is a marked `PLACEHOLDER=1`; a question the draft leaves open is a tunable with the comment `owner decision pending`. Nothing here is installed anywhere: **never copy it into live user data (`xyzfs/users`)**; the harness works on `/tmp` scratch roots only. Headless core only: no window, no AI seat (the harness bot is a deterministic policy, not a seat), no economy variant, no art, no print-and-play.

Sources: `ff-fu-IQ-a29-RULES.txt` (the v0.1 collaborative rulesheet draft, read in full) and the design notes in `OWN-GAMES-REFERENCE-SUITE-DESIGN.md`. The engine is `&.widgits/ring-board-rmmv/` (`dice_roll`, `var_math`, the page pattern, `event_page_op`); this folder adds only what a race needs.

## New ops
- `rand_roll <dir> <seed> <counter> <sides> <out>`: a deterministic die of N sides (2 = the coin) from seed + `rand_counter` (a separate stream from `dice_roll`), so a restored game flips and rolls what the uninterrupted game would. Ledger `rand_ledger.txt` (`RAND|seed|counter|sides|value`).
- `var_find <dir> <prefix> <skip_prefix|-> <center> <dmin> <dmax> <out>`: the nearest variable whose name starts with the prefix and whose value is `dmin..dmax` away from the center; the name numbers come back as `<out>_1`, `<out>_2` and the distance as `<out>_d`. Ties break by the numbers, never by file order. It is the "loop over variable names" gap (collision: an enemy on this space; Attack reach; nearest ally; my leading ninja).
- `row_append <dir> <file> <field>...`: one ledger row with `{var}` expanded, no timestamps. The pages log `ACT`, `COMBAT`, `CAST`, `REROLL`, `DEATH`, `SEATOUT`, `SLIDE`, `CLIMB`, `WIN`, `DRAW`, `TURN`, `REFUSE`, `SETUP`, `SELECT` into `ledger.txt` so the referee can check the pages from outside.

## State = variables (`key=int` lines in `variables.txt`, missing = 0)
Per seat `p` (1..4) and ninja slot `n` (1..5): `cls_p_n`, `hp_p_n`, `pos_p_n` (a dead ninja or unused slot sits at `off_track_pos`, never on the track), `alive_p_n`, `guard_p_n` (Block stance), `shield_p_n` (Chrono Shield), `fb_p_n` (free Block used this turn), `rr_p_n` (re-roll used), `tp_p_n` (teleports used), `use_<ab>_p_n`, `rdy_<ab>_p_n` (round the ability is ready again). Per seat `seat_up_p`, `alive_cnt_p`, `army_hp_p`. Global: `players`, `turn`, `round`, `current`, `sel` (the acting ninja of the current seat), `tokens`, `free_left`, `winner`, `winner_n`, `game_over_reason` (1 Finish, 2 last army standing, 3 both last armies fell together, 4 turn cap, 9 setup refused), `dice_seed`, `dice_counter`, `rand_counter`; switch `game_over`. Each trigger has its own `ph_*` phase variable (a page set runs in number order; `event_page_op` re-evaluates conditions as each page runs).

## Rules summary (v0)
- **Setup** (`setup`): 2-4 players, each army built from `roster.pdl` + `ninjas.pdl`; the table refuses to start (`game_over`, reason 9, a `SETUP|refused|...` row) when an army's HP is above `max_army_hp`, tokens above `max_action_tokens`, or `ninjas_per_player` is outside `ninjas_min..ninjas_max`. Seat 1 starts with `action_tokens`, its leading ninja selected.
- **Turn**: a player spends action tokens on Move, Attack, Block or a Cast, in any order, then End Turn (tokens reset, Block/Shield stances of the new seat end, the leader is selected, a seat with no ninja left is skipped, a lap of seats is a round).
- **Move**: 1d6 + (class Move - `move_baseline`), at least `move_min`, forward. Costs a token unless `move_costs_action=0` or a `free_moves_per_turn` step is left. Landing on an enemy ninja (not on Start or Finish) starts a melee combat; if both survive the mover bounces back (`collide_share=0`) or both stay (`1`). Then the finish rule (exact / bounce / overshoot wins), then a slide or climb, then the Finish check.
- **Combat**: attacker 1d6 + Attack (+ Blade Dancer's +1 within `adjacent_dist`) against defender 1d6 + Block (+ Block stance + Chrono Shield); the higher total wins, the loser loses `combat_loss` HP; a tie follows `tie_rule`. A Chrono-Weaver may re-roll its own die once per game when it is losing. At 0 HP a ninja is eliminated; an army with no ninja is out.
- **Attack**: an enemy within the class reach in either direction (melee 0..1, Ranged Mystic 2..3), same roll-off, no movement. **Block**: +`block_bonus` on the next defence; a Ward Sentinel's first Block each turn is free.
- **Cast** (token cost, roll condition, limit, cooldown, class are all rows in `abilities.pdl`): Time Skip (roll doubles, forward 1d4, max 2 per ninja), Warp Ally (coin flip, the nearest friendly ninja 3 forward, not past Finish), Banish Foe (2 tokens, double 6s, the nearest enemy to Start, or by coin to Finish only if `teleport_foe_to_finish=1`), Chrono Shield (+2 Block for one combat, cooldown 2 turns), Shadow blink (class 5: 1-2 forward by coin). A failed roll still spends the tokens and the use. Teleports (Warp, Banish, blink) are capped per ninja by `teleport_limit_per_ninja`.
- **Win**: the first ninja on Finish (also an enemy sent there); else the last army standing; both last armies falling together is a draw; `turn_cap` ends a stalled race as a draw.

## Player path
The menu rows in `entity/meta.pdl` are the same METHOD form as the ring board: `sh -c 'exec "$1/&.widgits/digipet/ops/+x/event_page_op.+x" "$0" "$1" --trigger <t>'` with `$0` the entity folder and `$1` the house root; triggers `setup select1..select5 move attack block cast_timeskip cast_warp cast_banish cast_shield cast_blink endturn`. The pages act for seat `current`, ninja `sel` (Select Ninja n changes it). The harness bot is the trigger `autoturn` (one action per call, picks by `bot_counter mod policy_period`, falls back to Move; it nests the other triggers through `event_page_op`, so it needs `EVENT_PAGE_PRISC` in the environment). Manual End Turn through the clock mailbox works the same way as in the ring board: `lc_clock <house> reminder-add <clock> <ms> common:end_turn "" every:1day`, runner `event_page_op` with `EVENT_PAGE_TRIGGER=endturn`, then `lc_clock <house> endturn <clock> 86400000`.

## Install note (by hand, scratch house first)
1. build the ops: `cd ops && for o in rand_roll var_find row_append; do gcc -std=gnu11 -Wall -Wextra -O2 -o +x/$o.+x $o.c; done` (plus the ring board `dice_roll` and `var_math`, `race_audit_op` in the harness ops folder, and the digipet `event_page_op`; the `+x` programs are git-ignored).
2. copy `entity/` to a desk entity folder `<ent>`; make `<ent>/ops/+x/` and copy `dice_roll`, `var_math`, `rand_roll`, `var_find`, `row_append` and `event_page_op.+x` into it (a pal `exec` cannot name the house root, so the pages find the ops relative to the entity).
3. write `players=2` and `dice_seed=<n>` into `<ent>/variables.txt`, run the menu row New Game once, then play.
4. optional clock hook: copy `common_events/end_turn` to `<house>/common_events/end_turn` and put `TARGET | state | <ent>` in its `target.pdl`.

## Gaps found (what the house cannot express yet)
Same engine gaps as the ring board (no variable compare in pages, `{var}` does not nest, one trigger per page, a pal `exec` hides the exit code and cannot name the house root, a COND rhs is a literal or one kv value), plus: no loop over variable names (`var_find`), no way for a page to write a text row (`row_append`), no die of N sides (`rand_roll`), no min/max (a floor is a compare plus a conditional page), a prisc program holds 1024 instructions (the setup page clears 20 ninja slots in one), and a variable name that looks like `r<digit>` / `x<digit>` in the 2nd or 3rd exec token would be read as a register. Not done in v0: Chrono-Weaver re-roll of a Move roll, ranged line of sight, heal, trading, the Buffet economy, duel/blitz presets, a board window, an AI seat.
