LPNS (LEDGER-PLAYER-NPC-SIMPLE) - IMPLEMENTATION COMPLETE
Reference Implementation of Ledger-Driven Multiplayer Game Architecture

================================================================================
WHAT WAS BUILT
================================================================================

A working demonstration of ledger-first game architecture supporting:

✓ MULTIPLAYER TURNS
  - Ring-based turn management (fair, deterministic cycling)
  - 1-8 total actors (mix of human players + NPCs)
  - Each player/NPC gets a turn in sequence
  - Game progresses through epochs (1-10 configurable)

✓ HUMAN INPUT
  - Interactive prompt: "Enter a word: "
  - Keyboard input captured and stored to ledger
  - Player sees their name, current epoch, turn counter
  - Confirmation feedback after word recorded

✓ COMPUTER AUTO-PLAY (NPCs)
  - 0-4 NPCs can be added at game setup
  - NPCs assigned IDs 5-8 (after human players 1-4)
  - Auto-play: randomly choose words from bank
  - No human intervention needed
  - Consistent with turn ring (take turns fairly)

✓ MASTER LEDGER (APPEND-ONLY LOG)
  - Single source of truth for all game state
  - Format: timestamp|epoch|player|turn|word|action_type
  - Every action logged (human + NPC)
  - Never modified (append-only semantic)
  - Enables replay/reconstruction/audit

✓ PLAYER DIRECTORIES + FILTERED LEDGERS
  - players/<actor_name>/ created for each actor
  - players/<actor_name>/ledger.txt contains ONLY that actor's entries
  - Auto-synced after each turn
  - Enables P2P: each node only needs to know about themselves

✓ STABLE, POSIX-COMPLIANT SHELL SCRIPT
  - Fixed bash-isms (now runs with /bin/sh)
  - Proper variable scoping
  - Tested with 2 players + 2 NPCs (4 actors, 2 epochs = 8 turns)

================================================================================
ARCHITECTURE PRINCIPLES VALIDATED
================================================================================

✓ LEDGER IS SOURCE OF TRUTH
  Master ledger contains all state
  Can reconstruct game by replaying ledger from turn 0

✓ RING TOPOLOGY FOR FAIRNESS
  Turn order deterministic: turn % num_actors → current actor
  Every actor moves exactly once per cycle
  No central arbiter needed

✓ SELF-CONTAINED OPERATIONS
  Each op is independent C binary
  No shared headers or complex dependencies
  Easy to test in isolation

✓ APPEND-ONLY LOG SEMANTICS
  Never truncate, overwrite, or reorder
  Enables crash recovery (ledger on disk persists)
  Enables P2P (each node replays ledger independently)

✓ ACTOR FILTERING (PLAYER VIEWS)
  Each actor gets own directory with filtered ledger
  Only sees own entries (privacy)
  Reduces sync bandwidth for P2P
  Enables client-side caching
