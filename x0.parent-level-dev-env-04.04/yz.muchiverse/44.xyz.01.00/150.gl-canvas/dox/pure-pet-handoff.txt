PHASE 1 — Xdnd Bug Fixing (egg_window + gl_mirror)
----------------------------------------------------
We found and fixed 6 bugs in the Xdnd drag-and-drop protocol between
muchi-pals' egg_window (drag SOURCE) and mutaclsym's gl_mirror (drag
TARGET). Both projects compile via their own button.sh / scripts/build.sh.

Bug 1: gl_mirror had glutIdleFunc(NULL) that overwrote glutIdleFunc(check_xdnd_events)
  Location: gl_mirror.c old lines 850-855
  Fix: Removed the overwrite

Bug 2: gl_mirror used XOpenDisplay(NULL) — separate X11 connection can't
  receive ClientMessage events destined for GLUT's connection
  Fix: Replaced with freeglut's fgDisplay.Display (extern hack)

Bug 3: egg_window used XQueryPointer to find drag target — returns egg_window
  itself since it's override_redirect/topmost
  Fix: Replaced with XQueryTree + XGetGeometry enumeration of root children

Bug 4: egg_window sent XdndSelection as ClientMessage — broken, target must
  request via XConvertSelection
  Fix: Replaced with proper XConvertSelection() call in gl_mirror

Bug 5: egg_window didn't call XSetSelectionOwner on drag start — target
  couldn't request the pet_id
  Fix: Added XSetSelectionOwner(dpy, XA_XdndSelection, win, CurrentTime)

Bug 6: egg_window sent spurious XdndLeave after XdndDrop — protocol violation
  Fix: Removed the XdndLeave after ButtonRelease

All bugs documented in: drag-drop-bugs.txt (at project root)

Both projects compile clean after fixes:
  mutaclsym: bash scripts/build.sh (or button.sh compile)
  muchi-pals: bash button.sh compile

PART 4: pet_purely vs egg_window (detailed)
======================================================================

pet_purely is a TEST STUB, not a copy of egg_window.

What it KEEPS from egg_window:
  - Raw X11 + GLX window creation (no freeglut)
  - override_redirect borderless window
  - 80x80 pixel size (same as egg_window's GRID_CELL_PX)
  - Mouse drag: ButtonPress → MotionNotify → ButtonRelease
  - Xdnd source protocol (XdndAware, Enter/Position/Drop, SelectionRequest)
  - XSetSelectionOwner on ButtonPress
  - XQueryPointer + XQueryTree target detection
  - SelectionRequest handler (sends pet_id as text/plain)

What it STRIPS from egg_window:
  - Sprite loading (sprite.csv + emoji atlas)
  - X11 Shape Extension masking (pet silhouette)
  - state.txt polling (grid_x/grid_y/z/tick_seq)
  - Autonomous movement (XMoveWindow from state.txt)
  - Self-tick (shelling out to tick_pets)
  - Grid snap on drop
  - write_pet_position() (state.txt writeback)
  - drag_drop_test.pdl polling
  - Close request file polling (/tmp/egg_window_close_*.txt)
  - Facing direction tracking
  - Icon overlays (sleep, poop)
  - Tick config reading

pet_purely renders: solid colored quad (hash of pet_id → RGB)
egg_window renders: GL texture of pet sprite + icon overlays

pet_purely position: argv[1]=pet_id, argv[2]=x, argv[3]=y
egg_window position: state.txt polling + drag_drop_test.pdl polling

See gl-canvas/dox/pet-only.txt for full comparison table.

PART 5: HOW THE Xdnd PROTOCOL WORKS (for this project)
======================================================================

SOURCE (egg_window or pet_purely) → TARGET (gl_canvas or gl_mirror)

1. ButtonPress on source:
   - source calls XSetSelectionOwner(XA_XdndSelection)
   - Records drag_start_x/y from xbutton.x_root/y_root

2. MotionNotify on source (while button held):
   - source calls XQueryPointer → gets root_x, root_y (actual cursor pos)
   - source calls XQueryTree(root) → enumerates all root children
   - source checks XGetGeometry on each child → finds which window
     the cursor is inside (the TARGET)
   - If new target: sends XdndLeave to old, XdndEnter to new
   - Sends XdndPosition to current target

3. Target receives XdndPosition:
   - Replies with XdndStatus (l[1]=1 means accepting)

4. ButtonRelease on source:
   - source sends XdndDrop to target
   - source clears xdnd_target, xdnd_have_target

5. Target receives XdndDrop:
   - Calls XConvertSelection(XA_XdndSelection, XA_text_plain, ...)

6. X server sends SelectionRequest to source:
   - Source responds with pet_id string via XChangeProperty

7. Target receives SelectionNotify:
   - Reads pet_id from property
   - Runs import_pet(pet_id)
   - Writes /tmp/egg_window_close_<pet_id>.txt
   - Sends XdndFinished to source

8. Source receives XdndFinished:
   - Cleans up xdnd_target, xdnd_have_target

9. Source detects close request file:
   - Reads and removes /tmp/egg_window_close_<pet_id>.txt
   - Exits

CRITICAL: Xdnd uses ClientMessage events. These are delivered only to
the X11 connection that CREATED the window. That's why gl_mirror must
use freeglut's fgDisplay.Display (the same connection glutCreateWindow
used), not XOpenDisplay(NULL) (a different connection).

PART 6: TEST HARNESS PATTERN
======================================================================

Follows the 044.pal-chat-irc/test-harn-same/ pattern:
  - Small self-contained C binaries in ops/
  - No shared headers, no shared libs
  - Each binary is a standalone CLI tool
  - argv-based arguments, stdout for output, exit 0/1
  - Compiled with: gcc -std=c11 -Wall -Wextra -O2

Test harness ops:
  tk_drag_sim    — finds windows by title (XFetchName), simulates drag
                    via XWarpPointer + XSendEvent (ButtonPress → 40 step
                    MotionNotify → ButtonRelease). Pure X11, no xdotool.
  tk_screenshot  — captures root window via XCopyArea → pixmap →
                    XGetImage → PPM file. 2496x1664 on current display.

Test scenario (test_drag_drop.sh):
  1. Kill prior instances
  2. Screenshot baseline
  3. Launch gl_canvas (background)
  4. Launch pet_purely at (100,100) (background)
  5. Screenshot both windows
  6. Run tk_drag_sim(pet_id, "gl-canvas", 10ms_delay)
  7. Wait 3 seconds
  8. Screenshot after drop
  9. Verify: imported_pets.txt contains pet_id
  10. Verify: close request file consumed
  11. Cleanup
