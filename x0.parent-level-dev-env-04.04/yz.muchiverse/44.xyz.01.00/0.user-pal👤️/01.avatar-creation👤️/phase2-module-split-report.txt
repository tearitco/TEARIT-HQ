## WHAT THIS IS AND WHY

Same Phase 2 house-wide standard as 041.pal-chain⛓️'s own
phase2-module-split-report.txt (read that file for the full reasoning
about launch_module()'s liveness check and why per-screen modules
matter). This project's own split was started earlier the same
session, then interrupted for the GL-typing-doubling investigation -
this doc is written after the ACTUAL split work (nothing from the
earlier interrupted attempt was reused; verified on pickup that no
per-screen module files existed yet, so this was a clean start).

## WHAT WAS DONE HERE

Before: all 6 layouts (customize, avatar_manage, avatars, main, store,
faucet) shared one
    <module>system/prisc+x pal/main_loop_chtpm.pal</module>

After: 6 new files, same content as the old shared loop, one per
screen:
    pal/customize_module.pal
    pal/avatar_manage_module.pal
    pal/avatars_module.pal
    pal/main_module.pal
    pal/store_module.pal
    pal/faucet_module.pal
Each layout's <module> line updated to point at its own file (e.g.
avatars.chtpm now has
    <module>system/prisc+x pal/avatars_module.pal</module>).

clear_saved_active_index() (PITFALL 66) ported into this project's own
local system/chtpm_parser_pal.c (3774 lines before this edit),
inserted after build_path_malloc(), called at 7 real transition
sites (same count/pattern as pal-chain and login-signup - grepped for
`focus_index = 0;` followed by a real parse_chtm() call, excluding
navigation-wraparound loops and the one focus-only re-init that
doesn't parse a new layout). One startup site already used
`unlink("pieces/display/active_gui_index.txt")` - left as-is
(functionally equivalent, matches the reference pattern).

Debug-spam printf lines (`DEBUG: Loaded directory_listing...` /
`DEBUG: Loaded last_key...`) removed from load_vars()'s modern-layout
branch.

## WHAT WAS NOT CHANGED

Shared ops binaries (avatar_menu_input, avatar_compose_frame, etc.)
were NOT split per-screen - still shared across all 6 new modules.

## VERIFICATION

Rebuilt via `bash scripts/build.sh` - "build ok", no new errors.
clear_saved_active_index appears 9 times (1 def + 1 doc-comment
mention + 7 real call sites). Debug-spam grep count is 0.

Real op-level test (test-harn-same/scenarios/demo_menu_fx.sh) run
after the edit - ALL 20 assertions PASS (faucet claim, free starter
mint, no-auto-select-on-entry stale-replay guard, DNA skin selection,
compose panel content, avatar_window + character_preview process
spawn, back-to-choose-clone with selection cleared, no-op compose not
spamming frame_changed). Note: this harness calls the ops binaries
DIRECTLY (avatar_menu_input.+x, avatar_compose_frame.+x), not through
a real running chtpm_parser_pal process + real keyboard injection -
it verifies the business logic wasn't broken, but does NOT exercise
launch_module()'s own per-screen relaunch behavior (the actual thing
Phase 2 changes). No K3-style real-injection harness exists for this
project - if you need to verify the module-relaunch behavior itself
(not just the ops logic), that would need a new scenario built on the
tk_inject_key.+x / tk_focus_item.+x pattern used elsewhere in this
rollout (see mutaclsym's or pal-chain's own test-harn-same/ for the
template).

## IF YOU HIT A BUG HERE

1. Doubling/dropped keystrokes: read #.haiku+/double-wr-grok-j31.txt
   first - already root-caused and fixed house-wide.
2. Stale focus after a transition: confirm clear_saved_active_index()
   is actually CALLED at the specific transition site involved.
3. A real ops/business-logic bug (tokens, DNA, cloning) is unrelated
   to this Phase 2 change - demo_menu_fx.sh already exercises that
   surface directly and passed clean after this edit.
