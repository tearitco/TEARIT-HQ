## 🎯 2. Why gemma (the real reason we're building tools)

From `!.GRAND-PLAN-TOOL-SCAFFOLD.txt` and `jul-21-gemma-fix.txt`:
- gemma3:270m (~935ms LAN round-trip) is the **cheap, fast, always-available**
  model — the distillation/corpus workhorse.
- It **cannot** reliably follow JSON tool schemas (gemini can; gemma can't).
  Fighting that = hallucinated `TOOL: read file ...` garbage (the bug we fixed).
- So the architecture inverts the normal agent pattern:

```
USER TYPES → gemma_strategy (DETERMINISTIC keyword → tool) 
           → strategy_execute_a (EXECUTES, captures output, logs result)
           → send_message (optionally asks gemma to narrate the result)
```

The model wraps results; it never decides to call a tool. This is already
PROVEN for `list_dir` (harness PASS, proof/harness-20260731-113214/).

## ⚖️ 4. Pre-LLM vs post-LLM — the decision

| | Pre-LLM (strategy A) ✅ **our path** | Post-LLM (check_response PENDING_PERM / gemini functionCall) |
|---|---|---|
| Who picks the tool | deterministic keyword match | the model emits `functionCall` / `TOOL:` |
| Works on gemma? | ✅ yes | ❌ no (hallucinates) |
| Latency | ~instant, result BEFORE any model call | one model round-trip before the tool runs |
| Safety | you can gate by message content | needs confirm flow (the old y/n we left alone) |
| Verdict | **use for every tool, every provider** | keep for gemini ONLY if ever needed; NOT this pass |

We already decided (2&3-jul31-sprint §6b) to leave the old y/n flow as-is —
this design doesn't need it: strategy A pre-executes deterministically, and
`model_after_tool=no` skips the model entirely. That is the product.

## 📜 5. The pipeline (proven by list_dir, reused verbatim)

```
Enter pressed
  → gemma_strategy: detect_tool(message) → detected_tool, selected_strategy=A
  → strategy_execute_a:
      • appends  system|strategy|...      ("→ [Strategy A] Detected tool: X")
      • stashes   tool_result.pending     (line1=tool, rest=raw result)
      • sets      tool_result_pending=1, sys_msg="[Tool: X] N bytes"
  → send_message:
      • appends  user|text|...            ("You: ...")
      • flushes   tool_result.pending → tool|result|X|...   (BELOW the user msg)
      • if model_after_tool != yes → IDLE, done
      • else → build request (with result in context) → fork connect_op
  → check_response (only if a model call actually happened)
```

One message = one tool. The result is **always** in the conversation, so gemma
can react to it later if `model_after_tool=yes`.

## ✍️ 6. Argument grammar (new: deterministic extraction)

Natural language in, structured argv out. Every pattern is case-insensitive
word-boundary; filename = **first whitespace-delimited token** after the
file-phrase; content = **everything after the content-phrase**.

### write_file
| You type | file | content |
|---|---|---|
| `write file hello.py containing print('hello world')` | `hello.py` | `print('hello world')` |
| `create file notes.txt with hello` | `notes.txt` | `hello` |
| `save file x.txt as "two words"` | `x.txt` | `two words` |
| `make a file data.txt that says 42` | `data.txt` | `42` |

file-phrase = `write file`/`create file`/`save file`/`make a file`.
content-phrase = first of `containing`/`with`/`as`/`that says`/`=`/`:`.
Quotes stripped if the whole content is quoted. Empty content → empty file.

### edit_file (surgical replace) + append (sub-mode)
| You type | file | search | replace |
|---|---|---|---|
| `edit hello.py replace print('hi') with print('hello world')` | `hello.py` | `print('hi')` | `print('hello world')` |
| `edit notes.txt change good with great` | `notes.txt` | `good` | `great` |
| `append more text to notes.txt` | `notes.txt` | *(append mode)* | `more text` |

append = `append <content> to <file>` → newline + content appended.

### read_file / exec_cmd / search_in_files (hardened)
- `read file <path>` — path = rest after `read file`/`cat`/`open` (quotes stripped), no more `cat <all-after-read>` slop.
- `run <command>` / `python3 <file>` — command = rest after `run`/`execute`.
- `search for <query>` / `grep <query>` — query = rest after `search for`/`grep`; optional `in <dir>`.

### Rules
- All paths are **session-scoped** (CWD = the session dir; sandbox depth=1).
- Outputs capped at 4KB (matching today's buffer) — a long `cat` or `search`
  result truncates with a note, never blocks.
- Non-matching message (e.g. "write file" with no filename) → `[Tool: write_file]
  Missing filename` result, never a crash.

## 🔁 7. Multi-step agentic coding = tool-per-turn chat

gemma can't plan multi-tool sequences in one shot (no planning context that
reliable). So the **dev drives the loop, one tool per turn**, exactly like a
human pair-programmer telling an assistant what to do:

```
You: create file hello.py containing print('hello world')   → [write_file result]
You: run python3 hello.py                                    → [exec_cmd result] hello world
You: edit hello.py replace hello with hi                     → [edit_file result]
You: run python3 hello.py                                    → [exec_cmd result] hi world
```

With `model_after_tool=yes`, gemma narrates between steps ("done, next?") —
optional. This is honest about the model's size and matches the house's
"deterministic before clever" law. A future `plan` tool (write a .pal script
and execute steps) is the stretch goal, NOT this pass.
