## THE BIGGEST CHANGES (real code, real behavior change)

1. 102.agy-txt file browser - rebuilt from a hand-drawn-marker fake
   browser to real chtpm <button>/<cli_io>/href navigation. 5 real bugs
   fixed along the way. -> see 102.agy-txt/refactor-report.txt

2. &.widgits/file-menu - same rebuild, same shape, 5 real bugs (some
   shared with agy-txt). -> see &.widgits/file-menu/refactor-report.txt

3. HOUSE-WIDE fix inside the SHARED chtpm_parser_pal.c (014.wsr-pal's
   copy): a fresh href transition could leave keyboard focus on a
   stale, coincidentally-same-indexed element from the PREVIOUS screen.
   Fixed via clear_saved_active_index(). This affects every href-driven
   project that shares this file - not just agy-txt/file-menu.
   >>> WORTH YOUR OWN SPOT-CHECK: any project with multi-screen href
       navigation you use often, to confirm focus resets cleanly.

4. prisc+x.c (the shared VM) - new opcode added (OP_READ_HISTORY_STR /
   read_history_str), proven working via a live test. NOTHING actually
   uses it yet - it's infrastructure for a future PAL-driven manager,
   not a behavior change on its own. Low risk to you.

5. 041.pal-chain⛓️ - REAL BUG FOUND AND FIXED: the "Sent N millicones..."
   send confirmation was silently truncating the recipient's wallet ID
   (a fixed-width box overflow, worsened by a double-truncating buffer).
   Fixed by shortening the confirmation message (dropped the redundant
   "from <sender>" - already shown one line above - and the tx_id,
   which is still saved to disk in full) and widening the internal
   render buffer. Re-tested, real PASS.
   >>> WORTH YOUR OWN SPOT-CHECK: send cones to a wallet with a long ID
       and confirm the confirmation line reads correctly.
