Confirmation line always shows the complete recipient wallet ID, no

## 🩹 WHAT WAS ACTUALLY BROKEN (already fixed)
The send confirmation used to repeat the sender's wallet ID (already
shown one line above) AND a long transaction ID — once both wallet IDs
got long enough, the line silently overflowed its display box and the
LAST CHARACTER of the recipient's wallet ID got chopped off. Example
of the bug (real, captured evidence):
    "...to walletB_112081"   ❌ (should end in ...1120810)

Fixed by shortening the message (dropped the redundant "from <sender>"
and the tx_id — tx_id is still saved in full on disk, just not shown)
and fixing a buffer sizing bug that was silently double-truncating the
text. Re-ran the real test after the fix → clean PASS. 🎉
