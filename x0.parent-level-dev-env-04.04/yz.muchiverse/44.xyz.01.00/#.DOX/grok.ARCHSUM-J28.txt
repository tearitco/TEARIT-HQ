DOES NOT WORK YET (do not expect)
  - Full FILE MENU / browser GL or even full chtpm chrome for widgets
  - Click emoji → click mutaclysm cell (coords only / cmd)
  - Multi-byte emoji as map cells
  - file-menu auto-discovering “mutaclysm is focused” from live GL OS
    without harness focus setup
  - Apps auto-registered into runtime on every button.sh run
  - @app-store install UX
  - Widget opening as second GL window next to game (proposal only)

MAY WORK / MAY FAIL (risk areas)

  A) Mutaclysm live game after new ops
     - New binaries only used if you call them; game loop does not
       auto-call muta_widget_cmds unless wired.
     - RISK: if you or something puts muta_* on the hot path wrongly,
       behavior changes. Default play should ignore them.
     - VERIFY: P0 play test.

  B) Hero always under map_start/hero/
     - SWITCH_MAP only updates map_id + coords in that file.
     - RISK: if you expected hero *directory* to move under map_02/hero,
       you will misunderstand “teleport.” Compose reads map_id from
       map_start/hero/state.txt — this matches existing mutaclysm code.
     - VERIFY: after switch, open that state file and check map_id.

  C) SAVE/LOAD copies entire world_01 trees
     - Large/slow; special files/permissions may surprise.
     - Harness uses workdir copies — should not delete install world.
     - VERIFY: install pieces/world_01 still intact after harness demos.

  D) NEW_GAME resets from world_01_template
     - Live content becomes template, not “empty void.”
     - If template ≠ your current live taste, NEW will look “wrong” but
       intentional.

  E) demo-project seed
     - Idempotent: won’t overwrite existing demo-project.
     - First seed from live or template depending on paths.

  F) Editor idle + widget cmds
     - Idle drains inbox; status should not be wiped by empty drains
       (fixed once for LOAD). If status looks IDLE after success, re-check
       buffer/disk not status alone.

  G) Proc-monitor
     - Isolated registry; **not** hooked into real mutaclysm/editor start.
     - Killing real game PIDs only works if you registered them first.
     - --soft needs session_path with pieces/system/.

  H) START_BUTTON same-TTY handoff
     - Launching an app *replaces* loader TTY until app exits.
     - Not the widget model (widgets should be parallel GL later).

  I) Paths with emoji
     - Shells sometimes break; prefer `cd` via tab-complete or harness
       scripts that already resolve paths.

  J) CPU / zombies
     - Agent earlier left sleep processes; demos should kill them.
     - If CPU high: `ps aux | grep sleep` and kill harness sleeps only.
     - Avoid: pkill -f prisc while other house projects run.

--------------------------------------------------------------------------------
11.1 Product shape (same idea as file-menu for the editor)
--------------------------------------------------------------------------------

  Editor     →  &.widgits/file-menu/     SAVE/LOAD docs (widget, no 2nd TTY)
  Mutaclysm  →  &.widgits/event-editor/  events + desktop packages

  DEFAULT launch profile = **widget**:
    - GL is primary UI
    - Does **not** steal a second human terminal
    - Optional ASCII:  SHOW_ASCII=1  or  sh button.sh r --ascii

  Mutaclysm path (partially designed, not full live UX yet):
    interact_mode + Space → xlector context menu
    1 Event · 2 Copy · 3 Paste · 4 Delete · 5 Exit
    Event → package under #.desktop/events/ + open-request for widget
    (see 101.mutaclsym*/dox/xelector-context.md)

  House desktop tray:  #.desktop/  (events/ entities/ tiles/ inbox/)
  Pickers may place stamps onto desktop; packages drop into muta later.

--------------------------------------------------------------------------------
11.2 TWO ways to show the editor (A/B) — do not confuse them
--------------------------------------------------------------------------------

  A) **THE GOOD ONE — pure freeglut RMMV chrome**  ← build target for look
     Path:  &.widgits/event-editor/gl_mock/
     Run:   cd &.widgits/event-editor/gl_mock && sh button.sh r
     Draws RMMV-like UI itself (left props, right Contents, footer, methods).
     Readable text via GLUT bitmap fonts (no font registry needed).
     Guide:  gl_mock/RMMV_EVENT_EDITOR_GUIDE.md
     Visual: gl_mock/VISUAL_REF_rmmv_target.jpg
             gl_mock/VISUAL_REF_rmmv_early.jpg
             gl_mock/event_editor_rmmv_look.jpg

  B) **House-standard pipeline — like mutaclysm menus**
     Path:  &.widgits/event-editor/   (parent button.sh)
     Run:   cd &.widgits/event-editor && sh button.sh r
     Pipeline:
       chtpm_parser_pal  →  current_frame.txt   (ASCII = nav source of truth)
       chtpm_rgb_render  →  rgb_frame.raw       (font-rasterize every char)
       gl_mirror         →  GL window           (blit only — no custom menus)
     **Must** symlink muta pieces/registry/ (fonts). Without it, GL was
     “colors only, no text” — FIXED in button.sh (ln -s registry).
     Layout is terminal-chrome style ([>] n. [label]), not full RMMV paint.

  Why freeglut looked nicer than first product GL attempt:
    freeglut draws UI + GLUT fonts; product path only mirrors rasterized
    ASCII and needs glyph files under pieces/registry/fonts/ascii/.
