## THE CORE INSTRUCTION, VERBATIM IN SPIRIT

"the ascii map and gl mirror, and ability to traverse level with
xelector is a feature we will keep no matter what" — the real-time
ASCII map rendering, the GL mirror window, and Xlector-cursor
traversal/possession are NOT up for redesign. Whatever the Menu/Title/
chrome redesign does, this core mechanic stays exactly as it is
architecturally. This is not cosmetic - it is the one thing explicitly
carved OUT of the redesign scope.

## PROBLEM 1: menu items should WRAP, not stack one-per-line

The current rtp-xyz screen (live frame shown, 2026-07-31 20:07:09)
renders every method as its own line:

    [>] 1. [Control Hero]
    [ ] 2. [pickup]
    [ ] 3. [drop]
    [ ] 4. [eat]
    [ ] 5. [save]
    [ ] 6. [toggle_emoji]
    ...

Real reference, 014.wsr-pal's own live `wsr_main_menu.chtpm` output
(shown directly, real terminal capture):

    [^] 1. [Actions ]
        [>] 2. [File  ]    [ ] 3. [Game Options  ]    [ ] 4. [Settings  ]    [ ] 5. [Help  ]
        [ ] 6. [Select Player  ]    [ ] 7. [Culture  ]    [ ] 8. [Entity Info  ]
        [ ] 9. [Select Corp.  ]    [ ] 10. [History  ]    [ ] 11. [General  ]
        ...

Multiple items per line, wrapping naturally to the next line when the
row fills up - NOT one per line. "instead of that title it will say
something else, also the options shouldn't be separated by <br>/
newline, they should wrap around like in wsr."
