## WHAT I VERIFIED BEFORE DRAWING ANYTHING (unchanged from v1, still
   the real technical grounding)

- `014.wsr-pal💸️📌️+2/pieces/chtpm/layouts/wsr_main_menu.chtpm` - real
  wrap-around technique: multiple `<button>` elements on the SAME
  markup line (or consecutive lines with no `<br/>` between them) -
  e.g. `<button label="Buy/Sell  " .../><button label="List
  Futures  " .../><br/>`. No manual column math - the frame composer's
  own text layout wraps naturally at the real render width. wsr-pal's
  own menu uses `${piece_methods_compact}`, NOT the standard
  `${piece_methods}` - a project-specific variant (see the reparse-
  risk discussion below - rtp-xyz deliberately does NOT copy this
  part).
- `slop-ed-dev.chtpm` (TPMOS reference tree, read at TWO separate
  snapshot paths, byte-identical both times - a settled, not moving,
  target) - real, already-built element types:
  - `<row label="...">` (`chtpm_parser_pal.c` line ~2561) - a real,
    auto-padded, box-bordered single line - `║ <label, padded to 57
    chars> ║` - zero manual padding needed in markup.
  - `<scroller id="MAPS" label="${var}">` (line ~2571) - renders as
    `║ N. <id, padded to 10> : <label, padded to 33> ║` - a real,
    numbered, ID-labeled, auto-formatted interactive row. **This is
    the real primitive behind "MAPS: ..." / "GLYPHS: ..."** - not
    hand-drawn text, a genuine built-in widget type.
  - Both confirmed present in rtp-xyz's own local `chtpm_parser_pal.c`
    too (same shared-engine lineage) - available today, zero new
    engine code needed.
- The real RPG Maker MV/MZ toolbar (given directly, verbatim list):
  New Project/Open/Save, Cut/Copy/Paste/Delete, Map Design Mode, Map
  Events Mode, Layer Select 1/2/3/A, Shadow Pen, Database, Plugin
  Manager, Resource Manager, Character Generator, Playtest. No real
  CHTPM element needed beyond `<button>`/`<row>` - each is just a
  labeled row, real or honest-placeholder depending on what's built
  behind it (see rtp-gui-design.md §3's own real-vs-placeholder table).

## 🔧 TECHNICAL PLAN - the wrap-around change specifically

Still the one piece with a real, non-obvious engineering decision,
now applying to BOTH new screens (editor toolbar rows AND game.chtpm's
method list), so worth getting right once:

**The problem**: `chtpm_parser_pal.c`'s own `load_dynamic_methods()`
(builds `${piece_methods}` from a piece's `piece.pdl` `METHOD` rows -
see `rtp-xyz-architecture.md` §9) hardcodes a trailing `<br/>` after
every button:

```c
asprintf(&btn, "<button label=\"%s\" onClick=\"KEY:%d\" /><br/>", trimmed_key, method_idx++);
```

That's why every method renders on its own line today - baked into
the generator, not a layout choice. wsr-pal's own fix uses a
different variable name (`piece_methods_compact`), which sidesteps
PITFALL 68's reparse trigger (only `piece_methods`/`active_target_id`/
`input_text` force a re-render) - risky to copy verbatim, since
wsr-pal likely gets away with it only because its own Actions menu
rarely changes mid-session.

**Fix, unchanged from v1's own plan**: edit `load_dynamic_methods()`
in rtp-xyz's OWN local copy of `chtpm_parser_pal.c` only (every
project keeps an independent local copy - zero blast radius
elsewhere). Join buttons with spaces instead of a forced `<br/>`, KEEP
the variable name `piece_methods` unchanged so PITFALL 68's reparse
trigger still fires correctly. Applies to `game.chtpm`'s real method
list. The Editor screen's toolbar rows are mostly static markup (not
`piece_methods`-driven) since most of them are placeholders, so this
fix path is scoped to `game.chtpm` specifically, not the Editor.
