## 1. Architecture Comparison

| Aspect | Benchmark (OG) | Current (+3) |
|--------|---------------|--------------|
| Main loop | Shell `while true` in `button.sh` | C daemon `game_manager.c` (16ms poll) |
| Turn dispatch | `game_tick.c` → stdout `HUMAN_TURN\|N` or `COMPUTER_TURN\|N` | `game_manager.c` polls `history.txt` for keycodes |
| Human input | `human_turn.c` → `fgets(stdin)` blocks | Parser handles cli_io → `gui_state.txt` → `game_manager` reads `input_text` |
| NPC action | `computer_turn.c` → random word, instant | **MISSING** — no NPC auto-play logic |
| Turn advancement | Shell: `sed -i` on `config.txt` after each action | `word_turn_input.c` updates `current_turn` in `config.txt` |
| Epoch check | Shell: `turns_this_epoch == 0 → epoch++` | `word_turn_input.c:54-56` same logic |
| Frame render | `view_ledger.c` → stdout | `word_compose_frame.c` → `state.txt` → parser `${game_map}` |
| Ledger append | Each turn handler appends directly | `word_turn_input.c` appends to `data/master_ledger.txt` |

## 2. Benchmark Main Loop (button.sh:73-136)

```
┌─────────────────────────────────────────────┐
│ SHELL MAIN LOOP (while true)                │
├─────────────────────────────────────────────┤
│ 1. Read game_state from config.txt          │
│    → break if "setup" or "finished"         │
│                                             │
│ 2. Run: ./ops/game_tick config ledger       │
│    → stdout: "HUMAN_TURN|N" or              │
│              "COMPUTER_TURN|N"              │
│                                             │
│ 3a. HUMAN_TURN:                             │
│    → ./ops/human_turn N config ledger       │
│    → BLOCKS on fgets(stdin)                 │
│    → Appends: timestamp|epoch|name|         │
│               turn|word|human_input         │
│                                             │
│ 3b. COMPUTER_TURN:                          │
│    → ./ops/computer_turn N config ledger    │
│    → INSTANT (rand()%20 from word bank)     │
│    → Appends: timestamp|epoch|name|         │
│               turn|word|computer_auto       │
│    → sleep 0.5 (visual pacing)              │
│                                             │
│ 4. Sync all player ledgers                  │
│    → ./ops/sync_player_ledger for each      │
│                                             │
│ 5. Increment current_turn in config.txt     │
│    → sed -i "s/current_turn=.*/..."         │
│                                             │
│ 6. Epoch check:                             │
│    → turns_this_epoch = new_turn % total    │
│    → if 0: epoch++, check if game over      │
└─────────────────────────────────────────────┘
```

**Key insight:** The benchmark uses a **blocking sequential loop**. Human turns block the entire loop. NPC turns are instant (plus 0.5s sleep). The loop decides WHO acts, then dispatches to the appropriate handler.

## 3. Current Game Manager (game_manager.c)

```
┌─────────────────────────────────────────────┐
│ C DAEMON (16ms poll loop)                   │
├─────────────────────────────────────────────┤
│ 1. Poll pieces/apps/player_app/history.txt  │
│    → Read KEY_PRESSED: N lines              │
│    → keycode_to_action(keycode)             │
│      13 → action=1 (submit word)            │
│      101 → action=3 (end_turn)              │
│      27 → action=-1 (ESC, ignore)           │
│                                             │
│ 2. execute_action(action):                  │
│    → action=1:                              │
│      read_input_word() from gui_state.txt   │
│      run_op("./ops/word_turn_input 1 word") │
│      clear_input_text()                     │
│    → action=3:                              │
│      run_op("./ops/word_turn_input 3")      │
│                                             │
│ 3. After action:                            │
│    → run_op("./ops/word_compose_frame")     │
│    → pulse_frame_marker()                   │
└─────────────────────────────────────────────┘
```

**Key insight:** The current manager is **reactive only** — it waits for human keypresses. It has NO logic to:
- Determine whose turn it is
- Check if current player is human or computer
- Auto-play NPC turns
- Know the game is "stuck" waiting for a human

## 6. What's Missing in Current (Bug Analysis)

### BUG 1: No NPC Auto-Play
**Benchmark:** `computer_turn.c` picks random word, appends to ledger instantly.
**Current:** `game_manager.c` has NO code to detect NPC turns or auto-play.
**Impact:** Game stalls on NPC turns — nothing happens until human acts.

### BUG 2: No Player Type in Config
**Benchmark:** `config.txt` has `player_N_type=human|computer` for each player.
**Current:** `config.txt` only has `player_N_name=...` — no type field.
**Impact:** game_manager can't determine if current player is human or computer.

### BUG 3: No Game State Machine
**Benchmark:** `config.txt` has `game_state=setup|playing|finished`.
**Current:** `config.txt` has no `game_state` field.
**Impact:** No way to detect game end or prevent actions after game over.

### BUG 4: Ledger Action Types Differ
**Benchmark:** `human_input` for humans, `computer_auto` for NPCs.
**Current:** `word` for human words, `end_turn` for manual end — no `computer_auto`.
**Impact:** Can't distinguish human vs NPC entries in ledger.

### BUG 5: No Turn-Based Pacing
**Benchmark:** `sleep 0.5` after NPC turns for visual pacing.
**Current:** No delay — game_manager fires instantly on 16ms poll.
**Impact:** NPC turns would flash by too fast to see.

## 7. What Needs to Change (Fix Plan)

### 7a. Add Player Types to Config
```
player_1_type=human
player_1_name=alice
player_2_type=computer
player_2_name=bot1
```
**Where:** `orchestrator.c` writes config on startup.

### 7b. Add Game State Machine
```
game_state=playing
```
**Where:** `orchestrator.c` writes on startup, `word_turn_input.c` sets to `finished` when epoch > epoch_length.

### 7c. game_manager: Detect Turn Type
```
1. Read config.txt → get current_turn, num_players, player_N_type for current player
2. If player_N_type == "computer":
   → Auto-pick random word from word_bank.txt
   → run_op("word_turn_input 1 <random_word>")
   → sleep 0.5 (visual pacing)
   → Continue loop (don't wait for human input)
3. If player_N_type == "human":
   → Wait for cli_io input (current behavior)
   → run_op("word_turn_input 1 <user_word>")
```

### 7d. word_turn_input: Track Action Type
```
- action=1, called by game_manager with player type info:
  → If human: append "...|human_input"
  → If computer: append "...|computer_auto"
- action=3 (end_turn): append "...|end_turn"
```

### 7e. word_compose_frame: Show Player Type
```
- Show "(YOU)" next to human player name
- Show "(NPC)" next to computer player name
- Show "→ YOUR TURN" or "→ NPC THINKING..." indicator
```

### 7f. orchestrator: Initialize with Player Types
```
- Write config.txt with player_N_type fields
- Write game_state=playing
- Write epoch_length, num_human_players, num_npcs
```
