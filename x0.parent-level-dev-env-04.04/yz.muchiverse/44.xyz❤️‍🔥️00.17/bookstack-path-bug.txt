================================================================================
DIRECTORY STRUCTURE NOTE
================================================================================

IMPORTANT: Directory names contain LITERAL ASTERISKS
- *.monads (directory is literally named with an asterisk prefix)
- *.book-stack (directory is literally named with an asterisk prefix)

This means paths like:
  /house/root/*.monads/*.book-stack/pieces/...

are VALID filesystem paths, not glob patterns. When passed to programs, they
need to be quoted properly to prevent shell interpretation of the asterisks.

All fixes account for this and properly quote these paths.

   - Does this binary require specific environment variables?

5. HIDDEN ERROR MESSAGES

================================================================================
HYPOTHESIS
================================================================================

The most likely issues (in order of probability):

1. PRISC+X LIMITATIONS
   Prisc+x may not properly handle:
   - File paths with literal asterisks
   - Exporting/inheriting PACKAGE_DIR environment variable
   - Executing external shell scripts via "exec"

2. EVENT.PAL SYNTAX ERROR
   The "exec /path/to/dispatch.sh" line may not be valid prisc syntax.
   Might need to be a different command or wrapper.

3. DISPATCH.SH SILENT FAILURE
   Dispatch.sh may be running but failing silently at a specific point:
   - dirname "$0" might not work as expected
   - find commands might not find paths with literal asterisks
   - khtpm_show_choices.+x might not exist or be incompatible

4. WORKING DIRECTORY ISSUE
   Prisc+x might not cd into event.pal's directory before executing it,
   causing dispatch.sh to be unable to find itself.
