3. What the demo proves
--------------------------------------------------------------------------------

  ./button.sh demo

Sequence:

  1. Compile editor + file-menu ops + harness helpers
  2. Boot a throwaway **editor session** (session-isolated)
  3. Publish widget_bridge.txt via editor_widget_cmds
  4. **file-menu** fm_set_focus → that session
  5. **file-menu** fm_enqueue LOAD fixture
  6. Editor drains inbox → buffer must equal fixture
  7. Mutate buffer; **file-menu** SAVE_AS → disk must equal buffer
  8. **file-menu** NEW → buffer empty
  9. Copy system paths into proof/; tear down session

Not proven here (out of scope for this harness slice):

  - GL windows for either side
  - Full FILE MENU / browser chtpm UI
  - Process registry in xyzfs
  - Human clicking FILE inside a live editor TTY/GL

5. How the bus is wired (for debugging a red run)
--------------------------------------------------------------------------------

  file-menu ops/
    fm_set_focus.+x  <widget_state> <editor_session>
    fm_enqueue_cmd.+x <widget_state> LOAD|SAVE|SAVE_AS|NEW|PING [path]

  editor ops/
    editor_widget_cmds.+x   # drain inbox; publish bridge

  Editor session files:
    pieces/system/widget_bridge.txt
    pieces/system/widget_cmds/inbox.txt
    pieces/system/widget_cmds/status.txt
    pieces/system/editor_buffer.txt

Harness scenario always:
  enqueue via **file-menu** ops → drain via **editor** op
  (never forge inbox only without going through widget ops)
