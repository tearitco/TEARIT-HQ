TEST SCOPE
==========
Proves that @.apps/text-editor-xyz (editor + file-menu widget,
launched together via its own real button.sh) can actually LOAD a file
and SAVE_AS a real edit, driven entirely through real key injection
into the real running processes — never a direct op call, never a
write into interact_relay.txt to fake a keypress for TEST purposes
(file-menu's own real production input channel for its buttonless
layout, confirmed and used correctly — see PITFALL 56 for why that's
the real channel here, not a shortcut).

Harness: @.apps/text-editor-xyz/test-harn-ed-app/
  ./button.sh demo-load   (scenarios/demo_load.sh)
  ./button.sh demo-save   (scenarios/demo_save.sh)
  ./button.sh demo        (both, sequentially)

KEY INJECTIONS PERFORMED
=========================
demo-load:
  1. file-menu: key 52 ('4' = LOAD, direct numeric select)
  2. file-menu: key 1003 (ARROW_DOWN, SEARCH field -> FILE field)
  3. file-menu: PASTE "<fixture absolute path>" (fm_menu_input.c's new
     PASTE mode, PITFALL 56 — bulk-string, not per-keystroke, because
     the real absolute path contains emoji segments this house's own
     directory tree has that per-keystroke typing can never carry —
     also PITFALL 56)
  4. file-menu: key 1003 x30 (bounded ARROW_DOWN, clamps at cancel_idx
     regardless of directory entry count)
  5. file-menu: key 1002 (ARROW_UP, steps back to confirm_idx)
  6. file-menu: key 13 (Enter — fires LOAD)

demo-save:
  1. editor: key 13 (Enter on the default-selected "EDIT TEXT
     (INTERACT)" button — a real chtpm onClick="INTERACT" engagement)
  2. editor: PASTE "<unique edit marker string>" (editor_menu_input.c's
     new PASTE mode — same PITFALL 56 fix, reused here for a SEPARATE
     timing bottleneck: even throttled per-keystroke injection through
     chtpm_parser_pal's own relay hop truncated a typed string; PASTE
     bypasses that hop entirely)
  3. editor: key 27 (ESC — exits INTERACT)
  4. editor: key 52 ('4' = FM/FILE MENU — real production signal,
     wakes/focuses the already-running widget)
  5. file-menu: key 51 ('3' = SAVE_AS, direct numeric select)
  6. file-menu: key 1003 (ARROW_DOWN to FILE field)
  7. file-menu: PASTE "<absolute output path>"
  8. file-menu: key 1003 x30, key 1002, key 13 (nav to confirm + Enter
     — fires SAVE_AS)

All file-menu keys above went through interact_relay.txt directly
(file-menu's own real, only input channel for its buttonless "dumb
ASCII menu" layout — gl_mirror.c's own append_key() writes here for a
real live GL keypress; this harness reproduces that exact mechanism,
confirmed via direct source read, PITFALL 56/§36.6). All editor keys
went through pieces/keyboard/history.txt in the real
`[TS] KEY_PRESSED: <code>` format, relayed by chtpm_parser_pal exactly
as a real keystroke would be (editor's layout has a real
<button onClick="INTERACT">, confirmed live).

BUG FOUND AND FIXED DURING THIS TEST PASS
===========================================
This test pass itself uncovered PITFALL 58: file-menu's own real
menu-driven LOAD/SAVE/SAVE_AS/NEW/PING had been silently doing nothing
since fm_menu_input.c's enqueue_cmd()/enqueue_cmd_with_path() was
written (wrong wdir passed to fm_enqueue_cmd.+x, silently exits 1, no
error surfaces anywhere). Fixed same session, re-verified with a clean
re-run after the fix (this report's own evidence above is from the
POST-FIX run). See !.xyzos-pitfalls+1.txt PITFALL 58 for the full
account — this is the single clearest demonstration this session of
exactly why §36.6 exists: the pre-existing level-1 harness had reported
6/6 PASS for this same feature the entire time this bug existed.
