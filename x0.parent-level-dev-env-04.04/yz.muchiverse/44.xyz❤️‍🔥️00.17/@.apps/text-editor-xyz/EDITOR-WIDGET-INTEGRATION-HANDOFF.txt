3.1 AUTO-SPAWN-ON-DEMAND (editor -> file-menu, standalone-editor case)
------------------------------------------------------------------------
FILE: 102.editor-📄️00.00/ops/editor_menu_input.c, do_fm() (~line 232)

Current:
  if (find_widget_via_ledger(widget_root, sizeof(widget_root)) != 0) {
      set_message("FM — no widget session (start app with button.sh run)");
      return;
  }

Change to: on ledger-miss, fork+exec (NOT system()/popen() — see
PITFALL 1's own "system() causes zombies" and PITFALL 50's own "never
interpolate a path into a shell string unquoted" — both apply here
directly) `&.widgits/file-menu/button.sh run-widget`, matching §35.2's
own step-by-step. Then either:
  (a) poll ledger_peers briefly (bounded retries, not a blocking spin
      — PITFALL 22/51's CPU-spin class is exactly what an unbounded
      poll here would reproduce) for the new session to register, or
  (b) fire-and-forget + set_message("FILE MENU — starting..."), let
      the NEXT do_fm() call (or an idle-tick re-check) find it once
      registered.
Prefer (b) for v1 — matches the existing async, file-mediated
philosophy everywhere else in this house.

NOTE: this is genuinely additive to, not a duplicate of, this
directory's own combined-launch button.sh (PART 0) — that path is for
"start both together from nothing"; this path is for "editor is
already running standalone, get a widget on demand." Both are
