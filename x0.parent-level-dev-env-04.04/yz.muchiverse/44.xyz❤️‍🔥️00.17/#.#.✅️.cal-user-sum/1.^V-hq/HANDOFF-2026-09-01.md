## The house rule

`*.monads/*.livedesk-taskbar/ops/khtpm_core_render.c` is the shared
X11/Xft renderer for db-hq, events-hq, chat-hai, open-hai, and (as of
this session) network-browser. **The renderer must never hardcode a
per-project mode** (no `g_is_<project>` branches for new work) — every
new capability is a generic, tag-based mechanism any `.chtpm` can opt
into. See `CENTROID_GOLD_STD.md` / `TPMOS-COMPLIANCE-DEBT.md` for the
full rationale. This has been re-confirmed and re-applied all session.

### network-browser — now real and working, 2 real bugs found+fixed this session
`&.hq-apps/network/network_browser_manager.c` +
`network_browser_render.c` were a pre-existing standalone app that
claimed (in a stale header comment) to already be on the shared
renderer but never actually was (confirmed: zero
`g_is_network_browser` references anywhere in
`khtpm_core_render.c`). A Haiku subagent did the initial conversion
(manager `write_chtpm_projection()`, `parent_still_alive()`, real
button.sh/bootstrap pattern copied from open-hai) but explicitly
self-reported it did NOT do real live testing. I did, and found/fixed:

1. **`ops/nb_write_go.sh` argv bug** — the script assumed a
   completely different argv shape than either real generic dispatch
   convention actually uses. `<cli_io>`'s `action=` gets the baked
   action string plus 3 appended trailing args
   (`package_dir house_root live_typed_value`); a plain `<item>
   action=` gets 2 appended trailing args (`package_dir house_root`).
   The script's real, full invocations end up being argc=5 (cli_io)
   or argc=4 (item) — fixed to branch on that and pull the real
   house_root/URL from the correct positions. Live-verified: direct
   script invocation writes the correct
   `#.desktop/network_browser_request.txt`, and a real relay-driven
   navigate-to-example.com rendered real fetched page content.
2. **No chrome X/! buttons** — `layout_sidebar_panel()` in
   `khtpm_core_render.c` only adds the generic chrome pair when BOTH
   `<sidebar>` and `<panel>` exist on the page; network-browser's
   projection emitted a bare `<page>` with neither. Fixed by wrapping
   its existing content in a minimal `<sidebar>` (title + empty
   scrolllist) + `<panel>` in `write_chtpm_projection()` — zero new
   renderer C, reuses the existing mechanism. Live-verified via
   screenshot: window is now the real 700x520 sidebar+panel shape with
   both buttons visible top-right.

Both fixes committed. Known real quirk (not a bug, just a timing
constraint for testing): `reparse_chtpm_if_changed()` disarms any
armed `<cli_io>` on every reparse, and navigating triggers a reparse
almost immediately — so a relay-injected "arm, type, submit" sequence
must fire fast enough that no intervening reparse lands mid-sequence,
or the arm gets silently dropped. Real users typing at human speed
into a field that's already settled aren't affected; only rapid
scripted test sequences right after a nav can race this.

Untested/unstarted for network-browser: actual real link-click
navigation (only address-bar submit was exercised); the `<item>`
argc=4 path in `nb_write_go.sh` is code-reviewed against the real
convention but not live-fired.

## New generic capabilities added this session (all reusable, all real)

- **`reparse_chtpm_if_changed()` nanosecond mtime** — `g_chtpm_mtime`
  is now `struct timespec` (was `time_t`), closing a real race where a
  manager's rewrite within the same second was missed. Also disarms
  any armed `<cli_io>` and releases any keyboard grab on every reparse
  (a live-regenerating manager reparsing mid-arm is the normal case,
  not an edge case).
- **`layout_sidebar_panel()` / `layout_fixed_rows_and_scrolllist()` /
  `layout_scroll_region()`** — the generic dual-region (fixed rows +
  independently-scrolling nested `<scrolllist>`) layout used by both
  `<sidebar>` and `<panel>`. One shared helper, not two near-duplicate
  copies.
- **Chrome X/! buttons** — added automatically by
  `layout_sidebar_panel()` whenever a page has both `<sidebar>` and
  `<panel>`. Positioned top-right (`btn_w=32, gap=8, right_margin=10`
  after live spacing feedback). `!` = `TOGGLE_FULLSCREEN` (new
  `dispatch()` action, saves/restores window position).
- **`backspace_action=`** — new generic `<item>` attribute; Backspace
  on a focused item dispatches it via `dispatch_no_quit()` (same shell
  dispatch as `dispatch()` minus the close-window-after-fire
  behavior). Used by open-hai to let Backspace delete a session row
  directly, instead of a separate "delete" item per row.
- **`rows="N"` on `<cli_io>`** — new Elem field, default 0 (=1 row).
  When set, `layout_fixed_rows_and_scrolllist()` reserves `N*ROW_H`
  instead of one row, and `draw_elem()` (in the shared
  `khtpm_draw_core.c`) does real, generic, UTF-8-safe greedy word-wrap
  (measuring actual Xft glyph widths) whenever the field's real
  `h > (line_h * 3) / 2`. Single-row `cli_io` consumers (open-hai's
  composer, network-browser's address bar) are byte-for-byte
  unaffected — verified via direct screenshot comparison. This is the
  capability chat-hai's own composer migration should build on.
- **`module_parent.pid` / `parent_still_alive()`** — generic orphan
  prevention: whatever launches a `<module>` writes its own PID next
  to the package dir; the module binary polls it and self-exits if the
  parent is gone. Generalized from chat-hai's own older, different
  mechanism (`state/chat_hai_renderer.pid` — left as-is, not replaced,
  only the pattern was reused).
- **Bootstrap self-healing** (`<app>.chtpm.bootstrap`) — a permanent
  template file, never overwritten by the live manager, that
  `button.sh` restores from whenever the live `.chtpm` is found
  missing its `<module>` tag (a real, confirmed failure mode: any
  stray write after a manager dies permanently erases the module tag).
  Now present for open-hai and network-browser; not yet for
  chat-hai/events-hq/db-hq (check whether they need it before assuming
  they're exempt).
- **Text-overflow ellipsis** — generic UTF-8-safe `"..."` clipping in
  `draw_elem()`'s single-line label path, whenever measured Xft width
  exceeds the element's box width.
- **Per-click focus reassertion** — `XSetInputFocus(dpy, win,
  RevertToParent, CurrentTime)` on every real click into a popup/
  default-mode window, fixing Backspace/keyboard-not-reaching-window
  under this WM's focus-follows-mouse behavior, WITHOUT a
  whole-window-lifetime keyboard grab (that was tried and immediately
  reverted — it makes the entire desktop keyboard-dead while the
  window is merely open). `<cli_io>` specifically also gets a scoped
  `XGrabKeyboard` for exactly its own armed lifetime.

## How to do real injection testing on any khtpm window (house convention)

Never use scrot/xwd/synthetic XTest. The real, house-standard method:

1. **Find the window ID**: `xwininfo -root -tree | grep -i <app name
   or size>` (khtpm windows usually have no title until you know their
   geometry — cross-check against the size the manager/renderer logs
   or against `DEFAULT_WIN_W`/`DEFAULT_WIN_H` = 700x520 for
   sidebar+panel windows).
2. **Find the renderer's PID**: `pgrep -fa "khtpm_core_render.*<app>.chtpm"`
   — this PID is what the relay file is named after.
3. **Inject keys**: write decimal ASCII codes, one per line, to
   `#.desktop/entity_menu_history/<renderer_pid>.txt`. Codes: 32-126 =
   printable, 13 = Enter, 27 = Escape, 8 = Backspace, 200-205 =
   arrow/page keys. To type a string: `for c in $(echo -n "text" | od
   -An -tu1); do echo "$c"; done`.
4. **Wait ~1-2s** for the renderer to poll and consume the relay file.
5. **Screenshot**: find the real window ID (`xwininfo`, step 1), then
   `&.widgits/_shared-lib/ops/+x/dump_frame_png_op.+x <window_id_hex>
   <out.png>`, then read the PNG directly (image tool) — do not guess
   from logs alone.
6. **Cross-check real backing state**, not just the screenshot: the
   app's own `#.desktop/*_request.txt` / `*_state.txt` files, and its
   `audit/<app>.log`, to confirm an action actually landed, not just
   that a field visually cleared (a field can look "submitted" purely
   because `<cli_io>` clears on Enter regardless of whether the
   dispatched action actually did anything).
7. **Remember `<cli_io>` needs to be armed first**: the first Enter
   (or a real click) arms/focuses the field before typed characters do
   anything; a reparse in between silently disarms it (see the
   network-browser quirk above) — keep injection sequences fast and
   arm-type-submit as one batch when testing address-bar/composer
   style fields.
