KEY STANDARDS COMPLIANCE
================================================================================

✓ PERSISTENT MODULE
  Pattern: prisc+x running *.pal with main loop
  Matches: real chtpm_manager.c, wsr-pal, pal-chain
  Why: Allows long-running state, proper event handling

✓ ASYNC KEY INJECTION
  Pattern: Fire-and-forget key write to interact_relay.txt
  Matches: real chtpm_parser.c's inject_raw_key()
  Why: Non-blocking, decoupled from rendering

✓ FRAME-BASED RENDERING
  Pattern: Only re-render when game_state_changed marker grows
  Matches: real chtpm idle optimization
  Why: Prevents flicker, efficient resource usage

✓ SEPARATED CONCERNS
  ├─ pal loop: orchestration only (read inputs, call ops, render)
  ├─ ops: pure logic (compose frames, process inputs, update state)
  ├─ config.txt: state storage (single source of truth)
  └─ ledger: history (immutable audit log)

✓ SYNC POINTS
  Pattern: Ops update config.txt, loop reads config, renders
  Matches: real TPMOS synchronous dispatch (waitpid on each op)
  Why: Serializes updates, prevents race conditions

EVENT LOOP (pal/main_loop_chtpm.pal)
================================================================================

loop:
  1. Check if game_state_changed marker grew
     └─ If YES: re-render, continue to render
     └─ If NO: check for key input

  2. Read from interact_relay.txt (key injection)
     └─ If key found: call game_turn_input op, continue to render
     └─ If no key: sleep 30ms, loop back

  3. render:
     └─ Call game_compose_frame → writes pieces/display/frame.txt
     └─ Call game_hit_frame → displays frame
     └─ Sleep 30ms, loop back

This creates a fair, non-blocking event loop:
  - Checks state every ~30ms
  - Processes one key per loop tick
  - Renders only when state changed
  - Never blocks on I/O

LEDGER & STATE
================================================================================

State is stored in layers:

  config.txt (mutable game state)
    ├─ current_turn, current_epoch
    ├─ player names, types, positions
    ├─ npc weights (move/word/end)
    └─ Read by ops, updated by ops

  data/master_ledger.txt (immutable history)
    ├─ All actions: words, moves, end_turns
    ├─ Append-only, never modified
    ├─ Format: timestamp|epoch|player|turn|action_data|action_type
    └─ Can replay to recover any past state

Rendering: positions reconstructed from ledger on each frame
  ├─ Start with config starting_positions
  ├─ Replay all MOVE actions from ledger
  ├─ Result: accurate current state
