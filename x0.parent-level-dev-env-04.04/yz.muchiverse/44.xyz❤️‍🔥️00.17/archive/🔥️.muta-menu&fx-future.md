# MUTA-MENU & FX-FUTURE: Mutaclsym Menu Evolution

**Created**: 2026-07-26  
**Status**: Documentation Phase  
**Goal**: Transform mutaclsym's hardcoded menu into dynamic, xelector-driven method system

---

## Current State: Hardcoded Menu

muchaclsym's menu is built directly in `ops/compose_frame.c`:

```c
// From compose_frame.c - hardcoded action bar
<option> [>] 1. pickup
<option> [ ] 2. drop
<option> [ ] 3. eat
<option> [ ] 4. save
<option> [ ] 5. toggle_emoji
<option> [ ] 6. craft
<option> [ ] 7. examine
<option> [ ] 8. Control Hero
```

**Problems**:
1. Menu items are hardcoded strings, not from piece.pdl
2. No dynamic methods based on selected piece
3. "Control Hero" always shows, even when xlector selects non-player piece
4. No export/import methods visible
5. No way to add methods without recompiling

---

## Target State: Dynamic Xelector Methods

### How fuzz-op Does It (Reference Implementation)

From `#.haiku+/tpmos-re-dox/fo-menu-sys.md`:

**Architecture**:
1. **Layout** (`*.chtpm`): Contains `${piece_methods}` variable slot
2. **Manager** (`_manager.c`): Reads piece.pdl, resolves methods, writes gui_state.txt
3. **Parser** (`chtpm_parser.c`): Substitutes variables, renders buttons
4. **PDL** (`piece.pdl`): Defines methods as `METHOD | name | op_path`

**Lifecycle**:
1. Manager reads active piece's `piece.pdl`
2. Manager calls `get_piece_methods_op` to build method markup
3. Manager writes to `gui_state.txt`:
   ```
   active_target=hero
   piece_methods=<button label="move" onClick="KEY:2" /><button label="feed" onClick="KEY:3" />...
   pet_name=Hero
   ```
4. Parser reads gui_state.txt, substitutes `${piece_methods}` in layout
5. User clicks button → parser injects key → manager dispatches to op

### What mutaclsym Needs

**Phase 1: Dynamic Method Display**

1. **Add manager process** (like fuzz-op's `_manager.c`)
   - Read active piece's `piece.pdl`
   - Extract METHOD entries
   - Build button markup
   - Write to `gui_state.txt`

2. **Update layout** (`pieces/chtpm/layouts/game.chtpm`)
   - Add `${piece_methods}` variable slot
   - Replace hardcoded action bar

3. **Update parser** (`system/chtpm_parser_pal.c`)
   - Add gui_state.txt reading
   - Add variable substitution for `${piece_methods}`

**Phase 2: Xelector-Driven Methods**

1. **Context-sensitive menu**
   - When xlector selects hero: show move/pickup/drop/eat/save/etc.
   - When xlector selects monster: show examine/attack/flee
   - When xlector selects item: show pickup/use/drop
   - When xlector selects furniture: show examine/use

2. **Method visibility rules**
   - `METHOD | move | ops/+x/move_player.+x` - always visible
   - `METHOD | export | ops/+x/pet_export.+x` - only when pet selected
   - `METHOD | import | ops/+x/pet_import.+x` - only when on zoo map
   - `METHOD | save | ops/+x/save_game.+x` - always visible
   - `METHOD | load | ops/+x/load_game.+x` - only on title screen

**Phase 3: Export/Import Integration**

1. **Add export method to piece.pdl**
   ```pdl
   METHOD | export | ops/+x/pet_export.+x
   ```

2. **Add import method to piece.pdl**
   ```pdl
   METHOD | import | ops/+x/pet_import.+x
   ```

3. **Conditional visibility**
   - Export only shows when pet piece is selected
   - Import only shows when on map that accepts imports

## Fuzz-Op Architecture Deep Dive

### Project Structure

```
fuzz-op/
├── project.pdl              # Project metadata + states
├── pieces/
│   ├── hero/                # Player piece
│   ├── xlector/             # Selector piece
│   ├── pet_01/              # Pet pieces
│   ├── pet_02/
│   └── world_01/            # Map data
├── ops/
│   ├── end_turn.c
│   ├── open_file_menu_op.c
│   └── toggle_clock.c
├── manager/                 # GUI manager
│   └── fuzz-op_manager.c    # Dynamic method resolver
└── layouts/
    └── fuzz-op.chtpm        # Layout with ${piece_methods}
```

### Manager Pattern

```c
// fuzz-op_manager.c (simplified)
while (1) {
    // 1. Read active target
    char target[64];
    read_kv_str(state_path, "active_target_id", target, sizeof(target), "hero");
    
    // 2. Read piece.pdl methods
    char *methods = get_piece_methods(target);  // Calls pdl_reader
    
    // 3. Write gui_state.txt
    FILE *gui = fopen("gui_state.txt", "w");
    fprintf(gui, "active_target=%s\n", target);
    fprintf(gui, "piece_methods=%s\n", methods);
    fclose(gui);
    
    // 4. Trigger render
    trigger_render();
    
    sleep_ms(30);
}
```

### PDL Method Format

```pdl
# piece.pdl for a pet
SECTION      | KEY                | VALUE
----------------------------------------
META         | piece_id           | fuzzball
METHOD       | feed               | projects/fuzz-op/ops/+x/feed_op.+x
METHOD       | play               | projects/fuzz-op/ops/+x/play_op.+x
METHOD       | sleep              | projects/fuzz-op/ops/+x/sleep_op.+x
METHOD       | scan               | projects/fuzz-op/ops/+x/scan_op.+x
```

### Dynamic Dispatch

```c
// Manager dispatch (simplified)
int key = read_key();
if (key >= '2' && key <= '9') {
    int idx = key - '0';
    char *method_name = pdl_reader(target, "list_methods", idx);
    char *method_op = pdl_reader(target, "get_method", method_name);
    system(method_op);  // Execute the op
}
```

## Implementation Plan for mutaclsym

### Step 1: Create Manager Process

**File**: `ops/menu_manager.c`

**Responsibilities**:
- Read `active_target_id` from `pieces/apps/player_app/state.txt`
- Read active piece's `piece.pdl`
- Extract METHOD entries
- Build button markup (index 2-9)
- Write to `pieces/apps/player_app/manager/gui_state.txt`
- Read key input from `pieces/keyboard/history.txt`
- Dispatch to appropriate op

### Step 2: Update Layout

**File**: `pieces/chtpm/layouts/game.chtpm`

**Changes**:
- Add `${piece_methods}` variable in action bar area
- Remove hardcoded menu items

```xml
<!-- Before -->
<text label="[>] 1. pickup" /><br/>
<text label="[ ] 2. drop" /><br/>

<!-- After -->
${piece_methods}
```

### Step 3: Add PDL Methods to Hero

**File**: `pieces/world_01/map_start/hero/piece.pdl`

**Add**:
```pdl
METHOD       | export             | ops/+x/pet_export.+x
METHOD       | import             | ops/+x/pet_import.+x
METHOD       | save               | ops/+x/save_game.+x
METHOD       | load               | ops/+x/load_game.+x
```

### Step 4: Conditional Method Visibility

**In manager**:
```c
// Only show export if selected piece is a pet
if (is_pet(target)) {
    add_method("export", "ops/+x/pet_export.+x");
}

// Only show import if on import-capable map
if (map_allows_import(current_map)) {
    add_method("import", "ops/+x/pet_import.+x");
}

// Always show these for hero
if (is_hero(target)) {
    add_method("move", "ops/+x/move_player.+x");
    add_method("pickup", "ops/+x/pickup.+x");
    add_method("drop", "ops/+x/drop.+x");
    add_method("eat", "ops/+x/eat.+x");
    add_method("save", "ops/+x/save_game.+x");
}
```

## Key Differences from fuzz-op

| Aspect | fuzz-op | mutaclsym target |
|--------|---------|------------------|
| Manager | Separate daemon process | Same pattern |
| Methods | Pet-focused (feed/play/sleep) | Game-focused (move/pickup/drop) |
| Xelector | Selects pets | Selects any piece (hero/monster/item) |
| Dispatch | `pdl_reader` + `system()` | Direct op execution |
| State | Simple pet state | Complex game state (hp/inventory/map) |

---

## Benefits of This Approach

1. **No recompilation** to add methods - just edit piece.pdl
2. **Context-sensitive** - different pieces show different methods
3. **Consistent with fuzz-op** - proven pattern, existing documentation
4. **Extensible** - add new methods by adding PDL entries
5. **Testable** - manager can be tested independently

---

## Risks & Mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
| Manager overhead | Low | 30ms poll loop is negligible |
| PDL parsing errors | Medium | Extensive validation in manager |
| Method index drift | Medium | Standardize: methods start at index 2 |
| Stale gui_state.txt | Low | Atomic write pattern (tmp + rename) |
