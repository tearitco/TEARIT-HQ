LIVE FIXES FOUND ON FIRST Windows run (2026-08-06)
--------------------------------------------------
1) prisc+x spawn failed (debug: handle=0xffffffff):
   - CreateProcessA cannot open absolute paths with emoji folder names
   - MinGW binaries are name.exe while layout says system/prisc+x
   - Fix: win_spawn uses CreateProcessW + relative path + .exe resolve

2) Frames never updated / Active:(none):
   - PRISC_PROJECT_ROOT absolute Unicode path → fopen fails
   - MinGW opendir/readdir returns 0 entries on OneDrive paths
   - Fix: PRISC_PROJECT_ROOT="." (CWD is project); list dirs with _findfirst

3) After "Ready. Press Ctrl+C":
   - Look for freeglut window "wsr-pal RGB mirror"
   - Terminal renderer may also scroll frames if history mode on
   - If blank: .\button.ps1 kill then re-run; check debug.txt for win_spawn

4) Windows rename() does NOT overwrite (unlike POSIX):
   - write_file_atomic in chtpm_rgb_render must remove() dest first
   - Without this, rgb_frame.raw freezes at first frame → GL never updates

5) button.ps1 run sets SKIP_ORCH_COMPILE=1 so orchestrator does not
   recompile everything on every launch (30-60s stall looked like hang).

6) button.ps1 kill must NOT access Process.Path (hangs). Name-only + taskkill.

7) Terminal "fast scroll / tear" (history mode ON by default):
   - TPMOS: pieces/display/state.txt "off" => in-place clear redraw
     (Windows: Console API clear in windows_renderer.c; Linux: ANSI)
   - History ON still scrolls frames intentionally; file history is
     frame_history.txt / session_frame_history (K3).
   - Windows-specific: write_crlf + CRLF frames can double CR - normalize
     if terminal UX is prioritized. GL path is independent and OK.
   - Full port notes: ../../windows-house-guide.md (house root).
