# gl-canvas Architecture

Minimal Xdnd drop target for pet drag-and-drop. Waits for a pet window
(muchi-pals egg_window) to be dragged onto it, receives the pet_id,
renders the pet's sprite in a GL canvas, and closes the source window.

This is the "hello world" of pet drag-and-drop — the simplest possible
working end-to-end test.

## Directory structure

```
gl-canvas/
  button.sh                  # compile / run / kill verbs
  system/
    gl_canvas.c              # the canvas window (~400 lines)
    import_pet.c             # write import receipt + close request (~80 lines)
    pet_purely.c             # minimal draggable pet window for testing (~350 lines)
  test-harn/

```

Three binaries in system/: `gl_canvas` (drop target), `import_pet` (import
action), `pet_purely` (minimal draggable pet for testing). Plus test harness
tools in test-harn/.

## gl_canvas.c — What it does

A freeglut GL window that:
1. Creates a borderless textured quad (like gl_mirror but smaller)
2. Initializes Xdnd target protocol (receiver only)
3. On drag enter: draws green border (g_drag_over = 1)
4. On drop: receives pet_id via XdndSelection, runs import_pet, closes source
5. After import: renders pet sprite in the canvas

### Window properties

- Size: 200x200 pixels (fixed, no resize)
- Title: "gl-canvas" (used by test harness to find it via XFetchName)
- Position: configurable via drag_drop_test.pdl (gl_canvas_x / gl_canvas_y)
- Background: black
- override_redirect: No (managed by window manager, unlike egg_window)

### Xdnd protocol (receiver side)

Copied from gl_mirror.c and simplified. The receiver side only needs:

1. **init_xdnd()** — Intern atoms, set XdndAware property on window
   - Use freeglut's fgDisplay.Display (same hack as gl_mirror, line 812)
   - Walk root children, find by XFetchName matching "gl-canvas"
   - Call init_xdnd on found window, register glutIdleFunc(check_xdnd_events)

2. **check_xdnd_events()** — XPending loop, dispatch to handle_xdnd_event()

3. **handle_xdnd_event()** — Protocol state machine:
   - XdndEnter: Set xdnd_source, g_drag_over=1, glutPostRedisplay()
   - XdndPosition: Reply with XdndStatus (accepting, l[1]=1, whole window)
   - XdndLeave: Clear g_drag_over, glutPostRedisplay()
   - XdndDrop: Call XConvertSelection(XA_XdndSelection, XA_text_plain, ...)
   - SelectionNotify: Read pet_id from property, call trigger_pet_import()

### trigger_pet_import()

1. Run `import_pet <pet_id>` via system() in background
2. Write `/tmp/egg_window_close_<pet_id>.txt` to signal source to close
3. Set g_drop_pending=1 for visual feedback (2 seconds)

### display()

1. glClear (black background)
2. If pet received: render pet sprite as GL texture (or placeholder quad)
3. If g_drag_over: draw green GL_LINE_LOOP border (4px, inset 95%)
4. If g_drop_pending && time < 2s: draw semi-transparent green overlay
5. glutSwapBuffers()

### Sprite rendering (phase 2 — after drag-drop works)

After the basic Xdnd flow works, add sprite loading:
- Read `<muchi_pals_root>/pieces/world_01/map_lobby/<pet_id>/sprite.csv`
- Sprite.csv is a CSV grid of emoji Unicode codepoints
- Use the emoji atlas PNG (already generated by muchi-pals' emoji_gen_atlas)
- Or: use simpler fallback — render the pet_id string in large text

For the initial version, just render a colored quad with the pet_id as title
and a "RECEIVED: <pet_id>" text overlay. Sprite rendering comes later.

```sh
$CC $CFLAGS -o system/gl_canvas system/gl_canvas.c -lglut -lGL -lGLU -lX11

```

### Environment

- `PRISC_PROJECT_ROOT` — points to gl-canvas directory (for config)
- `MUCHI_PALS_ROOT` — points to muchi-pals directory (for sprite files)
- Both resolved via resolve_root() reading env vars

## import_pet.c — What it does

Tiny op that receives a pet_id and:
1. Creates import receipt at `<PRISC_PROJECT_ROOT>/imported_pets.txt` (append)
2. Writes `/tmp/egg_window_close_<pet_id>.txt` (signals egg_window to close)
3. Prints "imported: <pet_id>" to stdout

```
Usage: import_pet <pet_id>
```

Follows the self-contained op pattern (no shared headers, resolve_root via
PRISC_PROJECT_ROOT, argv[1] as pet_id).

## pet_purely.c — Minimal test pet window

A stripped-down version of egg_window for testing drag-and-drop. Does ONE
thing: opens a small draggable X11/GLX window that can be dragged onto
gl-canvas to trigger a drop.

### What it keeps from egg_window

- Raw X11 + GLX window creation (no freeglut, no GLUT)
- override_redirect borderless window
- Mouse drag: ButtonPress → MotionNotify → ButtonRelease (free-pixel follow)
- Xdnd source protocol (XdndAware, XdndEnter/Position/Drop, SelectionRequest)
- XSetSelectionOwner on ButtonPress (so target can request pet_id)
- XQueryTree target detection (enumerate root children by geometry)
- Command line: `pet_purely <pet_id> [x] [y]`

### What it strips from egg_window

| Feature in egg_window | pet_purely | Why |
|----------------------|------------|-----|
| state.txt polling (grid_x/grid_y/tick_seq) | Removed | No autonomous movement |
| self-tick (shell out to tick_pets) | Removed | No game logic |
| sprite.csv + shape extension masking | Removed | Just draws colored quad |
| drag_drop_test.pdl polling | Removed | Position via argv only |
| Grid snap on drop | Removed | Free-pixel, no grid |
| write_pet_position() | Removed | No state.txt to write |
| Close request file polling | Removed | Test harness kills it |
| Facing direction / icon overlays | Removed | Pure visual |

### Window properties

- Size: 80x80 pixels (same as egg_window's GRID_CELL_PX)
- Title: the pet_id string (used by tk_drag_sim to find it)
- Position: argv[2],argv[3] or default (100,100)
- Background: colored quad (color based on pet_id hash — deterministic)
- override_redirect: Yes (borderless, like egg_window)

### Rendering

Just a solid colored quad. Color is derived from hashing the pet_id string
so each pet gets a unique but deterministic color. This is enough to visually
identify which pet is which during testing.

### Xdnd source (same as egg_window)

Copied from egg_window.c and simplified. The source side needs:
- XdndAware property on window
- ButtonPress → XSetSelectionOwner, track drag start
- MotionNotify → XQueryPointer + XQueryTree to find target, send XdndEnter/Position
- ButtonRelease → send XdndDrop, clean up
- SelectionRequest → send pet_id as text/plain

### Compilation

```sh
$CC $CFLAGS -o system/pet_purely system/pet_purely.c -lX11 -lXext -lGL -lm
```

No freeglut dependency — raw X11 + GLX only.

### Usage

```sh
# Launch pet at default position
./system/pet_purely my_test_pet

# Launch pet at specific position
./system/pet_purely my_test_pet 400 200
```

### tk_open_egg — Launch and position egg_window

```
Usage: tk_open_egg <muchi_pals_root> <pet_id> <x> <y>
```

1. Fork+exec: `cd <muchi_pals_root> && PRISC_PROJECT_ROOT=<muchi_pals_root> ./system/egg_window <pet_id>`
2. Wait 1 second for window to appear
3. Write drag_drop_test.pdl in muchi_pals_root with egg_window_x/egg_window_y
4. Wait 1 second for position to take effect
5. Print the X11 window ID (found by XFetchName matching pet_id) to stdout

### tk_drag_sim — Simulate mouse drag (THE KEY TOOL)

No xdotool. Pure X11. Uses XSendEvent + XWarpPointer.

```
Usage: tk_drag_sim <source_window_title> <target_window_title> [step_delay_ms]
```

Algorithm:
1. Open X11 display (XOpenDisplay(NULL))
2. Find source window by title (walk root children, XFetchName)
3. Find target window by title (same)
4. Get source window geometry (XGetGeometry → center x,y)
5. Get target window geometry (XGetGeometry → center x,y)
6. XWarpPointer to source center
7. usleep(50000) — let X server settle
8. XSendEvent: ButtonPress (Button 1) to source window
9. Loop: 40 steps from source center to target center
   - XWarpPointer: move cursor toward target by 1/40th of distance
   - XSendEvent: MotionNotify to source window (with current root_x/root_y)
   - XSync(dpy, False)
   - usleep(delay_ms) — default 10ms
10. usleep(50000) — let egg_window process last MotionNotify
11. XSendEvent: ButtonRelease (Button 1) to source window
12. XSync(dpy, False)
13. Print "drop simulated: <source> -> <target>"

Key X11 details:
- MotionNotify.xmotion.x_root / y_root = root-window coordinates (used by
  egg_window's XQueryTree to find target)
- ButtonPress.xbutton.x_root / y_root = same
- XSendEvent with send_event=True (bit 30 set) — but egg_window doesn't
  check this flag, so it works
- XWarpPointer moves the ACTUAL cursor (needed because egg_window uses
  XQueryTree on root children, which checks geometry — the actual cursor
  position is what matters for finding which window is under it)

Compilation:
```sh
gcc -Wall -Wextra -O2 -o ops/+x/tk_drag_sim.+x ops/tk_drag_sim.c -lX11
```

### test_drag_drop.sh — Full scenario

```bash
#!/bin/bash
CANVAS_ROOT="/path/to/gl-canvas"
MPALS_ROOT="/path/to/01.muchi-pals"
CANVAS="$CANVAS_ROOT/system"
MPALS="$MPALS_ROOT/system"
HARNESS="$CANVAS_ROOT/test-harn/ops/+x"
PET_ID="user_01_test_egg"  # or pick from registry

# 1. Kill any existing instances
pkill -f gl_canvas; pkill -f egg_window
sleep 1

# 2. Launch gl-canvas
cd "$CANVAS_ROOT" && PRISC_PROJECT_ROOT="$CANVAS_ROOT" "$CANVAS/gl_canvas" &
CANVAS_PID=$!
sleep 2

# 3. Launch egg_window with test pet
"$HARNESS/tk_open_egg.+x" "$MPALS_ROOT" "$PET_ID" 400 200
sleep 2

# 4. Simulate drag from egg_window to gl-canvas
"$HARNESS/tk_drag_sim.+x" "$PET_ID" "gl-canvas" 10
sleep 2

# 5. Check results
# - Is /tmp/egg_window_close_<PET_ID>.txt gone? (consumed by egg_window)
# - Is imported_pets.txt created with this pet_id?
# - Is egg_window still running? (should have closed)

# 6. Cleanup
kill $CANVAS_PID 2>/dev/null
pkill -f egg_window
```

## Xdnd protocol flow (complete)

```
egg_window (source)              gl-canvas (target)
     |                                |
     | ButtonPress on egg_window      |
     | -> XSetSelectionOwner          |
     |                                |
     | MotionNotify (cursor over      |
     | gl-canvas via XQueryTree)      |
     | -> XdndEnter ------->         | handle: g_drag_over=1, redraw (green border)
     | -> XdndPosition --->          | handle: XdndStatus (accepting)
     |                                |
     | ... more MotionNotify ...      |
     | -> XdndPosition --->          | (same)
     |                                |
     | ButtonRelease on egg_window    |
     | -> XdndDrop -------->         | handle: XConvertSelection()
     |                                |
     |   SelectionRequest <---------  | (X server asks source for data)
     | -> SelectionNotify ----->      | (sends pet_id as text/plain)
     |                                | handle: got pet_id
     |                                | -> run import_pet(pet_id)
     |                                | -> write /tmp/egg_window_close_<pet_id>.txt
     |                                | -> redraw (green overlay 2s)
     |                                |
     | XdndFinished <--------        | (target says "done")
     | handle: clean up               |
     |                                |
     | Close request file detected    |
     | -> exit(0)                     |
```

## What gl_canvas strips from gl_mirror

| Feature in gl_mirror | gl_canvas | Why |
|---------------------|-----------|-----|
| RGB frame texture pipeline (rgb_frame.raw, receipt polling) | Removed | Canvas shows pet sprite, not game frames |
| CHTPM keyboard bridge | Removed | No keyboard input needed |
| Focus lock management | Removed | Single window, no focus arbitration |
| Freeglut fgDisplay.Display hack | KEPT | Required for Xdnd on same connection |
| Xdnd receiver protocol | KEPT (simplified) | Core functionality |
| trigger_pet_import() | KEPT | Core functionality |
| Green border on drag | KEPT | Visual feedback |
| Green overlay on drop | KEPT | Visual feedback |
| display() with texture quad | Simplified | Colored quad + text, not texture pipeline |
| reshape() | Simplified | Fixed 200x200, no dynamic resize |
| Timer-based texture reload | Removed | No rgb_frame to poll |
| write_gl_display_receipt() | Removed | No pipeline verification needed |
| Test config polling | KEPT | For test harness positioning |
| Signal handler | KEPT | Graceful shutdown |
