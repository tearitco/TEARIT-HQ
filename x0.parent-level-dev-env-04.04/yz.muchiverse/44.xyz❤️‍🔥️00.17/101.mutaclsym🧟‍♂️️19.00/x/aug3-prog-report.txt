2. REAL BUGS FOUND AND FIXED DURING LIVE TESTING
--------------------------------------------------------------------------------
These were all found by actually running the game, not by code review:

1. **RGB mirror window opened but showed nothing.** Root cause: the entire
   `pieces/registry/fonts/ascii/` glyph-bitmap directory (95 real font
   glyphs) was missing from piececraft-xyz - `chtpm_rgb_render` needs this
   to draw any text at all. Copied from the house's canonical
   `014.wsr-pal💸️📌️+2/pieces/registry/fonts/ascii/` source (same place
   civ-txt's own copy came from). Verified: 0 → 10,321 nonzero rendered
   pixels.

2. **Board-viewer widget opened but showed a totally blank/black window.**
   Root cause: `&.widgits/board-viewer/ops/+x/bv_compose_frame.+x` and
   `bv_menu_input.+x` were **0-byte empty files** - never actually
   compiled, ever, in this environment. Ran board-viewer's own
   `scripts/build.sh` for real. This wasn't a piececraft-xyz bug - every
   project using this shared widget would have hit the same thing.

3. **"View Board" appeared to do nothing / showed flat boring terrain.**
   Root cause: a `board_manifest.txt` file I'd created for testing
   Z-level switching (see §3) was left behind in the real project,
   silently overriding the real generated board with flat single-glyph
   test data. Deleted once the Z-level feature itself was confirmed
   working.

4. **Board-viewer widgets clobbered each other across different games.**
   Pressing "View Board" in tactics-txt stole piececraft-xyz's
   already-open widget window, and the reverse. Root cause: board-viewer
   was a single global shared singleton (by original design - "there's
   only ever meant to be one, discover and reuse it") with no per-project
   scoping at all.
   **Real fix, applied to civ-txt, tactics-txt, AND piececraft-xyz alike:**
   - `board-viewer/button.sh` now registers on the shared ledger as
     `board-viewer:<host_project_name>` instead of a bare `board-viewer`
     identity - each host gets its own independently-discoverable widget.
   - Each host's own `OPEN_BOARD_WIDGET` handler (`civ_menu_input.c`,
     `tactics_menu_input.c`, `pc_menu_input.c`) now scans ALL ledger_peers
     output lines for the one matching ITS OWN scoped identity, instead of
     blindly taking the first line.
   - **Second-order bug caught in the same investigation:** even with
     correct scoping, a host that restarts while its OLD board-viewer
     widget is still alive (crash, force-kill, etc) would silently
     refocus that orphaned widget instead of spawning a visible new one -
     looked exactly like "the board didn't open." Fixed with a two-layer
     defense in every host's `button.sh`: `kill_own_board_widget()` now
     runs on both fresh START (safety net) and graceful QUIT (Ctrl+C),
     so an orphan can never survive a restart.

4. BOARD-VIEWER EXTENDED: REAL MULTI-Z CHUNK DISPLAY (done, verified)
--------------------------------------------------------------------------------
Board-viewer could previously only render one flat `board.txt` file - no
concept of Z-levels or chunk directories. Extended (shared widget code,
affects civ-txt/tactics-txt too, but zero-behavior-change for them):

- `bv_compose_frame.c` now reads an OPTIONAL `pieces/system/
  board_manifest.txt` (`z_base=...`, `z_count=N`) - if present, resolves
  board data from `{z_base}{current_z}.txt` instead of the flat
  `board.txt`. A host with no manifest (civ-txt, tactics-txt) is
  completely unaffected - falls back to the exact old behavior.
- `bv_menu_input.c` adds real `z`/`x` key handling to increment/decrement
  `current_z` in `bv_state.txt`, matching the real mutaclysm precedent
  (with one flagged, deliberate divergence: mutaclysm gates z/x to
  3D-mode-only, but this project's 3D per-layer voxel rendering doesn't
  exist yet, so it was made to work in 2D too - real per-Z 3D rendering
  is later work).
- A display-clamping bug (status line could show "Z-level: 3 / 2" - past
  the valid range, even though the actually-rendered layer was correctly
  clamped) was caught live during testing and fixed.
- **Verified live**: built a hand-made 3-layer test chunk (plains/forest/
  hills per layer) and confirmed pressing `x` correctly switched the
  displayed terrain layer.
