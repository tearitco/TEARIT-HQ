    FreeType color bitmap (Segoe UI Emoji on Win: C:/Windows/Fonts/seguiemj.ttf)

    stb_image load PNG → NxN RGBA CSV (sprite.csv)
    Format egg_window / tp_desktop_window both understand:
      # resolution=N

  NOT GDI text. Color emoji is a TEXTURE, never a font string.

1.4 Context menu (Win half)
  WM_RBUTTONUP → TrackPopupMenu (Close etc.)
  Same interaction class as livedesk METHOD menus, simpler item list.

1.5 Lesson for house convention
  Ref button.ps1 is a bash forwarder. House doctrine now prefers NATIVE
  button.ps1 (014.wsr, $.crypts) that does not require Git-Bash for
  compile/run/kill. Next muchi button.ps1 should follow 014/crypts style,
  not reintroduce bash-only as the only path (bash optional for sh parity).

4. Why book-stack is a blue square (detail)
======================================================================

tp_desktop_window_win.c WM_PAINT:
  HBRUSH blue → FillRect entire client
  DrawTextA "[N] book-stack\n📚"  — glyph string is UTF-8; GDI A path +
  system font will not show color emoji (often tofu/box/missing).

Linux path would:
  load_sprite_csv("<package>/sprite.csv")
  glClear + draw textured quad
  optional shape mask so only emoji silhouette is opaque

book-stack HAS sprite.csv + atlas.png. Fix is render path, not re-convert,
unless CSV is empty of opaque pixels (then re-run emoji_gen with Segoe).

5. Why RMB does not open KHTPM context window
======================================================================

Linux (tp_desktop_window.c):
  Button3 / right-click → open_context_menu()
    - load METHOD rows from meta.pdl and/or objects.pdl pages
    - override_redirect popup, nav claims, ACTIVATE_NAV, CLOSE, shell cmds
    - Show Text / Show Choices helpers (khtpm_show_*)

Win stub:
  WM_RBUTTONUP → append_history + DestroyWindow  (deliberate stub shortcut)

Required for parity:
  Port open_context_menu semantics to Win32:
    Option A (fast, matches egg-pals): TrackPopupMenu built from METHOD
      labels; execute action string via CreateProcess / system.
    Option B (closer to Linux look): second WS_POPUP "context" HWND with
      row list, nav digits, same measure_context_popup_w logic.
  Prefer A first for reliability; B for visual parity with Linux livedesk.

Also: meta.pdl METHOD commands still embed /home/no/... absolute paths
(see !.linux-absolute-FIXME-a6.txt). Even a perfect menu will fail to
launch Chat/Events/Play until those rows are relative or expanded.

6. "Convert solo PNG of asa/ava" — clarify
======================================================================

Two different operations users may mean:

  (1) glyph/emoji → atlas.png + sprite.csv
      Already done for ava/asa/book-stack on this tree (files present).
      Toolchain: emoji_gen_atlas + emoji_xtract (house copies under
      01.muchi-pals/system/ and used by tp_place_desktop on Linux).

  (2) arbitrary artist PNG (not emoji) → sprite.csv
      emoji_xtract can crop an atlas cell; for a solo full-frame PNG
      you still run emoji_xtract with index 0 if atlas is single-cell,
      OR add a "png_to_sprite_csv" helper (resize + write CSV) —
      egg-pals xtract already area-averages a cell to NxN.

  (3) display converted asset in a desk window
      This is the FAIL on Windows today (stub).

Prescription: do not re-convert first; prove sprite.csv loads under WGL.
If texture is blank, re-run gen with Windows emoji font.
