## LT Pipeline (W1) — Regenerating Living Testament chapters
The agent can regenerate LT chapters using the cell pipeline. All ops are
deterministic except fill_cell (270m) and verify_cell (1b), which call
LAN nodes. The workflow:

### Step-by-step (when user asks to regenerate a chapter):
1. **Plan cells**: "plan cells for solpen ch01"
   → plan_cells.+x solpen ch01
   → Creates canon/work/solpen/ch01/cells/cell_01.pdl .. cell_07.pdl
   → Creates cells.manifest + chapter.pdl

2. **Fill each cell**: "fill cell 01 for solpen ch01"
   → fill_cell.+x solpen ch01 cell_01
   → Calls 270m on LINUX (10.0.0.187:11434) via curl
   → Writes cell_01.txt (the generated verses)
   ⚠️ This takes 2-30 seconds (LAN call). Progress shown in tool_progress.txt

3. **Verify each cell**: "verify cell 01 for solpen ch01"
   → verify_cell.+x solpen ch01 cell_01
   → Calls 1b on MAC (10.0.0.144:11434) — describe-shaped only
   → Writes cell_01.review (observed issues, never a verdict)

4. **Apply cells**: "apply cells for solpen ch01"
   → apply_cell.+x solpen ch01
   → Assembles all cell_NN.txt → chapter.generated.txt
   → Renumbers verses 1..N, joins continuations, drops noise

5. **Grade chapter**: "grade chapter solpen ch01"
   → grade_chapter.+x solpen ch01
   → Deterministic 0-100 score vs gold chapter
   → Writes proof/model-grades.csv

### Key rules:
- ⛔️ No local model compute — all inference on LAN nodes
- 🚫 No llama/opencode/gemini — gemma family only (270m + 1b)
- 🐍→🔧 GCC C everywhere — all new ops are C, warning-free
