======================================================================
0. Vocabulary (do not conflate)
======================================================================

CHTPM  = full session pipeline (button.sh run):
           keyboard_input / chtpm_parser_pal / prisc+x / renderer /
           chtpm_rgb_render / gl_mirror (+ .chtpm layouts)
         Example: tile-picker's own picker UI (&.widgits/tile-picker/button.sh).

KHTPM  = house-own "livedesk entity window" convention (informal name,
         walk-off-au5 / TILE_PICKER_DESIGN):
           ONE binary: tp_desktop_window.+x
           Raw X11 + GLX (NOT freeglut, NOT chtpm_parser_pal)
           Per-package history.txt + interact_relay.txt
           objects.pdl multi-page menus, nav claims, taskbar tabs
         Every pet / asa / ava / MUCHI_RANCHER monster on the desk uses
         this same binary with a different <package_dir> argument.

$.crypts does NOT launch full CHTPM sessions for each entity.
It launches KHTPM windows + the livedesk taskbar (and optionally mounts
a volume). That is why this plan is titled KHTPM-first, not
"port every CHTPM app."

1. What $.crypts is
======================================================================

Path:  $.crypts/
Role:  House-wide autostart controller (manual + optional XDG login).

Files today:
  button.sh                 Linux entry (run/on/off/status/compile/check/install-xdg)
  autostart.pdl             STATE | MOUNT | LAUNCH rows
  ops/crypt_autostart.c     The real worker binary
  ops/+x/crypt_autostart.+x Compiled op
  enable_xwayland_grabs.sh  GNOME/Wayland XGrab allowlist (Linux compositor only)

No button.ps1 yet.

button.sh actions (must mirror in button.ps1 later):
  run|r|start|restart  compile if needed; run crypt_autostart.+x <autostart.pdl>
  on / off             toggle STATE|enabled in autostart.pdl (sed -i)
  status               grep enabled
  compile|c|build      gcc crypt_autostart.c
  check                binary + pdl exist
  install-xdg          write ~/.config/autostart/*.desktop (Linux-only)

======================================================================
2. Runtime pipeline (crypt_autostart.+x)
======================================================================

2.1 Resolve PDL
  - argv[1] or default via readlink("/proc/self/exe") walking up to
    <house>/$.crypts/autostart.pdl
  - Windows has no /proc/self/exe → need GetModuleFileName / _fullpath

2.2 Parse autostart.pdl (SECTION|KEY|VALUE)
  STATE | enabled | 0|1
  MOUNT | uuid | ...
  MOUNT | mountpoint | ...
  LAUNCH | <label> | <shell command string>

2.3 If enabled=0 → no-op exit 0

2.4 quit_current_livedesk(house_root)  [HEAVY LINUX]
  - Read #.desktop/livedesk_open.txt → write CLOSE into each entity
    interact_relay.txt
  - SIGTERM taskbar pid from livedesk_taskbar.pid
  - usleep; SIGTERM entity PIDs still alive
  - Scan /proc/*/cmdline for tp_taskbar / tp_desktop_window containing
    house_root → SIGTERM
  - Clear livedesk_open.txt, livedesk_nav_claims.txt, unlink taskbar pid

2.5 MOUNT (optional)
  - Check /proc/mounts
  - udisksctl mount -b /dev/disk/by-uuid/<uuid>
  - Windows: no-op or optional drive letter policy (see §6)

2.6 LAUNCH each command
  - system("setsid nohup <cmd> >/dev/null 2>&1 &")
  - Windows: CreateProcess / Start-Process without setsid/nohup

3. What autostart.pdl currently launches (this house copy)
======================================================================

All LAUNCH rows use HARDCODED Linux absolute paths under a Linux home
tree (not this Windows checkout path). That alone makes a naive port
fail even if binaries existed.

Current targets (logical):

  (1) tool-bar
      bin:  &.widgits/livedesk-taskbar/ops/+x/tp_taskbar.+x
      arg:  <house_root>

  (2) m6_golddeity
      bin:  &.widgits/tile-picker/ops/+x/tp_desktop_window.+x
      arg:  @.apps/MUCHI_RANCHER/entities/m6_golddeity

  (3) book-stack
      bin:  tp_desktop_window.+x
      arg:  #.desktop/entities/book-stack

  (4) ava
      bin:  tp_desktop_window.+x
      arg:  #.desktop/entities/ava

  (5) asa
      bin:  tp_desktop_window.+x
      arg:  #.desktop/entities/asa

So one run = 1 taskbar + N KHTPM entity windows (not N CHTPM stacks).

REQUIRED PDL FIX (any OS, especially Windows):
  Replace hardcoded /home/no/Desktop/... paths with house-relative
  resolution inside crypt_autostart (or rewrite PDL to relative
  templates and expand against house_root). Absolute Linux paths must
  not remain load-bearing.

4. KHTPM stack surface (what "needs the same treatment")
======================================================================

4.1 Core binaries (X11/GLX — hard part)

  &.widgits/tile-picker/ops/tp_desktop_window.c   (~140KB, largest)
    - Xlib, XShape, GLX, XGrabKeyboard/Pointer
    - override_redirect desktop stamps
    - objects.pdl menus, nav claims, soft focus, history/relay
    - spawns/ensures taskbar
    - polls package_dir/glyph.txt, desktop_pos.txt writeback

  &.widgits/livedesk-taskbar/ops/tp_taskbar.c      (~42KB)
    - Xlib bar, tabs, Nav digit jump, shortcuts, close
    - reads #.desktop/livedesk_open.txt
    - talks to entities via interact_relay ACTIVATE_NAV / raise

  These are NOT freeglut gl_mirror. They are raw X11 + GLX, same class
  as 01.muchi-pals egg_window. Windows needs either:
    A) Win32 + WGL (or ANGLE) port of the windowing layer, OR
    B) Temporary stub that logs "KHTPM not on Windows yet" while
       crypts still mounts/toggles, OR
    C) Run under WSLg/X server if available (not a real house product
       path; document only).

  Recommendation for first implementation phase:
    - Port crypt_autostart + button.ps1 + relative PDL first
    - Port tp_taskbar + tp_desktop_window windowing as a second
      work package (shared Win32 "livedesk_window" shim if possible)
    - Do NOT pretend freeglut is a drop-in for GLX override_redirect

4.2 Related but separate: tile-picker CHTPM session

  tile-picker/button.sh launches a FULL CHTPM session (parser, prisc,
  gl_mirror, rgb_render) for the *picker UI* itself. That is the
  014.wsr-style treatment (button.ps1, relative root, freeglut mirror).

  $.crypts does NOT invoke tile-picker/button.sh today. Porting crypts
  does not require tile-picker CHTPM session first — only the KHTPM
  desktop binary that tile-picker owns as source.

4.3 House-wide livedesk state files (already relative-friendly)

  #.desktop/livedesk_open.txt
  #.desktop/livedesk_nav_claims.txt
  #.desktop/livedesk_taskbar.pid
  #.desktop/livedesk_master_ledger.txt
  #.desktop/livedesk_next_index.txt
  #.desktop/entities/<name>/  (packages: glyph, meta.pdl, objects.pdl, …)

  These are plain files + PIDs. On Windows: same files; PID kill uses
  TerminateProcess / taskkill (no /proc).

5. Linux-only APIs inventory (crypt_autostart + KHTPM)
======================================================================

crypt_autostart.c
  - readlink("/proc/self/exe")
  - /proc/mounts, /proc/<pid>/cmdline
  - kill(SIGTERM), pid_alive via kill(0)
  - setsid + nohup via system()
  - udisksctl mount
  - dirname() mutates buffer (POSIX)
  - usleep

tp_desktop_window.c / tp_taskbar.c
  - XOpenDisplay, XCreateWindow, override_redirect, XShape
  - glXCreateContext / glXSwapBuffers
  - XGrabKeyboard / XGrabPointer (Wayland: enable_xwayland_grabs.sh)
  - select() on X connection fd
  - Possibly /proc for taskbar ensure

Windows mapping sketch (for later implement phase):

  /proc/self/exe     → GetModuleFileNameW
  kill / proc scan   → OpenProcess + TerminateProcess; CreateToolhelp32Snapshot
  setsid nohup &     → CreateProcess CREATE_NEW_PROCESS_GROUP | DETACHED
  udisksctl          → skip, or document manual drive letter; optional
                       mountvol if UUID known
  X11/GLX window     → Win32 HWND + WGL (or GDI stub for non-GL bar)
  XGrab*             → SetCapture / SetForegroundWindow (different model)
  gsettings Wayland  → N/A on Windows (enable_xwayland_grabs.sh stays Linux)

7. Testing plan (K3-aligned, KHTPM-adapted)
======================================================================

Crypts / KHTPM do not use current_frame.txt the same way as CHTPM.
Evidence sources differ:

  KHTPM entity package:
    <package>/history.txt
    <package>/interact_relay.txt
    <package>/desktop_pos.txt
    <package>/glyph.txt / meta.pdl / objects.pdl

  House livedesk:
    #.desktop/livedesk_open.txt
    #.desktop/livedesk_nav_claims.txt
    #.desktop/livedesk_taskbar.pid

  Crypts:
    autostart.pdl STATE
    stdout of crypt_autostart (launch/mount lines)

Suggested report name:
  KHTPM_WIN_REPORT_<yyyyMMdd-HHmm>_<topic>.txt  (root or $.crypts/)

Gates for Phase 1:
  R1  button.ps1 compile/check/status PASS
  R2  enabled=0 run is no-op PASS
  R3  relative house_root resolution PASS (no /home/no/... required)
  R4  quit_current_livedesk does not crash when registries empty PASS

Gates for Phase 2:
  R5  one tp_desktop_window process + visible window PASS
  R6  CLOSE via interact_relay exits window PASS
  R7  taskbar appears; tab for open entity PASS
  R8  ACTIVATE_NAV / digit jump moves focus PASS

Do not claim "desktop works" until R5–R8.

======================================================================
8. Risks / unknowns (call out before coding)
======================================================================

1. tp_desktop_window.c is ~140KB of X11/GLX — largest single port risk
   in this pipeline. Underestimate = disaster.

2. override_redirect + XShape transparency ≠ Win32 borderless by default;
   visual parity will take iteration.

3. Keyboard grab semantics on Win32 differ (focus model, not XGrab).

4. autostart.pdl absolute paths are a landmine even on Linux if the
   machine/user path changes; relative expansion is a correctness fix
   for all OS.

5. Mount UUID volume: may be irrelevant on this Windows machine;
   keep optional.

6. Do not confuse tile-picker CHTPM session port with KHTPM binary port.

7. Multiple entity windows = multiple processes; kill must be name-based
   (no Get-Process .Path hang — see windows-house-guide.md).

11. One-page summary
======================================================================

$.crypts = PDL-driven launcher that:
  (a) quits existing livedesk
  (b) mounts a volume (Linux)
  (c) starts tp_taskbar + several tp_desktop_window (KHTPM) entities

Windows work is two layers:
  Layer A — portable launcher (button.ps1, crypt_autostart, relative PDL)
  Layer B — replace X11/GLX in tp_desktop_window + tp_taskbar

Layer A is ready to schedule after this review.
Layer B is the hard project; size and X11 surface justify a separate
design pass with a call-site matrix before coding.
