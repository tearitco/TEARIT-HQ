## 🧭 0. The one correction that reshaped everything

Two rounds of direct correction, both real, both before any code was
written:

**Round 1 — Editor vs Player.** Real RPG Maker MZ is two separate
top-level experiences: the Editor (what you build in) and the Player
(a separate window that only exists once you hit Playtest). My first
draft designed a Title Screen as the default boot target — backwards.
Title Screen belongs to Player mode, reached via a real Playtest
action FROM the Editor.

**Round 2 — what's ON the Editor screen.** My second draft still had
mutaclysm's own survival actions (pickup/drop/eat/craft/examine/help)
visible on the main/default screen, just visually reorganized. Direct
correction, quoted: **"there is not dropping or eating, etc, we are
making an RPG Maker clone, only we need the RPG Maker options on
screen not mutaclysm."** Those actions are PLAYER-mode content —
they belong behind Playtest, not on the Editor's own home screen at
all.

**Round 2 also corrected the screen SHAPE.** My second draft split
"Editor Home" (a dashboard) and the real map view into two separate
screens. The real reference (`slop-ed-dev.chtpm`, TPMOS — read
directly, in full, from TWO separate snapshots, byte-identical
between them, confirming this is a settled, not a moving target)
puts them on **one single screen**: title → project row → map row →
real map render → status row → MAPS/GLYPHS pickers → toolbar row, all
together. Direct instruction: **"I want u to copy this first, then
we will add more RPG Maker toolbar"** — copy the real, working
slop-ed-dev shape as the baseline, then extend it with the real RPG
Maker MV/MZ toolbar (New/Open/Save, Cut/Copy/Paste/Delete, Map/Event
mode, Layer select, Database, Plugin Manager, Resource Manager,
Character Generator, Playtest — the project owner's own real,
complete list, given directly).

## 🏗️ 2. The real two-mode structure

```
button.sh run
      │
      ▼
┌─────────────────────┐         ▶️ Playtest        ┌──────────────────┐
│   🛠️ EDITOR (default) │ ─────────────────────────▶ │  🎮 PLAYER mode   │
│   editor_home.chtpm   │                             │  title.chtpm →   │
│   (real map + real    │ ◀───────────────────────── │  game.chtpm       │
│   RPG Maker toolbar)  │      ⏹️ Stop Playtest       │  (pickup/drop/    │
└─────────────────────┘                             │  eat/craft/etc.,  │
                                                      │  UNCHANGED today) │
                                                      └──────────────────┘
```

- **Editor mode** (`editor_home.chtpm`) is the default boot target and
  the ONLY screen with the RPG Maker toolbar on it. No survival
  actions here at all.
- **Player mode** (`title.chtpm` → `game.chtpm`) is reached ONLY via
  a real "▶️ Playtest" action. This is where pickup/drop/eat/craft/
  examine/help/save/toggle_emoji live — exactly as they exist TODAY,
  no redesign needed there beyond the visual polish already agreed
  (Round-2-unaffected: wrap-around methods, `<row>`-based status line
  — see §5).
- Real, both-directions traversal: Editor → Playtest → Title → New
  Game/Continue → `game.chtpm` → "⏹️ Stop Playtest" → back to Editor.

## 🎮 4. Player mode — unchanged in substance, minor visual polish only

`title.chtpm` (new, small): New Game / Continue / Options / Back to
Editor. `game.chtpm`: **stays exactly what it is today** —
pickup/drop/eat/craft/examine/help/save/toggle_emoji, Control Hero,

- Method list wraps 3-per-line instead of one-per-line (real
  technique: no forced `<br/>` per button, let the frame composer's
  own text-wrap handle it — see `claude-rtp-gui-view.txt` for the
  exact `load_dynamic_methods()` change, scoped to rtp-xyz's own
  local copy only, zero blast radius elsewhere).

  text line.
- A new "⏹️ Stop Playtest" link back to `editor_home.chtpm` (not to
  Title — stopping playtest is an Editor-level action).

## 📏 5. Real constraints (unchanged from the prior draft, still load-
   bearing, repeated here so this doc is self-contained)

| Constraint | Real value | Source |
|---|---|---|
| GL chrome window | 80 cols × up to 48 rows, 640×768px, 8×16px glyphs | `system/chtpm_rgb_render.c` |
| GL window sizing | dynamic, re-read per frame from `rgb_frame.receipt.txt` | `system/gl_mirror.c` |
| 2D terminal | same `current_frame.txt` buffer, mirrors chrome automatically | `system/renderer.c` |

**`chtpm_rgb_render.c` rasterizes whatever `current_frame.txt`
contains, chrome included, with zero awareness of tag semantics** —
design once in CHTPM markup, it renders correctly in both the
terminal and the GL mirror window automatically. No GL-specific code
needed for any of this.

Real, already-built element types available today (confirmed present
in rtp-xyz's own local `chtpm_parser_pal.c`, zero new engine code
needed):
- `<row label="...">` — auto-padded, auto-bordered full-width line.
- `<scroller id="X" label="${var}">` — auto-formatted, numbered,
  ID-labeled interactive row (the real primitive behind MAPS/GLYPHS).

Nav rules unchanged: no mouse, digit-accumulator + Enter-commit, href
= full layout transition, `<module>` = per-layout daemon gated by
`is_active_layout()`.

**⚠️ PITFALL 68** (found this session): a bare `${custom_var}`
injection point only re-renders when `piece_methods`/`active_
target_id`/`input_text` change. Any new screen's dynamic list content
(MAPS/GLYPHS scrollers, the toolbar row if any part of it becomes
real+dynamic) must ride on `piece_methods` by name, not a custom
variable, unless there's no competing `active_target_id`.

**⚠️ PITFALL #99**: custom `onClick` values need a real prefix
(`SET_`/`KEY:`/etc.) or they're silently dropped.
