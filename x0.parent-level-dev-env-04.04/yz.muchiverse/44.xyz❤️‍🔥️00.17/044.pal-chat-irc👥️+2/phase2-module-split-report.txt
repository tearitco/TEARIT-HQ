## WHAT THIS IS AND WHY

Same Phase 2 house-wide change as 041.pal-chain⛓️'s own
phase2-module-split-report.txt - read that file for the full
reasoning. This file only covers what's specific to pal-chat-irc.

Note: this project's p2p layer (the real thing this project tests -
see this session's own earlier "real testing of the p2p layer" work)
was NOT touched by this change. Phase 2 only affects the <module>
string each .chtpm layout launches; it has nothing to do with the
peer-to-peer networking code.

## WHAT WAS DONE HERE

Before: all 3 layouts (login, room_list, room) shared one
<module>system/prisc+x pal/main_loop_chtpm.pal</module>.

After: 3 new files, same content as the old shared loop, one per
screen:
    pal/login_module.pal
    pal/room_list_module.pal
    pal/room_module.pal
Each layout's <module> line updated to point at its own file.

clear_saved_active_index() (PITFALL 66) ported into this project's own
local system/chtpm_parser_pal.c, called immediately before every real
layout-transition parse_chtm() site. Debug-spam printf lines were
already absent from this project's load_vars() before this work -
nothing to remove here.

## WHAT WAS NOT CHANGED

Shared ops binaries were NOT split per-screen. The real p2p/networking
code is entirely untouched by this change.

## VERIFICATION

Re-verified live 2026-07-31: all 3 pal/*_module.pal files exist, all 3
layouts' <module> lines point at their own file, clear_saved_
active_index appears 9 times in chtpm_parser_pal.c. Real K3 harness
(test-harn-same/scenarios/demo_2user_chat.sh, the same one built
earlier this session for the real p2p test pass) was confirmed
PASSING after the split was applied - not re-run again for this doc.

## IF YOU HIT A BUG HERE

1. Doubling/dropped keystrokes: read #.haiku+/double-wr-grok-j31.txt
   first - already root-caused and fixed house-wide.
2. Stale focus after a transition: confirm clear_saved_active_index()
   is actually CALLED at the specific transition site involved.
3. A real p2p/networking bug is almost certainly unrelated to this
   Phase 2 change - look at the p2p code paths directly, not here.
