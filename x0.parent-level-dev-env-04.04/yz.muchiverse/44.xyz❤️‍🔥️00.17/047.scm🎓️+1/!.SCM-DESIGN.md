## 0️⃣ THE ONE-SENTENCE VERSION

**An SCM (Student-Curriculum Model) doesn't generate language — it LEARNS TO
CHOOSE which phrase to say from a tiny, human-written corpus (a "curriculum"),
where choice is biased by plain-text weights, coherence is guaranteed by an
FSM/bandit skeleton, and every choice is graded by gemma via the
describe-don't-classify judge shape.**

Category name: **SCM — Student-Curriculum Model** (parallel to "transformer",
"LLM", "FSM"). The "student" learns a selection policy; the "curriculum" is the
small human-readable phrase bank it chooses from.

## 2️⃣ THE CORE BET — SELECT, DON'T GENERATE

Both tiny models (`iqabod`, `T@Q`) keep failing at **token generation**
(word-salad, <UNK> noise, <PAD> flooding — all visible in `iqa-fork/log.pdl`
early rows). But the same log shows the model DOES master **phrase-level
recall** once it has data. So instead of asking a tiny model to *write*, ask it
to *choose*:

- The **corpus is the action space** — the same discrete-action setting RL
  already wins at (Mario/Pokémon, and your JS game thread). Picking a phrase is
  picking a button.
- **Grammar & vocabulary come free** — a human wrote every phrase.
- **The <UNK>/closed-vocab problem disappears** — every phrase is in-vocab by
  construction (kills the exact-match-tokenizer trap from ROADMAP §4).
- **Weights are readable text** — a game designer edits an NPC's "deck" like a
  character sheet; RL tunes it like a trainer.
- **The judge stays honest** — gemma *describes* (what it's good at); our code
  *scores* (what it isn't).

The one-skill ladder: small talk FIRST (the probe iqa-fork already tracks),
then topic packs, then roleplay packs. The router (below) decides which
curriculum is live.

## 3️⃣ COMPONENTS (5 pieces + memory)

### 3.1 CURRICULA — a folder is a curriculum
```
corpuses/<name>/
├── phrases.txt        # one candidate utterance per line, {slots} allowed
├── weights.txt        # the BASE weight file (readable, RL-editable, lockable)
├── meta/<situation>.txt  # "META WEIGHTS" — per-situation override files
└── curriculum.pdl     # metadata: reply shape, temperature, features, intents
```
- `phrases.txt` is the "deck of cards" — small (v1: 10-30 lines). Human-written
  or teacher-authored (§7).
- `weights.txt` row: `phrase|bias|w_f1|w_f2|...|lock` — one column per feature
  listed in `curriculum.pdl`. `lock` = `-` free, `floor:X`, `ceil:X`, or `hard`.
- `meta/<situation>.txt`: per-situation deltas applied ON TOP of base weights.
  Row = `phrase-or-*|delta`. `*` = global offset for that situation ("grumpy NPC"
  = a meta file that drags every phrase down a bit, and drags cheerful phrases
  down harder). THIS is the "weights/ meta weights for words/ curriculum/
  specific situations" ask — three layers: phrase weights (base), situation
  overrides (meta), curriculum routing (below).
- `curriculum.pdl`: `reply_shape` (`single` | `sequence(N)` | `template`),
  `temperature`, `features` (the w_* column list), `intents` (which intent
  buckets route here), `fallback` (generic phrase if nothing fits).

### 3.2 ROUTER — "is this small talk, a topic, or roleplay?"
Deterministic first (house rule), gemma only when ambiguous:
1. **Deterministic pass** (fast, free, runs on this box): keyword/pattern
   matches on the user message → intent buckets: `casual`, `topic:<name>`,
   `game:<scenario>`. Roleplay (`/rp <pack>`) is **slash-command gated for v1**
   (S5) — auto-detection deferred.
2. **Gemma fallback** (ambiguous topic/game): ask gemma to *describe* the intent
   in one open sentence → deterministic scorer maps description → intent bucket
   (the describe-don't-classify shape, again — never "classify this as A/B/C").
3. **Hard switch** (S4): load the target curriculum (and FSM scenario if game
   dialogue), replacing the previous active one. `intent.conf` maps bucket →
   curriculum, so "add a roleplay pack" = add a line (and a `/rp` route).

### 3.3 SKELETON — FSM for game dialogue, bandit for casual chat (hybrid)
- **Game dialogue** (quest, shop, guard): real FSM — `states.txt`,
  `transitions.txt`, `on_tick.pal` (ROADMAP §6.1 shape). Each state declares:
  which phrases are allowed, which reply shape, and its rules. **Coherence is
  GUARANTEED by the skeleton** — you cannot skip open→offer→deal→close.
- **Casual chat**: a "free bandit" state — no hard transitions, sample from the
  small-talk curriculum every turn. Coherence here is *learned*: the judge's
  multi-turn-coherence criterion + a `repeat` penalty feature.
- **Reply granularity is per-state** (your call): a state can emit
  `single` (one phrase), `sequence(N)` (N sampled phrases joined, FSM caps N),
  or `template` (slot-filled: "I sell {item}, want {item} for {price}?").

### 3.4 SELECTOR — the policy (the heart)
```
v = situation_vector(features, fsm_state, memory)     # small float vector
score(p) = bias_p + Σ_k v[k] * w[p][k]   (+ Σ meta deltas that apply)
P(p) = softmax(score(p) / temperature)
sample → emit (single) / sample-without-replacement (sequence) / slot-fill (template)
```
- Features v1: `greet`, `question`, `neg`, `topic_roleplay`, `state:<s>` (one-hot),
  `repeat` (recently-used penalty), `turn`, `length`, memory words.
- Slots: v1 deterministic substitution from a per-curriculum slot table;
  free-text slots = later, via iqabod/gemma token fallback (§7).
- This is a **contextual bandit** — the exact class of problem RL games handle.

### 3.5 JUDGE — gemma, describe→score + spot-check (hybrid, your call)
- **Primary (bulk)**: prompt gemma on the Mac (270m): *"Describe in one
  sentence what's good and bad about this reply, given the prompt and prior
  conversation."* Open-ended = the shape that's MEASURED reliable.
- **Deterministic scorer** (on this box, over gemma's description): per-criterion
  lexicon — `relevance`, `naturalness`, `in-character/situation fit`,
  `multi-turn coherence` (the 4 you picked). Each criterion yields a sub-score;
  total = weighted sum, mapped to reward in `[-1, +1]`. Empty/vague descriptions
  score near zero (weak signal = no reward).
- **Spot-check (rare)**: every Nth turn, also ask gemma3:1b for a direct 1-5,
  log both, and periodically re-calibrate the lexicon weights against the
  spot-checks (the PITFALL-69 lesson: the cheap signal must be AUDITED against
  a trusted one, or it silently rots).

### 3.6 REWARD UPDATER — the RL engine, writing plain text
```
for each chosen phrase p:
    w[p][k] += lr * reward * v[k]      # per-criterion rewards update their own features
    respect locks (floor/ceil/hard)
backup weights.txt -> weights.bak    # git-diff-able, revert-able
append rating_log.txt row: (turn, prompt, phrase(s), features, reward, per-criterion breakdown, gemma description)
```
- Attribution = response phrases only (ROADMAP §5.4's decision — don't reward
  prompt tokens).
- Reward is **decomposed per criterion** so a failing dimension fixes its own
  weights: low-coherence sub-reward pulls down `repeat`/`state` weights, etc.
- `lr` starts tiny (1e-3-ish) so edits stay small and human-readable.

### 3.7 MEMORY
- Rolling window of last N turns (user msg + chosen phrase) → feeds features
  (`repeat`, `topic_prev`), feeds the judge's coherence prompt, and keeps
  small-talk from looping on the same phrase.

## 4️⃣ THE LOOP (FSM op shape, mirroring ROADMAP §11.2 with the fixed judge)
```
state ROUTE:    features = extract(msg); intent = router(features)
                (load curriculum + FSM scenario if game dialogue) → SELECT
state SELECT:   v = situation_vector(...); chosen = sample(score_phrases(...))
                slot-fill if template state; emit → JUDGE
state JUDGE:    desc = gemma_describe(prompt, chosen, memory)   # open-ended
                reward = deterministic_score(desc, criteria)    # -1..+1
                if counter % N == 0: direct = gemma3:1b_rate(...); log both → REWARD
state REWARD:   update_weights(weights.txt, chosen, v, reward, lr, locks)
                append rating_log; → ROUTE (wait for next turn)
```
Unattended batch runs = a shell loop (like `iqa-fork/run.sh`) pulling prompts
from a probe bank; interactive = per real turn.

## 6️⃣ REWARD CRITERIA → SCORING LEXICON (v1, hand-tunable)

The deterministic scorer reads gemma's description with a lexicon per criterion:
| Criterion | Positive hits | Negative hits |
|---|---|---|
| relevance | on-topic, addresses, answers, relevant, about | off-topic, unrelated, ignores, dodges |
| naturalness | natural, human, flows, fluent, clear | awkward, robotic, word-salad, gibberish, repetitive |
| in-character/situation | in-character, fitting, appropriate, persona, tone | out of character, wrong tone, inappropriate |
| multi-turn coherence | continues, consistent, follows, context, remembers | contradicts, repeats, ignores context |

Plus a specificity proxy (empty or one-word descriptions = weak signal). The
lexicon lives in a plain text file — a human tunes it exactly like the weights.

## 7️⃣ RELATIONSHIP TO IQABELLA AND TOMO (division of labor)
- **IQABELLA/IQABOD** stays the token-level generator. It supplies the *raw
  material*: its iqa-fork teacher lines (llama3-authored, already flowing into
  the corpus) become SCM phrase banks — i.e. **distillation = content, SCM =
  choice** (S3). iqabod also becomes the optional free-text slot filler and the
  last-resort fallback when no phrase fits.
- **Corpus sourcing (S3)**: v1 phrase banks are built by (a) harvesting the
  good teacher/student lines already in `iqa-fork/log.pdl`, and (b) batch
  authoring with gemma/llama via a `corpus_author`-style persona (ROADMAP
  §11.1's exact pipeline, constrained to small, simple, in-vocab phrases). A
  hand-written core stays the seed (the `corpuses/small-talk/` example here).
- **T@Q** stays the hand-tunable steering layer / future MoE router. SCM's
  `weights.txt` is the same *readable-text-weights* philosophy, so a future
  adapter can read SCM weight files and vice-versa. SCM is standalone first;
  neither model is required to run it (compute: this box does selection math,
  Mac does judging, Linux does optional iqabod training).
- **Wiring into 045 chat**: later, as a new `provider_kind` (like `iqabod`)
  once the standalone CLI loop is proven — don't build the chat integration
  until the loop works (harness-before-hype).

## 9️⃣ EVAL & HARNESS-BEFORE-HYPE
1. **Probe bank** (extend iqa-fork's single "How are you?" into a file):
   greetings, questions, topic triggers, roleplay triggers. Fixed, logged,
   compared over time.
2. **Judge calibration set**: ~20 hand-labeled `(prompt, reply, criteria)`
   triples; run describe→score vs. labels; tune the lexicon until agreement
   (the §3.5 audit is not optional — this is the whole PITFALL-69 bet).
3. **KPI report** (`report.sh`): avg reward, per-criterion breakdown, repetition
   rate, curriculum-switch accuracy, and the raw "latest reply" samples.
4. **Baseline gate**: selection must beat random-uniform sampling on the probe
   bank before any RL tuning is trusted (mirrors T@Q's "beats uniform baseline"
   bar).

- **PITFALL caught during build**: `out[strlen(out)] = *p++` in the slot filler silently corrupts output — after the first write the "NUL terminator" position isn't actually NUL, so `strlen` scans uninitialized stack and writes land at garbage offsets.
