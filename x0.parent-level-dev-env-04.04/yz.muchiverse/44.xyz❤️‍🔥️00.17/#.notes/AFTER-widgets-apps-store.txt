================================================================================
1. The idea (good)
================================================================================

A **project + widgets** can run **all together** and feel like an entirely
different **@app**:

  - Open mutaclysm (sys/project) + file-menu + tile-picker + map-picker
  - Optional: toolbar for the *app shell* (launch/focus widgets, not game UI)
  - Same processes/cmd-bus under the hood; the "app" is a **launch recipe**
    + chrome, not a rewrite of mutaclysm

Get it: widgets compose surfaces; apps are **saved compositions** of
(project + widget set + layout prefs).

================================================================================
2. Hard rule — when to make an @app
================================================================================

  DO NOT create @.apps/ entries until:
    1. You have actually run the project with those widgets, and
    2. You literally want a quicker way to open that combo.

Then:
  - Register the recipe in **@app-store** (catalog of available apps)
  - User can **install** it → profile remembers install
  - This is **prod-pretend testing** (local profile flags, not real billing yet)

================================================================================
