## What works now
- iMovie-shaped UI: File menu, transport, preview + inspector, multi-track timeline (V1/V2/A1/A2)
- Demo MP4s (`media/demo_*.mp4`) auto-placed on timeline
- Playhead + ffmpeg single-frame preview decode
- Select clip, split (C), ripple delete (R), I/O trim, nudge [ ]
- Save/load `timeline.clips`; Export V1 via ffmpeg concat → `export.mp4`
- Writes `canvas.raw` for future house canvas-widgit
- Window resize keeps UI top-left (same fix as DAW)
- **OS drag-drop** of video/audio/image/webm (X11 XDND) onto timeline
- **Clip drag** on timeline to move
- **House-path-safe** URI resolve: `../shared/media_drop_path.c` (emoji/ZWJ/`file://` decode, PATH_MAX buffers, debug log)
- Fallback: File → Paste files (clipboard / xclip)
- **Audio playback**: ffmpeg `-vn` PCM s16le stereo 44.1k pipe → PulseAudio (`-lpulse -lpulse-simple`); play/pause via `set_playing()`; status “Playing (video + audio)”. Demo sines are audible on Space.
- **CPU-safe play**: **no ffmpeg video during play** (hold last frame + audio). Decode only scrub/pause/first load, ≤~2/sec, 320×180, `nice -n 15`. UI ≤20fps play / ≤8 idle. Main loop always sleeps.

## Architecture
Single file `ops/ve_main.c` + `button.sh` (mirrors DAW iteration style).
Split when features grow: state / decode / ui.

## Pitfalls
- Don’t decode every timer tick at 30fps without cache (we throttle + 40ms cache)
- Don’t write `rgb_frame.raw` for preview (use canvas.raw) — design §3 P1
- ffmpeg must be on PATH for real frames / export / audio decode  
- Preview was video-only until Pulse path; don’t set `g_playing` without `set_playing()` or audio never starts  
- Don’t busy-loop `glutMainLoopEvent` without sleep — pegs one core  
- **Never** `system(ffmpeg)` while playing for video — one frame seek/spawn ~melts CPU; hold texture + audio pipe only
