## 0. One-line status

**Runnable Phase-1 DAW shell** (freeglut + PulseAudio soft-synth) that *looks* roughly like a Logic/GB-style layout: File menu, left channel strip, multi-track arrangement + regions, piano roll underneath, transport, basic inserts.  
**Not** GarageBand: no real audio clips, no Apple-quality UX, no library/loops, no real plugins/VST, no CHTPM house shell yet.

---

## 1. How to run (now)

```bash
cd 103.media-studio/103.daw
sh button.sh compile   # optional
sh button.sh r         # launch window
sh button.sh kill      # stop
```

- Binary: `ops/+x/daw_main.+x` (single C file: `ops/daw_main.c`)
- Log: `/tmp/muchi-daw.log`
- State: `pieces/apps/player_app/daw_state.txt`, `sequence.txt`
- Canvas export (for later house widget): `canvas.raw` + `canvas.receipt.txt`
- Quit: **Esc** (not `q` — house rule)

## 2. What is possible NOW (honest inventory)

### UI / layout (pass 2–3)
| Area | What works |
|---|---|
| **File menu** | New / Open-Load / Save / Save As / Quit; Ctrl+N/O/S |
| **Transport** | Return-to-zero, stop, play, rec, cycle; LCD bars.beats.ticks; BPM |
| **Left CHANNEL strip** | Active track: M/S/R, volume fader (click), pan, EQ on+low/high, Reverb, Distortion |
| **Tracks area** | Horizontal lanes, color chip, track header M/S/R, mini fader, **+ Track** (`=` key) |
| **Regions** | One MIDI region block per track spanning note extents; mini note sparks |
| **Piano roll** | **Below** arrangement (not the main view); notes for selected track; click to place when armed/rec |
| **Playhead** | Red line over arrangement + piano roll; auto-scroll while playing |
| **Resize** | `reshape` updates live window size so UI stays top-left (fixed mid-session) |
| **Musical typing** | a–l whites, wetyu blacks; z/x octave |
| **Record** | R arms; typed notes land on sequence at playhead |
| **Save/load** | Project name + tracks + notes to plain text files |
| **Audio** | PulseAudio mono soft-synth; EQ/reverb/dist **actually tint the synth** (not VST) |

### What agents must not claim
- Real GarageBand / Logic / Pro Tools feature parity  
- Real audio recording / WAV import-export  
- Real MIDI I/O devices (USB controllers) — keyboard mapping only  
- Real plugin hosts (AU/VST/LV2)  
- Full CHTPM session (`prisc+x` / `chtpm_parser_pal` / `gl_mirror` canvas-widgit path)  
- Multi-window screensets, automation lanes, tempo map, time signature changes beyond fixed 4/4 display  

### Known gaps / rough edges
- CPU can sit high (soft-synth scans notes every sample under lock)  
- No mouse-drag on region edges / note length  
- No dual-click “open editor” vs single-click select (Logic-style)  
- Bottom mixer (**B**) overlaps conceptually with left strip (acceptable for MVP)  
- File “Open” loads fixed house paths only (no file picker dialog)  
- Freeglut is the GL host (Phase-1 exception to pure gl_mirror law — see §5)

## 3. Architecture of *this* binary (so you don’t fight it)

```
button.sh
  └── ops/daw_main.+x
        ├── freeglut UI (draw_* at ≤30fps timer)
        ├── pthread + PulseAudio simple → soft-synth
        ├── in-memory Track[] + Note[]
        └── writes sequence.txt / daw_state.txt / canvas.raw
```

**Single translation unit** by design for speed of iteration. When it grows, split:
- `daw_state.c` — tracks/notes I/O  
- `daw_audio.c` — synth + plugins  
- `daw_ui.c` — layout/draw/mouse  
- keep `button.sh` as the only user entry  

**Layout constants** (top of `daw_main.c`): `MENU_H`, `STRIP_W`, `HDR_W`, `LANE_X`, `ARR_TOP`, live `g_win_w`/`g_win_h`.

**Critical layout lessons already learned (do not regress):**
1. Piano roll is an **editor under** the tracks area, not the whole window (GB/Logic).  
2. Transport must start at **y = MENU_H**, never y=0, or File menu “overlaps” transport.  
3. **reshape must set viewport + ortho to real window size** or resize leaves UI floating mid-window.  
4. File **dropdown** redrawn last when open so it paints above tracks.

### P0 — Closer to GB *feel* (still one binary OK)
| Item | Why GB-like |
|---|---|

## 5. How to make it *better* and *closer to GarageBand*

### 5.1 Study the real product (don’t invent chrome)
GarageBand (and Logic) hierarchy:

```
Menu bar
Control bar (transport + LCD + display modes)
[ Library | ]  Inspector/Smart Controls optional
Tracks area (headers + horizontal regions)     ← primary workspace
Editors (Piano Roll / Audio Editor) UNDER split
[ Loop browser / Media ]
```

**Do:** match that information hierarchy.  
**Don’t:** put piano roll as the only view (pass-1 mistake).  
**Don’t:** dock a permanent plugin column that steals ⅓ of the arrange area (pass-1 mistake).

### 5.2 Concrete code priorities (if continuing DAW next)

1. **Region interaction**  
   - Click select region; drag move; edges resize length; double-click focuses piano roll.  
2. **Audio track stub**  
   - Track type flag; draw waveform from loaded mono buffer in region.  
3. **Loop library stub**  
   - Folder of `pieces/loops/*.mid.txt` or tiny pattern defs; drag onto arrange.  
4. **CPU**  
   - Pre-schedule active notes into voice slots each audio block, not O(notes) per sample under global lock.  
5. **Visual polish**  
   - Track icons (emoji/glyph), better region labels, darker GB-like greys, larger hit targets.  
6. **Then** migrate draw path to `canvas.raw` + house canvas widget so media suite shares one GL policy.

### 5.3 Hybrid rule (from advisory — keep it)
- Phase-1 freeglut viewer is OK as **MVP** for “see how it looks.”  
- Do **not** grow a permanent second GL framework.  
- Long-term: host ops write buffers; **one** widget blits (house-design-docs §0).

### 5.4 Testing discipline
- Manual: `HOW2_DAW.md` checklist after every UI pass.  
- Later headless: write known notes → save → reload → assert note count/pitches from file; audio optional.  
- Never claim “GB clone done” without user eyeball on arrange + library + one audio loop.
