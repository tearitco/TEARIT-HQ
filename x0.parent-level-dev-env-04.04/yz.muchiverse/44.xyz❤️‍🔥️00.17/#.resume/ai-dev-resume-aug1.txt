4. NEW: opencode as an API arm (proven live today)
=================================================================
opencode (this workspace's CLI agent) can be called over HTTP by the 045
framework — a new escalation rung above llama3, WITH full tool use.

HOW TO START THE SERVER (from the project dir you want it rooted in):
  setsid opencode serve --port 4123 --hostname 127.0.0.1 \
        < /dev/null > /tmp/opencode/serve.log 2>&1 &

VERIFY: curl -s http://127.0.0.1:4123/global/health  -> {"healthy":true}

CALL IT (op built today, 045 house style):
  cd 045.muchi-pal-agent🤖️+1
  ./ops/+x/opencode_ask.+x "your question"            # defaults to :4123
  ./ops/+x/opencode_ask.+x "your question" "http://127.0.0.1:4123"

WHAT THE OP DOES: POST /session -> {id} -> POST /session/<id>/message with
the question -> prints the text parts of the reply. Same curl shape as
connect_op (600s max-time, -sS). Exit 0 = got a reply.

KEY API FACTS (server spec at http://<host>:<port>/doc):
  - POST /session                  create a thread (returns {id,...})
  - POST /session/<id>/message     send prompt, WAITS for reply
    body: {"parts":[{"type":"text","text":"..."}]}
  - GET  /session/<id>/message     list messages
  - GET  /session                  list sessions (shares the TUI's DB)
  - The server shares the local session database with the TUI: don't create
    throwaway sessions without cleaning up (DELETE /session/<id>).
  - auth: set OPENCODE_SERVER_PASSWORD for basic auth.

LIVE-TESTED OUTPUT (2026-08-01):
  $ ./ops/+x/opencode_ask.+x "Reply with exactly: BRIDGE_OK"
  BRIDGE_OK
  $ ./ops/+x/opencode_ask.+x "List the files in ops/ and name the first"
  Files in `ops/`: `+x/` directory and 27 files. First alphabetically: `+x/`

LESSONS / BUGS CAUGHT TODAY (all fixed):
  - The prompt must be JSON-escaped and QUOTED inside the body
    ("text":"...") — an unquoted %s produced invalid JSON and the server
    returned an error part with no text (silent no-reply). Fixed + tested.
  - Server working dir = the dir you launched it in. Launch it inside the
    project you want it to work on (else it searches from the wrong root).
