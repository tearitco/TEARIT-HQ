## 2. The two things this file was specifically asked to carry forward

Full write-ups: PITFALL 63 in `!.xyzos-pitfalls+1.txt`, §38 in
`!.xyzos-standards+1.txt`. Condensed here so you don't have to
context-switch files to get the actionable version.

**The finding**: a harness can satisfy §36.6's "real key injection
through the real running app" bar and STILL give a false positive on
real bugs, if it only ever reaches its assertions via the mechanically
shortest path — an op's own PASTE mode for typed text, and a direct
digit-jump straight to a "confirm" button — instead of the natural
order a real human uses (type character by character, press Enter
expecting it to submit, press Esc expecting it to only stop typing).
This happened THREE times in one week, independently: a real dual-
process key-capture race invisible to any single-deliberate-write
injection (chtpm_parser_pal.c/gl_mirror.c, now fixed); 102.agy-txt's
own SAVE AS path field, whose harness used PASTE for every path-typing
assertion and so never once exercised real per-keystroke typing into
that field (still open); and &.widgits/file-menu's own file_browser
mode, whose ALREADY-GREEN, ALREADY-SHIPPED harness never once pressed
Enter on the typed field or Esc mid-typing, hiding three real bugs
(Enter-does-nothing, Esc-exits-the-wrong-scope, no cursor indicator)
behind full harness confidence.

**The rule (§38)**: every level-2 harness scenario involving typed
input must exercise the natural interaction order — real per-keystroke
injection ending in the field's own domain-natural terminator — at
least ONCE, not only PASTE/digit-jump shortcuts. And when the code
under test is an explicit port of a named reference architecture (which
almost everything in Track A/B is — TPMOS's slop-ed-dev, rpg-maker-
clone, and the event system all have real reference implementations),
that reference's own interaction contract for typed fields — does
Enter submit-in-place or need a separate confirm step, does Esc
deactivate-only or exit the whole screen, is there a focus/cursor
indicator — must be read and written down BEFORE a PASTE-only-proven
harness is trusted as "done." Proving output DATA matches the
reference is a real, necessary check; it is not the same claim as
proving the INTERACTION matches, and nothing else in this house's

**UPDATE, same day (§39, PITFALL 64) — NON-NEGOTIABLE, per direct
instruction**: §38's own fix STILL missed two more real bugs, found by
a human the same day the fix was verified — selecting a real listed
file required an unsignaled second Enter to load (every harness always
typed/pasted a path, never once selected from the real listing), and a
digit keypress activated a main-menu option in the same keystroke
instead of only navigating to it (every harness always sent Enter
right after the digit, never checked state between the two
separately). §39 is now the MANDATORY checklist this produced — real
listed-entry selection, real digit-jump-vs-activate assertions, a real
on-disk file-existence check after any save, and a real jail-escape
attempt where a containment boundary exists. Every harness testing
save/load-shaped user interaction in rpg-xyz/rtp-xyz MUST follow §39,
not just §38 — read both, not just the first one you find.
tooling checks the second claim for you.

## 3. How to actually apply this to rpg-xyz / rtp-xyz

- **Before PHASE A1** (level-2-verifying the existing map save/load):
  don't just add real key injection and call it done — make sure at
  least one pass types a real path/filename character-by-character and
  hits the field's own real terminator key, not a PASTE call straight
  to a confirm button. If the existing UI has no such terminator
  wired (matching file-menu's own Enter-does-nothing bug), that IS a
  PITFALL-63-shaped bug worth finding now, cheaply, before B2/B3 build
  on top of the same underlying save/load ops.
- **Before PHASE B1 writes rtp_manager.c**: read slop-ed-dev's own
  source for its typed-input fields specifically (map name entry,
  event text entry, whatever it has) — does it use something
  cli_io-shaped, or its own thing — and write down the answer, the
  same way this file's §1.4 already did for the smaller text-editor
  reference. Do not assume it matches agy-text-editor's own `<cli_io>`
  convention just because both are TPMOS projects — verify per-project.
- **Before PHASE A2's event system is considered "ported"**: rpg-maker-
  clone's own real event editor almost certainly has typed fields
  (message text, switch names, whatever CMD_SHOW_TEXT's own UI needs)
  — same rule: real per-keystroke + real terminator, at least once,
  before trusting a PASTE-driven harness.
- **When building either full-loop harness** (`%.harnesses/
  rpg-xyz-full-loop/`, `%.harnesses/rtp-xyz-full-loop/`, per
  todo-j30.txt §5): budget the natural-interaction-order pass into the
  harness design from the START, the same way todo-j30.txt already
  mandates level-2-from-the-start for real key injection generally —
  this is the same mandate, one level more specific, not a separate
  ask.
- If you find a PITFALL-63-shaped bug (harness green, real interaction
  broken) in rpg-xyz or rtp-xyz's own code, record it the same way —
  a PITFALL entry citing exact file/line, plus (if it's substantial
  enough to need its own worked-example doc) a `todo-how2-*.txt` in
  the relevant project dir, matching the two examples cited in §1
  item 5 above.
