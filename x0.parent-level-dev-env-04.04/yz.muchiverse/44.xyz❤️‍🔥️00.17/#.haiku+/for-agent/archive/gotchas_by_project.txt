Shared Ops & VM

PRISC+X.C REGISTER-SENTINEL BUG:
  - Several opcodes had bug: unset register fields defaulted to 0 (valid register) instead of -1 (sentinel)
  - Affected: OP_READ_HISTORY, OP_EXEC (both fixed this session)
  - If adding new opcodes/forms: check this exact class of bug before trusting
  - How to spot it: "if an unset field defaults to something indistinguishable from a valid value"

RENDERING FLICKER (CHTPM PROJECTS - COMMON PITFALL)
  Problem: Constant screen redraw/flicker even at idle (no keypresses)
  Root cause: Calling compose_frame on EVERY main_loop tick unconditionally
  Solution (verified 2026-07-20 on muchi-pal-agent):
    1. Use a marker file (pieces/display/chat_screen_changed.txt)
    2. compose_frame appends a dot (fputc('.')) to marker on EACH run
    3. Main loop reads marker file size BEFORE rendering
    4. Only render when: marker size changed (bne x7, x8) OR user action (Enter)
    5. On idle (no key + marker unchanged): skip compose_frame, just sleep
  Pattern (mutaclsym-style):
    - Initial render before loop starts
    - In loop: check_response, read_pos marker, bne → render if changed
    - Read key: only render if key==13 (Enter/submit)
    - No_key: sleep without render
  This eliminates all idle redraws while keeping responsive UI.
  Reference: mutaclsym/pal/main_loop_chtpm.pal (doesn't have marker file, but has
  the same "only render after action" pattern - no idle renders).

Testing & Verification
================================================================================
LIVE TESTING PATTERN (This family's standing convention):
  1. KEY INJECTION: write directly to pieces/keyboard/history.txt (matches real keypress data)
  2. FRAME READING: read pieces/display/current_frame.txt (matches what ops actually wrote)
  3. VERIFY DATA/LOGIC: confirmed (file injection proves data layer is correct)
  4. LIMITATION: doesn't verify real terminal rendering (frame history/scrollback)
  5. NEXT STEP: if frame history/scrollback matters, RUN REAL TERMINAL and observe with eyes

DEBUG FRAME HISTORY:
  - Convention: projects write debug/frame_history.txt (every frame appended, deleted at session start)
  - This answers "frame history/scrollback" question far better than single current_frame.txt read
  - IF a project has this, USE it for testing (grep "frame_history" first, don't assume)
  - IF a project doesn't have it, add it (compose_frame fopen(...,"a") pattern, same as context_log.txt)

Session Isolation & Process Management
================================================================================
BUTTON.SH CONVENTION:
  - Always launch via button.sh `run` or replicate exactly (pal-scripts/launch_irc_agent.sh is worked example)
  - Creates pieces/sessions/<id>/ (ephemeral, deleted on exit)
  - Symlinks shared code, real private ephemeral state

KILL PATTERN (CRITICAL):
  - Every session's processes have IDENTICAL argv text (system/prisc+x pal/main_loop.pal)
  - Bare pkill -f will kill WRONG session
  - Always match /proc/$pid/cwd against target session dir
  - After ANY directory move: sweep /proc/$pid/cwd TWICE (once often isn't enough)

PRISC_PROJECT_ROOT:
  - Env var read ONCE at process startup into static buffer
  - Moving directory updates kernel cwd, but NOT this cached string
  - Leftover process keeps writing to OLD path indefinitely after move
  - After moves: kill orphaned processes by cwd match

The ONE Pattern (Applies Everywhere)
================================================================================
REGISTRY + SWITCH + SELF-CONTAINED OPS

When adding ANY swappable behavior, use this pattern:
  1. REGISTRY file (plain text, pipe-delimited rows: id|kind|param|param)
  2. SWITCH op (look up id in registry, rewrite state.txt fields, done)
  3. SELF-CONTAINED OPS (each does one thing, owns constants/root-resolution)

Examples already in code:
  - Provider: model_list.txt + switch_model.c + send_message.c
  - Routing: trigger_list.txt + script provider parser + execute_tool.c
  - NPC behavior: npc_bank.txt (future) + switch command + per-NPC script/fsm/rl
  - Terrain: terrain_registry.txt (future) + selector op + generator ops
  - Scale: SCALE_BANK.txt (future) + config file + actual modules

Don't invent new patterns. This is the pattern.
