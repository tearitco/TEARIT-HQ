## Current State (All 4 Projects)

All 4 projects share the **same confused architecture**:

| Feature | Current State | What Standard TPMOS Has |
|---------|---------------|------------------------|
| game_manager.c | **MISSING** — game logic scattered across PAL scripts + individual ops | C daemon with polling thread, poll_relay(), NPC auto-play |
| orchestrator.c | **MISSING** — button.sh does raw `&` background launches | fork/exec orchestrator with 3-layer kill, PAL_LAYOUT env var |
| button.sh --pal | **MISSING** — PAL is always-on, no C mode option | `--pal` flag exports PAL_LAYOUT env var |
| renderer.c | **BROKEN** — `else if` causes double-render flicker (Pitfall #17) | Single-pass dual-trigger consumption, one render per cycle |
| chtpm_parser | Only `chtpm_parser_pal.c` exists (forked) | Both `chtpm_parser.c` (C mode) and `chtpm_parser_pal.c` (PAL mode) |
| Kill/cleanup | Shell `pkill -f` in button.sh trap | 3-layer cascading: process group → PID file → kill_all.sh |

### What "PAL-only" means in these projects

Every project uses `<module>system/prisc+x pal/main_loop_chtpm.pal</module>` in its CHTPM layouts. The PAL script is the game loop — it reads `interact_relay.txt`, dispatches to ops, and composes frames. There is NO C-side game_manager that polls the relay. The CHTPM parser + PAL script together ARE the game manager.

This is architecturally sound for PAL mode, but there's no C fallback. The user wants `./button.sh run` (C mode) and `./button.sh run --pal` (PAL mode) as options.

## Risk Assessment

| Risk | Severity | Mitigation |
|------|----------|------------|
| PAL scripts use `read_history` with literal path (3-arg form) | LOW | Already correct in all 4 projects |
| No C game_manager to fall back to | MEDIUM | C mode is "future" — for now, both modes use PAL |
| Persistent daemons (inbox_watcher, palnet_peer, path_nav_manager) | HIGH | game_dispatch must NOT kill daemons; only the orchestrator's 3-layer kill should touch them |
| 36 ops in wsr-pal — game_dispatch keycode mapping is complex | MEDIUM | Model after wsr_menu_input.c's existing dispatch logic |
| RGB rendering in mutaclsym — compose_rgb_frame must be called too | LOW | Include in game_dispatch compose step |
| chtpm_parser_pal is a forked file, different per project | LOW | Each project keeps its own fork; orchestrator compiles in-place |
