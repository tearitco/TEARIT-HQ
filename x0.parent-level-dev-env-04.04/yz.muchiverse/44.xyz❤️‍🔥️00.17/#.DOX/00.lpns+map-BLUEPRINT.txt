LEDGER-PLAYER-NPC-SIMPLE + MAP (LPNS+MAP)
Blueprint for Spatial Game Demo with Ledger Architecture
Map-Based Movement + RGB Window Rendering

================================================================================
OVERVIEW
================================================================================

LPNS+MAP extends the ledger-driven word game with:
  ✓ Spatial gameplay: 8x8 game map
  ✓ Player positions tracked in ledger
  ✓ Movement mechanics (x/y input via CLI-IO)
  ✓ RGB rendering: live view of map in secondary window
  ✓ Same ledger architecture as LPNS (actions → append-only log)

Design philosophy:
  - Map state derived from ledger (replay from turn 0 to get any past map)
  - Players and NPCs occupy grid positions
  - Each turn: player chooses action (word, move, or end turn)
  - All actions logged to master ledger
  - Map rendered from current ledger state

Inspired by: mutaclysm🧟️ (map rendering, position tracking)
But: keep our ledger-first architecture (don't make map the source of truth)

PART 1: DATA STRUCTURES
================================================================================

MAP STATE (derived from ledger, not authoritative):

  8x8 grid: (x: 0-7, y: 0-7)

  Cell contents:
    '.' = empty
    '1'-'8' = human player (player number)
    'A'-'H' = NPC (NPC letter A-H for NPCs 1-8)
    '#' = wall (optional, for future)

  Example map after setup:
    01234567
  0 1.......
  1 .......2
  2 ........
  3 .A......
  4 ........
  5 .......B
  6 ........
  7 3......4

PLAYER STATE (tracked per game):

  actors/<player_name>/state.txt:
    name=alice
    player_type=human
    position_x=0
    position_y=0
    score=0
    inventory=word1,word2  (optional)
    current_action=idle    (last action taken)

NPC STATE (same structure):

  actors/<npc_name>/state.txt:
    name=NPC_Alpha
    player_type=npc
    position_x=1
    position_y=3
    score=0
    strategy_id=0          (which NPC strategy to use)
    current_action=idle

EXTENDED MASTER LEDGER:

  Format: timestamp|epoch|player|turn|action_type|action_data

  Previous format still supported:
    2026-07-23T10:00:00|1|alice|0|word:hello|word_spoken

  New movement actions:
    2026-07-23T10:01:00|1|alice|1|move:x:1,y:0|movement
    2026-07-23T10:02:00|1|bob|2|move:x:7,y:1|movement
    2026-07-23T10:03:00|1|npc_alpha|3|move:x:2,y:3|npc_auto
    2026-07-23T10:04:00|1|alice|4|end_turn|turn_end

PART 2: GAME LOOP WITH MOVEMENT
================================================================================

TURN SEQUENCE (extended from LPNS):

  1. Ring determines current player (same as LPNS)
  2. If human player:
     - Display map (ASCII in CLI)
     - Display input prompt: "Enter action (word/move/end): "
     - CLI-IO buttons for: word input, move, end turn
     - Player chooses:
       a) TYPE WORD: "hello" → append to ledger
       b) MOVE: prompt "X (0-7): " and "Y (0-7): " → validate → append move to ledger
       c) END TURN: → append end_turn to ledger
  3. If NPC:
     - Run NPC strategy (existing ai_module)
     - NPC chooses: word, move, or end turn
     - Append NPC action to ledger
  4. Render updated map (all actors from current ledger state)
  5. Increment turn counter
  6. Loop

MOVEMENT VALIDATION:

  On MOVE action:
    - Parse target position (x, y)
    - Check bounds: 0 <= x <= 7, 0 <= y <= 7
    - Check occupancy: target cell must be empty or word-bearable
    - If valid: append move to ledger
    - If invalid: reject, re-prompt for action

  Position update:
    - After move appended to ledger, update actors/<player>/state.txt
    - position_x=new_x
    - position_y=new_y

MAP RECONSTRUCTION:

  void reconstruct_map(char ledger_path[MAX_PATH], GameMap *map) {
    // Start with all players at origin (0, 0)
    for each actor in actors/:
      map.players[actor].x = 0
      map.players[actor].y = 0

    // Replay all ledger entries
    FILE *ledger = fopen(ledger_path, "r")
    while (read_line(ledger)):
      if action_type == "move":
        parse x, y from action_data
        update map.players[actor].x = x
        update map.players[actor].y = y

    return map
  }

PART 4: RGB WINDOW (SECONDARY DISPLAY)
================================================================================

REFERENCE: mutaclysm's chtpm_rgb_render (chtpm_rgb_render.c or similar)

Purpose: render 8x8 map as colored pixel grid in separate window

APPROACH (from mutaclysm pattern):

  1. Use same chtpm_rgb_render engine (shared-ops/)
  2. Read layout from pieces/chtpm/layouts/map_render_rgb.chtpm
  3. Render map cells as 32x32 pixel squares (configurable)
  4. Color coding:
     - Empty (.) = light gray background
     - Player 1-8 = bright colors (e.g., red, blue, green, yellow, etc.)
     - NPC A-H = muted colors (brown, purple, teal, etc.)
     - Optional: walls (#) = dark gray
  5. Update in real-time: every game tick, re-render from current ledger state
  6. Optional: show player names as text overlay on their cell

RGB LAYOUT FILE: pieces/chtpm/layouts/map_render_rgb.chtpm

  Defines:
    - Map cell size (32x32 pixels)
    - Colors per player/NPC (palette)
    - Font for overlays
    - Window title "LPNS+MAP Game View"

RENDERING FLOW:

  1. button.sh launches both:
     - Terminal CLI (prisc+x with main_loop.pal)
     - RGB window (chtpm_rgb_render reading map state)
  2. Both read from same game state (master ledger + actors/ dirs)
  3. On each tick:
     - CLI shows map in ASCII (8x8 grid of characters)
     - RGB window shows same map in pixels (256x256 window)
  4. Player chooses action in CLI → appends to ledger
  5. Both re-render from updated ledger state

PSEUDO-CODE (chtpm_rgb_render rendering loop):

  while game_running:
    // Reconstruct map from ledger
    map = reconstruct_map(master_ledger.txt)

    // Clear canvas (light gray background)
    fill_rect(0, 0, 256, 256, color_bg_gray)

    // Draw each cell
    for y in 0..7:
      for x in 0..7:
        cell = map[y][x]
        if cell == '.':
          draw_empty_cell(x, y)
        else if cell in '1'..'8':
          player_num = atoi(cell)
          draw_player_cell(x, y, player_num, get_player_color(player_num))
        else if cell in 'A'..'H':
          npc_idx = cell - 'A'
          draw_npc_cell(x, y, npc_idx, get_npc_color(npc_idx))

    // Optional: draw grid lines
    for i in 0..8:
      draw_line_h(i * 32, 0, 256, color_grid)
      draw_line_v(0, i * 32, 256, color_grid)

    // Optional: show player names as overlay
    for each actor in actors/:
      x, y = map.players[actor].position
      draw_text(x*32 + 4, y*32 + 4, actor.name, font_small, color_text)

    // Blit to screen
    display_update()

    sleep(50ms)  // ~20fps

PART 8: ARCHITECTURE ALIGNMENT
================================================================================

LEDGER-FIRST DESIGN:

  ✓ Master ledger is source of truth (not map data structure)
  ✓ All position changes → ledger entries
  ✓ Map state derived by replaying ledger
  ✓ Crash recovery: restart, replay ledger, get same map
  ✓ Time-travel: any past turn's map can be reconstructed
  ✓ P2P ready: each node replays ledger → convergent map state

COMPARISON TO MUTACLYSM:

  Mutaclysm (source of truth):
    - Entity positions in RAM data structures
    - Map is "the world"
    - Ledger is audit trail (optional)

  LPNS+MAP (source of truth):
    - Entity positions DERIVED from ledger
    - Ledger is "the world"
    - Map is a VIEW of ledger state

BENEFIT:
  - Same architecture as LPNS (words in ledger)
  - Scales to hundreds of actors (no RAM bloat)
  - Deterministic replay (no hidden state bugs)
  - P2P-friendly (no conflict resolution needed)
