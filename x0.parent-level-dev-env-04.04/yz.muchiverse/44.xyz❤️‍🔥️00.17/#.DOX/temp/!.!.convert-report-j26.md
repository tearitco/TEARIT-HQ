## Standing rules established this session (apply to every project, see xyzos-standards.txt sec.33/34 for full writeups)

1. **`101.mutaclsym` is the canonical reference** for the renderer flicker-fix pattern (single-marker `renderer_pulse.txt`, not the dual-marker `frame_changed.txt` + `renderer_pulse.txt` variant some projects had).
2. **Never use 'q' as a quit key.** Ctrl+C (ETX, byte 3) is the only quit trigger, handled directly in `keyboard_input.c`. Every project had at least one leftover literal `'q'`/`'Q'` check to remove (usually `chtpm_parser_pal.c`'s own `process_key()`, sometimes a pal script's `beq x2,x9,quit` too), plus in-frame help text ("[q] Quit") to relabel.
3. **No forced periodic re-render.** A background tick can update state on its own timer, but must never unconditionally trigger a compose/render afterward - rendering is marker-driven only.
4. **Skip re-printing an unchanged frame**, even if the pulse marker grew - added a `last_printed` content-equality guard to every `renderer.c`.
5. **Pre-sync before first compose**: a persistent pal module that gets killed+relaunched on every href transition must run its own idle-sync once *before* its first `compose_frame`, not after - otherwise the first render reads stale/pre-generation content.
