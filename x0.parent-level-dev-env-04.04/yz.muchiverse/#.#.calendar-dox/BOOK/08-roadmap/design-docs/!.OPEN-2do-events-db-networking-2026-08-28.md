`ends_with_switches_path()`. Scans the freshly-compiled `event.pal`
(compile_page() ALWAYS runs immediately before publish_page_state() on
every append:/edit:) for the exact instruction shape `control_switch`
compiles to via the registry:

    li x15, 7
    li x12, <V>
    ecall "{STATE_DIR}/switches.txt" "{key}"

and appends one `SCRATCHBLOCK|<key>|<ON|OFF>` row per match to
`page.state.txt` (after the CMD rows). Deliberately matched on the
compiled opcode shape (HARNESS-AUTHORING-GUIDE.md §3a-proof3 principle),
not the IR type row, so a hand-written PAL with the same shape gets the
same visual block. §3a-switchvals word: `<V>` is the integer 1/0 at
compile time (ON/OFF live only at the picker layer) - mapped 1→ON,
0→OFF; any other `<V>` is not matched (honest: a stray literal "ON"
in a hand-written PAL is not claimed as a block). Purely additive -
the renderer's strncmp prefix parser ignores unknown prefixes, so
pre-patch renderers are byte-unaffected.

**Layout (`&.widgits/events-hq/pieces/`)** — `dashboard.css` gained the
real `.scratch-block` class (background + border, colors modeled on
RPG Maker MV's own Show-Text blue). `dashboard.chtpm`: comment-only

stub-label fill loop touches every child, so adding real children now
