# 🤝🎲 Collaborative Entity Games — architecture explainer + delegation map

**Goal:** multiple entities operating on the same game mechanic simultaneously (roguelike,
business sim, farming, etc.) — e.g. your business-sim plan (banks/stores trading, players working
for salary, buying/selling to farmers/miners/scientists). See `project-starters/14.` for that
specific starter.

## 🧠 The real, existing building blocks (attach-this-file-as-context version)

- **Sessions = games.** Each game instance is a session folder.
- **Desks = maps.** A session can have multiple desks; a desk is one playable map/screen.
- **Pals = placed entities.** A pal is an entity instance living on a desk, with its own
  `state.txt` — the SAME piece-containment model as everything else in the house
  (`PIECE → MODULE → OS`).
- **Multiple entities on one desk** is already the base case, not a special mode — the taskbar's
  own tab bar tracks multiple open entities per session today.
- **The real open question for "collaborative" specifically**: how entities on the SAME desk
  read/write SHARED state (a bank's ledger, a market's price list) without a one-writer-rule
  violation. This needs a real answer before building — see file 8 (data storage ledger) for the
  real mechanism to reuse (`master_ledger`-style append-only ledgers, one canonical writer per
  ledger, readers poll).
