🏚️➡️🏡 Is the House in Shape? — honest status report

This is a direct answer to your own recurring question, not a delegation-map file — read it yourself, don't necessarily attach it to a browser prompt.

✅ What's genuinely solid right now (directly verified this session)

  • Taskbar terminal ASCII mirror — new, real, built + live-tested this session (khtpm_strip_render_ascii.+x / khtpm_strip_keyboard_ascii.+x). Matches TPMOS's real renderer.c/keyboard_input.c split *exactly in form* (two processes, capture never prints, render never touches termios) after fixing a real staircase bug caused by combining them.
  • Taskbar input/dispatch architecture — cutover complete (2026-08-19). The feature-flag dual path (KHTPM_NEW_DISPATCH_MODE) is gone — old inline dispatch was deleted outright, not just defaulted-off. Capture-only-writers + one-read-back-dispatcher (matching mutaclysm's real x11_mirror.c/game_dispatch.c shape) is now the only path, live-verified with genuine X11 input (both real user interaction and XTest-injected), and the bottom tab bar was confirmed fully covered before the old path was removed. A same-day frame-unification pass on top of this (strip_frame.cells.pdl) introduced and then fixed a real bug (arrow-key submenu nav getting wiped every tick by a change-signal filename collision) — see tb-bugfix-au19.txt in the outer root and au11-hq/TASKBAR-FRAME-UNIFICATION-HANDOFF.md under 44.xyz.01.00/.
  • au11-hq/ doc index (INDEX.md) is actively maintained and was just updated with real pointers to all this session's work — trustworthy as a routing layer.

🧭 Taskbar vs TPMOS — spirit, form, and the honest gap

  • Spirit: very close now for the ASCII-mirror slice. Same "capture writes, dispatch reads, render displays" philosophy, same marker-pulse discipline, same dual-rate (60Hz active / 10Hz idle) poll standard.
  • Form: necessarily different — TPMOS's real shape is N independent sibling processes under one orchestrator; the taskbar is still mostly ONE process (khtpm_strip_parser.c) with Xlib event-loop dispatch, now with an opt-in alternate path rather than a true multi-binary split. This is an acknowledged, deliberate difference (see taskbar-history-txt-migration- investigation.md's own "Phase 2 design" section) — not a gap to silently close, a real architectural choice still under evaluation.
  • What's NOT yet TPMOS-shaped: bottom-tab-bar activation via relay (renders, doesn't activate yet — bigger shared nav-claims numbering system), cli_io typing support in the ASCII mirror, and the real X11 capture path is STILL the default (new mode is opt-in only).

📚 Documentation organization — your instinct is right, it IS a bit sprawled

Direct count: au11-hq/ alone has 36 files as of this session, ranging from 1.8KB to 172KB, spanning dates from 2026-08-11 through 2026-08-18, on topics from taskbar architecture to chat-hai memory design to event-runtime mechanics to database context. INDEX.md (157 lines) is the one genuinely reliable routing layer — it exists specifically because the raw file list isn't self-explanatory, and it's kept current (this session added real entries for the new work).

Real, honest characterization: not "stale" in the sense of being wrong — the docs found this session were accurate and load-bearing (TASKBAR-MENU-ARCHITECTURE.md, &.widgits/tile-picker/ops/tp_test_send_key.c's own header comment, etc.). It IS excessive in volume relative to any one task's real need — exactly the problem this browser-prompting/ directory exists to solve: instead of making a browser AI wade through 36 files, each delegation- map entry here names the 2-3 that actually matter for one job.

Where to actually look, as a human:
