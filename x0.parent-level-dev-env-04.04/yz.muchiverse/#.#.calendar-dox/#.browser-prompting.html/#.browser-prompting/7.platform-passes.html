🪟🍎 Grok — Windows/Mac Compatibility Catch-Up — delegation map

Goal: bring Windows usability back up to date after heavy Linux-focused refactors drifted it out of sync. Some shims exist but are UNTESTED since the refactors.

🧠 Real, house-standard cross-platform rules to give Grok up front (from TPMOS's own real

standards — these are proven, not aspirational)

  • #ifndef _WIN32 for Linux/macOS blocks, #ifdef _WIN32 for Windows — NEVER refactor established POSIX logic "to clean it up" for Windows compat. Surgical wraps only.
  • Linux: fork()+exec()+waitpid(). Windows: _spawnl() with _P_NOWAIT (shared console) or _P_DETACH (background daemon).
  • Linux orchestrators block on pthread_join(). Windows needs a persistent while(!should_exit) { Sleep(100); } loop instead — detached Windows processes return immediately, unlike Linux's join-based lifecycle.
  • Path separators: / for all internal logic/fopen(), only convert to \\ for native Windows _spawn/system() calls.
  • setpgid has no Windows equivalent — Windows signal handling needs explicit taskkill or tracked-PID cleanup to avoid orphaned processes.
  • Hardcoded Linux font paths will crash Windows — always provide a C:/Windows/Fonts/ fallback or a graceful no-asset exit.

C. Ordering the nav [ ] items — the rules

nav_index ([ ]1. [ ]2. …) is assigned in document order to every <tab>, <item>, and <cli_io> that has a label or an action/onclick. <text> / <text_area> / <title> / <module> get no nav number. So:

  1. Order = the order you write them in the template. Put the control the user reaches for most FIRST. Put destructive / rare ones LAST.
  2. The chrome [X] close is auto-appended after everything. Don't add your own <item id="close"> unless you deliberately want it earlier in the run.
  3. <tab>s come first in a sidebar+panel window (they're the 1st child of <page>). If a tab has target_id=, clicking it *scopes* nav into that region — [^] on the tab, arrows stay inside, Esc pops out. Use target_id when "pick a tab, then navigate its contents" is the flow (record lists, layer lists). Omit it when the tab is just a one-shot action (File → New).
  4. Scroll regions nav-number only the VISIBLE rows — a 500-item list is fine, off-screen rows have nav_index=0 and PageDn/wheel/ the ^/v sbar arrows bring more into range. Never emit 500 bare <item>s outside a <scrolllist>.
  5. Keep ~20 nav items visible per screen. More than that = you need a scroll region or a second page (GOTO:), not a wall.
  6. Group with <row class="toolbar">. Items in one toolbar row still each get a nav number but read as a visual cluster — that's how you make a transport bar or a tool strip.
  7. A [ ]N. badge is ~46px of the element's width. In CSS give a short-labelled button enough width: or the label clips to just the badge.

D. CSS is a tiny subset — plan around it

Supported: background-color, color, border / border-width, font-family, font-size, font-weight, padding, width, height, display:flex + flex-direction + flex-wrap + gap, flex-grow, position:absolute + top/left.

NOT supported (silent no-op → element renders 0px or unstyled): min-width / max-width / width:auto, margin (mostly), % widths on most elements, any color/gradient/shadow/radius/transition, grid, floats. If an element has no explicit width: it is very often laid out at 0 and you'll swear it "didn't render" — pitfall #16's sibling. Set real px.

Set every color as a literal in the rule (there are no CSS variables). Dark theme by default (#121214 bg, #e6e6ea text, #24242a buttons) — match the other @.apps/*.css.
