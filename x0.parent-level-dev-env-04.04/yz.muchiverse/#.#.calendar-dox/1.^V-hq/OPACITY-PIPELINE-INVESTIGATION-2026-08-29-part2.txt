## 3. CRITICAL STRUCTURAL DIFFERENCE: WM HINTS ON override_redirect WINDOW

The entity menu renderer (khtpm_entity_menu_render.c) sets TWO properties that should
NEVER be set on an override_redirect window:

1. _MOTIF_WM_HINTS (lines 10160-10162 for db-hq, similar for events-hq/chat-hai)
   Tells the compositor "apply window decoration/management to this window"
   Value: 0x2, 0x0, 0x0, 0x0, 0x0
   (0x2 in first field = "use the hints in following fields", but rest are 0)

2. WM_DELETE_WINDOW protocol (line 10165, via XSetWMProtocols)
   Also signals "I'm a managed window, handle my close requests"

These are ICCCM/EWMH hints for REAL window-manager-managed windows. Setting them
on an override_redirect window is contradictory - the window is saying "I am NOT
managed by a WM" (override_redirect=True) but then setting properties that say
"please manage me" (_MOTIF_WM_HINTS, WM_DELETE_WINDOW).

Mutter/modern compositors likely interpret this as:
"If the client is setting these hints, treat it as a managed window and apply
window management compositing rules (which may ignore client-side opacity requests
and substitute the WM's own opacity model)."

This would explain the EXACT symptom:
- Property is set correctly (verified via xprop)
- Property value is correct (2860448218 = 0.666)
- Window is override_redirect (verified via xwininfo)
- Yet zero visible transparency (because Mutter switched to WM-managed opacity model)

## 4. ROOT CAUSE CONFIRMED: WM HINTS CONFLICT

The taskbar (khtpm_strip_parser.c) does NOT set either of these properties.
Grep confirmed: zero mentions of _MOTIF_WM_HINTS or XSetWMProtocols in the
taskbar's own source.

The entity menu renderer (khtpm_entity_menu_render.c) DOES set both.
Both are in lines 10159-10165 (db-hq window creation), with identical copies in
events-hq (~line 10243-10250) and chat-hai (~line 10307-10314) branches.

The comment in the code (lines 10166-10178) even ACKNOWLEDGES this issue exists:
"XSetWMHints(InputHint)/XSetWMNormalHints(PPosition) removed... for a window
that's now genuinely override_redirect... The taskbar's own real override_
redirect windows (khtpm_strip_parser.c) never set either hint - this makes the
shape match exactly."

But the comment only removed XSetWMHints/XSetWMNormalHints, NOT the _MOTIF_WM_HINTS
and WM_DELETE_WINDOW that are still being set on lines 10160-10165, making the
comment's own statement factually false - the shapes do NOT match exactly, because
these two properties are still present.

## 5. THE FIX (NOT YET APPLIED)

Remove lines 10160-10165 (and equivalent lines in events-hq and chat-hai branches)
that set _MOTIF_WM_HINTS and WM_DELETE_WINDOW on override_redirect windows.

These properties are meaningless on override_redirect surfaces. The window already
has manual focus handling (dbhq_grab_keyboard_retry()/dbhq_soft_focus()), so the
WM_DELETE_WINDOW protocol (which is for asking the WM to close the window) is not
needed.

Exact code to remove (db-hq branch):
    {
        Atom motif_hints = XInternAtom(dpy, "_MOTIF_WM_HINTS", False);
        long hints[5] = { 2, 0, 0, 0, 0 };
        XChangeProperty(dpy, win, motif_hints, motif_hints, 32, PropModeReplace, (unsigned char *)hints, 5);

        Atom wm_delete = XInternAtom(dpy, "WM_DELETE_WINDOW", False);
        XSetWMProtocols(dpy, win, &wm_delete, 1);
    }

This entire block (10159-10165 in the current file) should be deleted for override_redirect
windows. Similar blocks exist in events-hq and chat-hai branches.

After deletion, the xprop output of entity menu windows will match taskbar windows exactly,
and opacity should render visibly because the compositor will no longer be confused about
whether to apply client-side opacity (override_redirect mode) or WM-managed opacity
(suggested by the ICCCM hints).
