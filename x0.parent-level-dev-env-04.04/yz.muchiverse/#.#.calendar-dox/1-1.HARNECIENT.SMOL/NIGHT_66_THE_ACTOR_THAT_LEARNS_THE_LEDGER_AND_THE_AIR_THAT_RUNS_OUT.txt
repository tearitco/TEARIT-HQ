**THE NARRATOR:** Part two. What did the tutorial work add? Tomo, start with the action space.

**TOMO:** The game has a closed set of verbs. READ in vox op: give, move, mine, place, wait, sleep, eat, craft, walk, face, jump, seat, reset. Each either appends all its rows in one write or refuses and writes nothing. That is a small, enumerated action space, and every refusal has an exit code. Reach, no ground, hunger, no item. The refusals are the guardrails.

**MAXINE:** Why does that matter for learning?

**TOMO:** Because an actor cannot invent a move. It can only call a verb the game already knows. It cannot write a ledger row by hand. A hand-edited ledger is detected and refused. RAN: the verify step is built into every mutating verb.

**RAHWEH:** Second addition. The seat row. Who drives an actor is a row, human or harness. RAN, built into the voxel game. So the slot where an AI actor would sit already exists. A learning actor is a caller with the seat set to harness, using the same verbs a human uses with the keyboard.

**MAXINE:** Third. The tutorial itself. The lesson is data. The checker is an op that reads the ledger from the point where the lesson started and says step three of seven, have two, need five. It stores no progress. RAN, nineteen checks.

**TOMO:** And that is exactly the shape of a reward signal. A deterministic function from ledger rows to progress. It is cheap, it can fail, and it is not a language model's opinion. A curriculum and a reward in one data file.

**RAHWEH:** NOT PROVEN, and say it loudly. Nobody has run an AI actor through lesson one. Only a human and a recording script have. The shape fits. The fit has not been shown.

**MAXINE:** Fourth, and this is the one I did not expect. Today the proof of a place was weak, and the reason was a rule.

**TOMO:** The game wrote a free give row before every place and every swing. A creative hotbar. So the count never went down. A learner rewarded for placing blocks would have learned to place forever, for nothing.

**RAHWEH:** That is reward hacking, at home, in miniature. A reward is only as honest as the rule under it. RAN: the owner ruled creative off by default, a menu toggle, and today's take shows dirt twelve, thirteen after the mine, twelve after the place. Decision one-forty-two.

**MAXINE:** And the lesson inside the lesson. I first called it a double credit bug, and I was wrong. Replaying the ledger row by row showed the design. Before you say a rule is broken, replay it.

**TOMO:** Fifth. The grade is derived, never stored. So any actor, human, scripted or learned, can be graded after the fact by replaying. **THE NARRATOR:** Part three. How the house would learn by itself. Rahwey, begin with the honest limit.

**RAHWEH:** Training here is counting. Reward and punish counts per context and per op, and a weight, reward plus one over reward plus punish plus two. No gradient descent. No graphics card. Neural training on this machine is explicitly out of scope. READ. And hand-tuned weights choose among an enumerated set in a closed domain. They do not write novel code.

**MAXINE:** So what does reinforcement learning on itself mean, here?

**TOMO:** DESIGN, in steps. One. An actor proposes a phase table, a story of verbs with a stated expectation. Two. The harness runs it on a scratch copy of the game, not the live one. Three. The verdict, pass or fail with counts, is the reward. Four. The weight for that phase moves. Five. Next time the planner prefers the phases with the better weight, and sometimes tries a new one to explore.

**RAHWEH:** The pieces that exist, RAN: the runner that plays a phase table in a scratch copy, the bank that updates weights, the search that ranks phases by words times weight, the decision ledger in three games, one choice that reads a weight back, the log and the with-and-without control. The caller does not exist. The planner that reads weights does not exist. The exploration rule does not exist.

**MAXINE:** Say the control again, because it is the part people skip.

**TOMO:** Toolformer's test, house version. Keep a tool call only if the case passes more checks with the call than without it. RAN, one route: committing with the scoped commit tool beat a plain commit in a scratch repo, three checks against one. A control where the two were equal came out useless, so the test can fail.

**RAHWEH:** Nineteen of twenty routes have no such test yet. Most need real work with a pass or fail attached.

**MAXINE:** And the three published techniques, mapped?

**TOMO:** Toolformer is the with-and-without credit. ToolkenGPT, tools as tokens, is the concept bank: each op is a node, the attention score is the bank ranking, fire above a threshold rule row. And synthetic data from a big model becomes: generate scenarios ourselves from seeds, solve them with a planner, keep only traces the harness passed.

**RAHWEH:** Attention, since the owner asked. Today attention is a sparse, inspectable score over a fixed list of routes. It is hand-tunable. The meta page says a learned layer is only worth building when a logged failure needs it, and gives a table of failures and the smallest piece for each. RAN analysis: the router's problem was a threshold problem, and softmax did no better than a plain gap on forty goals. So adding attention first would have been building for its own sake.

**MAXINE:** What did the lab measure about the router?

**TOMO:** RAN, the lab. Ninety percent on the forty goals the author wrote. About fifty-three percent on phrasings written by two other models. The router is bound to wording. In-sample fixes looked big and did not transfer.

**RAHWEH:** And the router's confidence, a softmax over the scores at a low temperature, was close to calibrated on three datasets, a candidate to replace the gap rule. It needs an owner yes. Open.

**THE NARRATOR:** Part four. More characters. What changes when there are many NPCs?

**TOMO:** An NPC is an actor row, a seat, and a policy. The policy has two layers. A state machine for what is already known, a planner for what must be figured out. Neither writes the ledger directly. They call verbs, and the verbs refuse what is not allowed.

**MAXINE:** So ten NPCs are ten seats and ten callers. What does that cost?

**RAHWEH:** CPU, on a weak machine next to the owner's browser. The ticks must be cheap, idle cost near zero, and heavy work niced, gated, one at a time, and offloaded to another machine. Today's own compose run proved it: ffmpeg took the machine over because niceness does not cap threads.

**TOMO:** Per-actor memory is the open piece. The weights today belong to a phase or a route, not to a character. Two NPCs would share one bank. Whether they should is a design choice, with the five questions, not a default.

**MAXINE:** And talking?

**RAHWEH:** The entity chat endpoints exist, READ, on the owner's Mac. The model describes in a fixed shape. It does not decide. An NPC's words never become a ledger row without a verb.

**TOMO:** The party order, who is in the party and in what sequence, is already a ledger row, not a second file. One authority per fact, even for friends.

**THE NARRATOR:** Part six. Advanced mechanics. The owner named two sources: the survival-game ideas of the cdda family, and the oxygen of rpg-space. Maxine, what is the oxygen mechanic, exactly?

**MAXINE:** READ, the data file. Air and heat per room. Constants: oxygen below sixteen percent and a character chokes. Thirty per-mille of maximum health lost per tick while choking. A recycler gives back one percent a tick in a sealed room. A hole in the hull leaks twelve percent of the gap to the outside each tick. A collision at speed punctures a chosen room. Cold below five degrees, heat above forty-five. The outside is no air at minus a hundred and fifty. The constants are re-read every two seconds, no rebuild.

**TOMO:** And the state is one row per room, in a state file: room, oxygen, temperature, breach.

**RAHWEH:** Two honest observations, both READ. One: the logic itself is native C inside the rpg-space program, a function that ticks the air. It predates decision ninety-two, which says every rule is an op. Two: the air lives in a mutable state file, not a ledger. It predates the no-ghost-data rule. So it is a good source of constants and design, and a bad precedent for how to build.

**MAXINE:** It also reaches damage through a shared sink that hunger and cold use. And there is a reactions file, hydrogen and methane and rusting, that no game reads. Paper data.

**TOMO:** Now Asa. Could Asa stand in that level?

**RAHWEH:** Not by walking in. Two different engines. Asa lives in the voxel ledger: terrain columns, a bag, verbs of the vox op. Rpg-space is a pets-style board with rooms, its own life verbs and its own state. They share no ledger and no actor table. To put Asa there you would carry her rig, her colours, her possession and her driver into another engine. Expensive, and it duplicates a driver.

**MAXINE:** So the other direction. Bring the oxygen to Asa's world.

**TOMO:** DESIGN, in pieces. The voxel game already has the right model, in miniature. Hunger rises on every turn row, eating is a row, and at a starving threshold mining and placing refuse. All data in the rules file. Note that hunger per turn is set to zero in rmmc, so it exists and is switched off.

**RAHWEH:** And here is the gap. The voxel game has no health. I searched the op: no health, no damage to an actor. Oxygen needs it. So the first missing piece is a small health fold and a hurt row.

**MAXINE:** And rooms?

**TOMO:** In a voxel world a room is not drawn, it emerges. A sealed volume is air cells with no path to the outside. Mining a wall opens it. Placing a block closes it. That is a derived fold over the ledger, the same way the world itself is derived. Oxygen then comes from geometry, which is better than a flag called breach.

**RAHWEH:** And that is where the two games meet in a way that is actually Minecraft. You dig the wall, the air goes, you choke, you place a block, you recover. Every one of those is a row the existing verbs already write, except hurt.

**MAXINE:** What could Asa do then, and what could she not?

**TOMO:** She could mine, place, craft and eat as before, and she would also choke, freeze or scorch, by the rule rows. She could not fly a ship, because there is no ship in the voxel game. She could not use the rpg-space rooms, hold or bridge, because those are that board's data. Each of those is a separate feature, not a side effect.

**THE NARRATOR:** Topic two: how should the router decide when to fire a route, and how confident is it?

**MAXINE:** Option A, keep the gap rule: fire only when the best score beats the second by a margin, now zero point four five. The case: it is simple, inspectable, one number in a rule row, and it blocked every wrong route on forty test goals in both weight lanes. The price: that number was fitted to four wrong routes, it falls apart at a different scale, and about a fifth of the right routes were pushed to a fallback.

**TOMO:** Option B, replace it with softmax confidence at a low temperature. The case, RAN in the lab: it was close to calibrated on three datasets, two fitted and one never fitted, with an error of about five to eight percent, and answers above zero point eight were right nine times in ten. A calibrated confidence is something a human can read and a threshold can use. The price: it adds a temperature to fit, it was measured on a small, authored set, and it needs the owner's yes.

**RAHWEH:** Option C, both: softmax as the confidence, the gap as a veto for close races. The case: two independent checks agree before anything fires. The price: two rules to maintain and a worse chance of silence. PROPOSAL: B first in shadow, logging what it would have done next to the gap rule, then decide on real goals. NOT PROVEN on goals nobody wrote. OWNER DECIDES.

**THE NARRATOR:** Topic three: when does a learned edit become something the house believes?

**MAXINE:** Option A, a human reviews every edit, forever. The case: it is the standing rule, nothing the model suggests can change behaviour without a person, and it cannot be gamed. The price: it is the real ceiling on how fast the house learns, and review is slow.

**TOMO:** Option B, thresholds after enough evidence: a weight nudge inside a safe range is applied after, say, a set number of verified rows agree, and a human audits a sample. **RAHWEH:** Option C, wait. Build the other three edit types and their validators first, let real review entries pile up, and design promotion rules from what that pile looks like. The case: promotion rules written now would be guesses. The price: nothing speeds up meanwhile. PROPOSAL: C, with A staying in force. The class said it in night thirty and it is still true. OWNER DECIDES.

**THE NARRATOR:** Topic four: do all the NPCs share one bank of learned actions, or does each have its own?

**MAXINE:** Option A, one shared bank. The case: every NPC benefits from every verified row, learning is faster, and there is one authority. The price: characters become identical in behaviour, and one bad row spoils all of them.

**TOMO:** Option B, a bank per actor. The case: personalities, and a mistake stays local. The price: each actor learns from far fewer rows, storage and checking multiply, and there is no shared knowledge.

**RAHWEH:** Option C, layered: a shared base with a small set of per-actor changes on top. The house already has this shape, trunk and branch for shared data, decision eighty-seven, though the operation that builds it is not written. The case: shared learning with room for character, and one authority per fact. The price: it needs that operation, and a rule for which layer wins. PROPOSAL: C, and do not build per-actor weights until at least two NPCs actually need them. OWNER DECIDES.
