## 🧭 Taskbar vs TPMOS — spirit, form, and the honest gap

- **Spirit**: very close now for the ASCII-mirror slice. Same "capture writes, dispatch reads,
  render displays" philosophy, same marker-pulse discipline, same dual-rate (60Hz active / 10Hz
  idle) poll standard.
- **Form**: necessarily different — TPMOS's real shape is N independent sibling processes under
  one orchestrator; the taskbar is still mostly ONE process (`khtpm_strip_parser.c`) with Xlib
  event-loop dispatch, now with an opt-in alternate path rather than a true multi-binary split.
  This is an acknowledged, deliberate difference (see `taskbar-history-txt-migration-
  investigation.md`'s own "Phase 2 design" section) — not a gap to silently close, a real
  architectural choice still under evaluation.
- **What's NOT yet TPMOS-shaped**: bottom-tab-bar activation via relay (renders, doesn't activate
  yet — bigger shared nav-claims numbering system), `cli_io` typing support in the ASCII mirror,
  and the real X11 capture path is STILL the default (new mode is opt-in only).
