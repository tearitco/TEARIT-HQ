## The house rule

`*.monads/*.livedesk-taskbar/ops/khtpm_core_render.c` is the shared
X11/Xft renderer for db-hq, events-hq, chat-hai, open-hai, and
network-browser. **The renderer must never hardcode a per-project
mode** (no `g_is_<project>` branches for new work) — every new
capability is a generic, tag-based mechanism any `.chtpm` can opt
into. See `CENTROID_GOLD_STD.md` / `TPMOS-COMPLIANCE-DEBT.md`.

### 4 real, house-wide bugs found + fixed this session (2026-09-01)
All affect every sidebar+panel window, not just chat-hai — found via
live testing chat-hai, then confirmed to independently affect
open-hai's real running window too:

1. **`dispatch()`'s unconditional `g_quit=1`** after ANY plain `<item
   action=...>` silently closed the WHOLE window on one click (open-
   hai's Sound/Model-cycle toggles, chat-hai's Pause/Speed). Fixed:
   `g_default_has_sidebar_panel` latches true once a page uses the
   real dual-region layout; `dispatch()` skips the quit for those
   windows. `CLOSE`/`void` keep their own explicit quit, unaffected.
2. **Hardcoded 60px chrome drag-exclusion zone** — sized when `X` was
   the only chrome button; once `!`/`_` were added to its left, most
   of their clickable area fell outside it and got eaten as a
   drag-start (worked via keyboard nav, not real mouse clicks). Fixed
   to use `g_default_hide_elem`'s own real x as the boundary.
3. **Fatal, unhandled X `BadMatch` on `XSetInputFocus`** killed open-
   hai/chat-hai/network-browser outright once windows became
   optionally WM-managed (oc's z-order work, see below) — a managed
   window's map is asynchronous, so the existing post-map focus-retry
   loop could fire before the window was viewable, and X's default
   error handler calls `exit()`. Fixed by installing the existing
   `evhq_nonfatal_x_error()` handler globally (it existed but was only
   ever wired up for events-hq mode).
4. **Opacity changes required a full app restart** to take effect —
   entities (`tp_desktop_window_rgb.c`) already had live, event-driven
   reapply (`theme_changed_dirty()`); the exact same mechanism existed
   in `khtpm_core_render.c` (`pchq_theme_changed_dirty()`/
   `set_window_opacity()`) but was wired up for `pchq_board` mode
   only. Wired into the shared, every-mode per-tick loop instead —
   live-verified, opacity now updates instantly with no restart.

  window-switcher/dock, which an `override_redirect` window never is.
  This is expected, not clutter — confirmed live: it tracks real open
  windows exactly (hiding a window removes its dock entry).
- Real code: `khtpm_strip_parser.c` (respawn scan + `@` dispatch),

## How to do real injection testing on any khtpm window (house convention)

Never use scrot/xwd/synthetic XTest.
1. Find the window: `xwininfo -root -tree | grep <size>` (sidebar+panel
   windows default to 700x520).
2. Find the renderer PID: `pgrep -fa "khtpm_core_render.*<app>.chtpm"`.
3. Inject keys: decimal ASCII codes, one per line, appended (not
   overwritten — see below) to
   `#.desktop/entity_menu_history/<renderer_pid>.txt`. 32-126 =
   printable, 13 = Enter, 27 = Escape, 8 = Backspace, 200/201 = Up/Down,
   204/205 = Page Up/Down.
4. **Real gotcha found this session**: the relay file is genuinely
   append-only/cursor-based (never truncating) — repeatedly
   overwriting it with `>` across separate test commands produces
   unpredictable cursor behavior (stray/duplicate dispatches). Always
   append (`>>`), and if starting fresh, truncate ONCE with `: >`
   before the first real append, not between every step.
5. **Digit-key nav only reaches nav 1-9** — `ch >= '1' && ch <= '9'`
   sets `g_focus_nav` directly to that digit; for anything past nav 9
   (any window with more than ~8 sidebar/chrome items) you MUST use
   Up/Down (codes 200/201), not digits — sending a digit that doesn't
   correspond to a real low nav index can focus a stale/out-of-range
   `g_nav[]` slot and crash the renderer. This was the real cause of
   several apparent "crashes" investigated this session that turned
   out to be test-methodology bugs, not renderer bugs — always
   screenshot to confirm real focus position before pressing Enter,
   don't compute nav numbers from memory.
6. Screenshot via `dump_frame_png_op.+x <window_id_hex> <out.png>`,
   read the PNG directly.
7. Cross-check real backing state (`*_request.txt`/`*_state.txt`,
   `audit/<app>.log`), not just the screenshot.
8. `<cli_io>` needs arming first (first Enter/click), and a reparse in
   between silently disarms it — keep arm-type-submit sequences fast.
