2026-10-07, claude. The reviewer (`00-REVIEW-PACKET-APPENDED.md`) had **no source files** ("source-refs folder was not uploaded"), so several answers rest on my packet's wrong statements. ## A. Errors in MY packet (findings 2 and 5)
1. **"The active level is `mineclonia_sample`" is WRONG.** `board_config.txt` is a **dead key**: comments dated 2026-09-15 in `ops/pchq_board_projector.c` (~596-620) and `ops/pchq_board_action.sh` (~116-175) say nothing in the engine reads it for level selection and that earlier code writing it was "pure dead writes". The **real active map** is `pieces/world_01/state.txt` key `map_id` (empty or absent = the flat/procedural **default** world). The live `world_01/state.txt` has `map_id=test_walls` and `desk_id=desk1` (lines 11-12; **I first wrote that it had no map_id because I read only the first 8 lines; that was my error, corrected 2026-10-07**), so the loaded world is the **`test_walls`** map (seed 1789563438, tick 375), neither `mineclonia_sample` (stale board_config) nor the procedural default. So **the sun/chicken `default` level is NOT what pc-hq currently has loaded**, which is part of why it has not been seen from the desktop.
2. **"`open_pchq_board.sh` always opens at level 1" was misread.** That "level" is the **z floor**: the launcher resets the hero and xelector to `floor_z + 1` (floor_z from `board_manifest.txt`, currently 16). It is not a map. The launcher takes **no level argument** and does not read `board_config.txt`.
3. **The real map-load path** is the `CONFIRM_START_MAP:<map_id>` line appended to `pieces/system/widget_cmds/inbox.txt`, handled in `ops/pc_menu_input.c`, which runs `pc_generate_chunk.+x` (the File menu's `file-hq` / `load-map` verbs write exactly that line).
