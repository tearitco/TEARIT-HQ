## 1. Book:page harness (new)
**On disk (read from `livedesk_new_session`, `livedesk_new_desk`, `livedesk_ensure_session`, `livedesk_rename_desk`):** a book is `sessions/<id>/` with `session.pdl` (`STATE | name | <book>`, `STATE | active_desk | <page>`) and `desks/`; a page is `desks/<page>.pdl` (DESK rows). The taskbar creates them by menu rows `new-desk` (empty `desk_NN.pdl`, then switches to it) and `rename-desk`, and `new-session`.
**Deliver:** `book_page_op` (compiled C, one verb each): `new-page <book> <page>` (create the book if missing, create an empty page file, never overwrite, never switch the active page unless `--activate`), `list`, `exists`, `rename`, `--root <sessions root>` (default: refuse unless given, so a test cannot touch live data by accident), name validation (letters, digits, `-`, `_`), exit codes. **Two layers of proof:** (1) pal harness on scratch session roots (create, refuse duplicate, refuse bad names, book auto-create, files match what the taskbar writes byte-for-byte for a fresh page); (2) a **relay driver case** for a beta copy: drive the real taskbar menu (`new-desk`, then the rename modal) through `#.desktop/entity_menu_history/<pid>.txt` to create `pre-design:eden-test`, verified by reading `desks/eden-test.pdl` and the book/page labels (relay alone can mask focus bugs; confirm on hardware). ## 2. Eden game v1 on the conductor (alpha first, scratch house, then eden-test page)
Conductor 🔘 button: **Start / Stop** (and Pause, Save, Load, Status). **Start** spawns, from templates with fresh identities: **Asa, Ava, a house, 2 chickens, some plants (garden plots)**; kits per section 3 of the conductor doc; the game clock starts. **Stop** pauses the clock and (option) despawns game-owned entities, restoring nothing outside the manifest.
- **Events (RPG Maker style, data-driven):** day tick; hunger/needs; weather; plant growth and harvest; **chickens** (feed, eggs on a schedule; `evolution.pdl`: chicken -> cow -> horse as data rows with requirements, rideable later); **digging** (act `dig` at a spot; seeded finds table `finds.pdl`: stone, clay, **gold, silver**, with depth and tool requirements); **trading** between Asa and Ava (item and coin swap through the existing ledger ops); **talking through tomom** (below); build/house upkeep (shelter).
- **Talking through tomom:** each `talk` act asks the **tomom chatbot on its scratch copy** (seeded, repeatable; `tomom-hq` Ask path) for a line seeded from the speaker's word bank/topic and writes it to the listener's phone inbox and the game history; a deterministic phrase table is the fallback when tomom cannot answer (as today's v0). tomom's answers are runs of curriculum words, so lines will be odd; that is honest and logged. Never touches the live tomom folder.
- **Souls/ghosts** (conductor doc 11-12) are the later brain; v1 keeps the weighted agent seat.
- **100 save slots from the top toolbar:** `Save <n>` / `Load <n>`, n = 1..100, via `game_snapshot_op` (clock state and schedule ledger as `--extra`), slot labels with game day and a `slots.pdl` index. The pages cannot take arguments, so slot menus call the op directly with the number. **Toolbar:** a pdl-driven menu cell in the taskbar (`TASKBAR-MENUS-DATA-DRIVEN.md`) with paged slot lists (10 pages of 10) or a number prompt; whether it needs a change to the shared `khtpm_taskbar_manager.c` is checked first; if so it is rehearsed in beta only.
- **Playable loop acceptance (harness):** Start -> N game days with all events firing -> Save 7 -> mutate -> Load 7 == uninterrupted -> Stop; 100-slot save/load round trip; determinism by seed; invariants (conservation of items/coin, no negatives, spawned entity counts); a case shown able to fail.

## 4. Music daemon (game background music) and the roadmap entry
**Goal:** a small **music generation daemon**: synthesizer + sequencer that plays seeded, endless background music for the game and can be tuned later ("we can keep messing with it").
- **Steal from, in this order:** `103.media-studio/103.daw` (`daw_main.c`, Muchi DAW: tracks, piano roll, MIDI regions, mixer inserts, save/load), `@.apps/media-daw`, `@.apps/media-daw-hq` (manager), `@.apps/music-player-hq` (`music_player_manager.c`, `library.pdl`, action file). Audio players on this machine: `aplay`, `paplay`, `ffplay`, `sox`.
- **Design (house rules):** compiled C, self-contained; `music_synth` (oscillators, ADSR, simple filter, drum noise) renders 16-bit PCM from a **pattern file**; `music_seq` generates patterns from a seed + mood (`mood.pdl`: scale, tempo, chord progression, density, per-time-of-day and weather variants driven by the game clock); a daemon loops: read `music_state.txt` (mood, volume, on/off, written by game events), render the next bar or phrase, stream to the player (fork + exec + waitpid, no `system()`), append `music_ledger.txt`; kill switch is a flag file, not `pkill -f`. Every number is data. The conductor's Start/Stop and the weather/day events write the mood; the daemon never touches game state.
- **Joint contract:** tempo, density, scale weights and instrument mix are joints (bounded step, ledgered, gated, default autonomy 0); Heal = fall back to a fixed safe pattern on a render error or silence.
- **Proof:** a harness renders a pattern headlessly to PCM and checks length, sample range (no clipping), determinism by seed, the right pitches by simple zero-crossing/frequency analysis, mood changes alter output, and the daemon starts/stops on its flag file without leaving a process. Listening quality is NOT verified by a harness.
- **Roadmap placement:** Area R in `XO/.../02-ROADMAP-TECHNICAL-SPECIFICATION.md` (added).
