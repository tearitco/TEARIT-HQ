# PALCRAFT design spec (v1)

**2026-09-15.** A Minecraft-inspired "desk" built on piececraft-hq's
existing real voxel world — camera, movement and possession stay
piececraft-hq's own, all block/interaction behavior is scripted as
real, auditable RPG Maker-style Common Events, so nothing about this
desk needs new house architecture to be testable by agent relay.

## 0. What already exists (the real starting point)

PALCRAFT is **not** a new engine. It's a new *map + a real block-event
catalog* layered on the piececraft-hq stack that's already live:

- **World/voxels**: `@.apps/piececraft-hq/pieces/world_01/` — real
  voxel chunk data, generated by `ops/pc_generate_chunk.c`, composited
  by `ops/pc_compose_frame.c`. `world_01/animals.txt` already has one
  live test entity: `chicken,6,10,17` (x,y,z).
- **Camera/movement/possession**: owned by board-viewer's
  `bv_menu_input.c` (the 1-4→5-8 camera-key remap, per this session's
  own `pchq-camera-pov-keys` memory), shared into piececraft-hq via
  `pchq_board_projector.c`. Movement is driven through the **xelector**
  entity (`pieces/xelector_01/state.txt`, `pos_x`/`pos_y`), and
  advances the turn counter per `PCHQ-ENTITY-MENU-AND-TASKBAR-DESIGN.md`.
  **PALCRAFT reuses this verbatim — no new camera/movement/possession
  code.**
- **Voxel removal** already exists as a real input handler:
  `ops/pc_menu_input.c` (~line 806, `"Removed voxel @ %d,%d,%d"`).
  PALCRAFT's own block-*placement* is the real, symmetric gap (see §3).
- **Launcher**: `@.apps/piececraft-hq/open_pchq_board.sh` — real
  x11-hq single-instance launcher (kills any existing board+projector,
  builds on demand, launches `pchq-board.xhtpm`). PALCRAFT is a new map
  + xhtpm variant launched the same way, not a new launcher family.
- **Block palette source**: `#.ref/menu/event-guides/mineclonia/`
  (`interact.pdl` + `mcl_core.pdl`) already catalogs every Minecraft-
  style block/interactable as a real, pipe-delimited row (id, texture
  path, trigger type, RMMV DB, command list, missing-feature notes). A
  worked full example event package already exists:
  `#.ref/menu/event-guides/examples/mcl_chest/`. A sample map already
  wired to these tiles exists:
  `@.apps/piececraft-hq/pieces/system/maps/mineclonia_sample/events.pdl`.

## 1. Edit mode vs Play mode

- **Edit mode** = default. Every block placement/removal is a direct,
  inspectable data edit (voxel grid + a Common Event binding), the same
  as any other house map editor — nothing hidden, nothing compiled
  that isn't also sitting on disk as real `.pdl`/`.ir.pdl`.
- **Play mode** = piececraft-hq's existing possession/movement loop
  runs live against that same data; ON is however piececraft-hq's own
  desks already gate play vs edit today (reuse that toggle — **Grok:
  confirm the exact existing mechanism in `pc_menu_input.c`/
  `PCHQ-ENTITY-MENU-AND-TASKBAR-DESIGN.md` before inventing a new
  PALCRAFT-specific flag; if one already exists, wire into it, don't
  duplicate it**).
- The auditability requirement (user's own words: "each behavior and
  block is auditable in edit mode") is satisfied by construction as
  long as §2/§3 are followed — every block's behavior is a real,
  on-disk Common Event, openable in the existing events-hq editor, not
  logic baked into PALCRAFT's own C/renderer code.

## 2. One Common Event package per block type (confirmed convention)

Matches `common_events/cdda_beartrap_touch/` exactly:

```
common_events/palcraft_<block_id>_<trigger>/
  event_pkg/pages/page_1/event.ir.pdl   <- real IR script (NODE rows)
  event_pkg/pages/page_1/condition.pdl
  event_pkg/pages/page_1/text_1.txt     <- if show_text is used
  event_pkg/pages/page_1/cmd_1.sh       <- compiled runnable
  event_pkg/pages/page_1/event.pal      <- compiled PAL (sibling to .ir.pdl)
  interact_relay.txt, history.txt, master_ledger.txt
```

Compile chain (unchanged, real, existing):
`event.ir.pdl → event.pal → cmd_N.sh` via
`&.widgits/events-hq/ops/khtpm_events_hq_manager.c`.

- `<block_id>` = the mineclonia `TILE | id=...` value (e.g. `chest`,
  `furnace`, `tnt`).
- `<trigger>` = mineclonia's own `trigger=` column (`on-click` |
  `parallel`), so the dir name alone tells a reviewer when it fires.
- v1 scope: port the mineclonia rows whose `need=` column is already
  `-` (no missing renderer feature) first — `sign`, `crafting_table`
  (verify), etc. Rows with a real `need=` gap (`shop_processing`,
  `transfer_player`, `set_move_route`, `fadeout`/`fadein`, `play_se`)
  are real, flagged follow-up work, not silently stubbed — track them
  in a `## Deferred (need= gaps)` section Grok appends to this doc as
  it works through the catalog, not swept under a TODO comment in code.

## 3. Block placement (the real, symmetric gap)

`pc_menu_input.c` already has voxel *removal*. PALCRAFT v1 needs real
voxel *placement* wired the same way: pick a block id from the
palette (mineclonia tiles, `#.ref/.../mineclonia/interact.pdl`), place
a voxel at the aimed cell, and — if that block id has a Common Event
package under `common_events/palcraft_*`— bind it so the existing
interact-relay dispatch (same mechanism `cdda_beartrap_touch` already
uses on touch) fires it. **This is new C work in `pc_menu_input.c`/
`pc_generate_chunk.c` — flag it explicitly in your first co-lab post so
Sonnet can review the diff before it lands, per house standard for
`khtpm_core_render.c`-family files (though this specific file is
piececraft-hq's own ops, not the shared renderer — still coordinate,
same reasoning).**

## 4. World/session model (already answered, not open)

Desks are per-user/per-session under the existing file-hq convention,
same as every other desk — **not** a new shared/house-wide world like
dsr or civ-test. No new session-scoping code needed; PALCRAFT's map
just lives under the same per-user desk path every other desk uses.

## 5. Palette UI

Reuse the existing mineclonia tile picker (already palette/event/nav-
friendly per the user's own requirement) rather than building a new
block-picker widget. If it needs a PALCRAFT-specific filtered view
(only blocks with a landed Common Event package, say), that's a real,
small, additive view on top of the existing picker data — not a fork.

## 6. Testability (the actual point of this whole doc)

Every real requirement above reduces to: nothing in PALCRAFT should be
testable *only* by looking at rendered pixels. Concretely, agent relay
must be able to:
- read `common_events/palcraft_<id>_<trigger>/event_pkg/.../event.ir.pdl`
  directly to audit a block's behavior (real text, no rendering needed),
- drive placement/removal/possession through the existing relay file
  mechanism (`#.desktop/entity_menu_history/<pid>.txt`), same as any
  other khtpm-family window,
- confirm world state via the real, plain-text voxel/entity data files
  (`animals.txt`-style), not a screenshot.

If a Grok PR ever requires *only* a screenshot to verify what a block
does, that PR is out of spec — say so directly rather than merge it.
