**Real bug found + fixed along the way** (`16710365`):
`livedesk_splash.c`'s "BUILD FAILED" banner was a false positive on
nearly every build — it checked the `.build_failed.txt` dead-man's-
switch marker unconditionally from t=0 and latched permanently on
first sighting, but the marker is *supposed* to be present for the
whole build by design. Fixed to only check at the two real decision
points (all binaries fresh; timeout). **Note**: this fix needed one
extra rebuild cycle to take effect, since `build_khtpm_strip.sh` reuses
an already-built splash binary to show its own progress and only
rebuilds it later in the same run — already done, confirmed clean on
the next build after.

**Real process lesson, worth keeping**: pixels and receipts (text
state files like `strip_ui.txt`) are not the same evidence. A text
receipt updating does not prove the drawn pixels have caught up — a
frame dumped immediately after a khtpm restart can show stale content
from the previous window (same X11 window ID can persist across
restart; backing-store lag). Wait for an actual repaint before
trusting `dump_frame_png_op` output as proof.
