## 4. Landmines learned today (read before building)
- **Control flag flips by itself**: `state/flag_ctl`/`flag_follow` flipped pet->player and then INT arrows only moved the xelector (follow_xelector bails when the controlled entity has no placed position). Tab no longer toggles; a `state/ctl_trace.txt` names each change. Cause not proven. Copy the *fixed* daemon, not the old one.
- **Key path**: the board window's In: tab relays keys to the ENGINE session's files (`bv_h1`/`bv_h2` in the board's `state/ui.txt`); the daemon does not read them. The engine moves the xelector; the daemon moves the chosen character toward it (`follow_xelector`) and reads Enter from the engine session's `pieces/keyboard/history.txt`. Do not "fix" arrows by reading `state/interact_relay.txt`.
- **pc-hq instance isolation**: `PCHQ_PKG` = data root, programs stay in `@.apps/piececraft-hq`; a new instance needs `pieces/registry` (HUD font) or the HUD is black on black.
- **CPU**: a board window was 25-30% of a core (reparse + CSS + layout on every clock tick) and was cut to ~14% (`03-pitfalls/hq-cpu-safety.md` section 5). New games must not publish a fast-changing label into the window's vars (clock label at most once per 5 s) and must not poll files at 10-60 Hz (use `kh_state_notify.h`, branch `marker`, not yet merged).
- **Hotbar/windows**: vars-positioned windows are created unmapped and mapped when placed; restart swaps the hotbar make-before-break; minimized state persists in `#.desktop/hq_minimized.pdl`.
- **House rules**: C or pal for window logic (Python only for one-off converters); no symlinks; never `git add -A`, commit own paths only, own branch, never touch `xyzfs/users`; never report a number or "done" without a fresh build, a run and evidence (screenshot/state file); marker (size growth) not mtime; never kill the owner's windows without asking.
