## 2️⃣ UUID + xyzfs on signup

### Decision
Character creation **out of scope**. Every human gets:
1. Friendly login name (`user_id`)
2. **Unique UUID** (fs key)
3. Private tree `xyzfs/users/<uuid>/`

### Layout
```
00.login-signup/
├── users/<user_id>/profile.txt     # login name + uuid= + xyzfs_path=
├── current_login.txt                # current_user_id / uuid / xyzfs
└── xyzfs/
    ├── bin/                         # reserved
    ├── session.pdl                  # (sprint 6) guest vs logged_in
    └── users/<uuid>/
        ├── meta.txt
        ├── home/                    # exchange/, net/, later avatars/
        └── projects/
```

### Code touchpoints
| File | Behavior |
|------|----------|
| `ops/userpal_create_account.c` | Mint UUID (`/proc/sys/kernel/random/uuid`), write profile, mkdir xyzfs tree, auto-login |
| `ops/userpal_login.c` | Load uuid/xyzfs into `current_login.txt`; backfill UUID on legacy profiles |
| `ops/userpal_logout.c` / `whoami.c` / `compose_frame.c` | Clear or display uuid/xyzfs fields |
| `button.sh` | Durable `xyzfs/` + session symlink hygiene |

### How to audit manually
```bash

export PRISC_PROJECT_ROOT="$(pwd)"
./ops/+x/userpal_logout.+x
./ops/+x/userpal_create_account.+x alice "Alice"

```

**Association:** UUID is the **filesystem identity**; login name is **human-facing**. Avatar trees hang off the UUID path later.

## 4️⃣ Avatar menu FX — why menus were dead

### Root causes
1. **`${piece_methods}` empty** — `active_target_id` in `pieces/apps/player_app/state.txt` stayed `main` on faucet/store/avatars screens, so METHOD rows from those `piece.pdl` files never loaded → UI showed **[No Methods]** or inert buttons.
2. **Panel empty** — layouts referenced `${panel_content}`; compose only wrote `game_map` / `view.txt`.

### Fixes
| Fix | Where |
|-----|--------|
| `write_chtpm_bridge()` (muchi pattern) | `ops/avatar_menu_input.c` — on idle/sync, set `active_target_id` from `current_layout.txt` basename |
| Fill `panel_content` from `view.txt` | compose / parser side so status + DNA show in panel |
| DNA cycles on avatars detail | Select clone → cycle gender/skin/hair without dead-end |
| KEY dispatch | CHTPM sends ASCII codes (`'2'` = 50), not integer 2 — harnesses must use correct keycodes |

### Harness
```bash
cd 0.user-pal👤/01.avatar-creation👤
bash test-harn-same/scenarios/demo_menu_fx.sh
# Expect: claim → wallet+10; free starter → inventory UUID; select → cycle skin; open window process
```

### How to audit manually (GUI)
1. Log in (sprint 1–2).
2. `01.avatar-creation` → **Faucet** → Claim Tokens (message + wallet).
3. **Store** → Free Starter (new row under Avatars).
4. **Avatars** → select → Cycle Skin / Gender; watch face emoji + `state.txt`.
5. **Open Desktop Window** → process `system/avatar_window` (then kill on quit).

**Association:** CHTPM layout file name ↔ `active_target_id` ↔ `projects/.../pieces/<id>/piece.pdl` METHOD list ↔ KEY:N onClick → `avatar_menu_input.+x`.

## 5️⃣ Kill-on-quit / 60fps safety

### Problem
Desktop `avatar_window` and chtpm poll ~16ms. Quitting the terminal without reaping left cores warm. Stale `window.pid` files lied about liveness.

### What landed
| Mechanism | Path / behavior |
|-----------|-----------------|
| Soft stop | `quit_flag.txt` for poll loops |
| Ordered kill | SIGTERM UI trio + windows → ~0.3s grace → SIGKILL |
| Tracking | `open_avatar_window` writes `window.pid`, appends `pieces/system/avatar_window_pids.txt`, replaces prior window for same clone |
| `button.sh kill` / `kill-windows` | Full vs windows-only |
| `EMERGENCY_KILL.sh` | Match `/proc/pid/exe` **basename** (not cmdline) so Chrome/`-f` self-match avoided |

### How to audit manually
```bash
cd 0.user-pal👤/01.avatar-creation👤
./button.sh run
# Open a desktop window from Avatars
./button.sh kill
# Verify:
for n in avatar_window chtpm_parser_pal keyboard_input prisc+x; do
  pgrep -x "$n" && echo STILL:$n || echo OK:no_$n
done
find . -name 'window.pid'
```

**Association:** Any freeglut/GL clone with `glutTimerFunc(16)` has the same rule — **kill when not testing**.

## 6️⃣ `xyzfs/session.pdl` + character → desktop window

### session.pdl (machine-wide “who am I”)
Path: `00.login-signup/xyzfs/session.pdl`

| STATE key | Meaning |
|-----------|---------|
| `mode` | `logged_in` \| `guest` |
| `user_id` / `user_uuid` / `display_name` | identity |
| `xyzfs_path` | relative e.g. `xyzfs/users/<uuid>` |
| `logged_in_at` | unix time |
| `active_avatar_uuid` / `active_avatar_path` | last minted or opened clone |

**Writers:** login (logged_in), logout (guest), `generate_clone` (sets active avatar), `open_avatar_window` (refreshes active).  
**Readers:** avatar-creation prefers session.pdl → else `current_login.txt` → else guest fallback.

### Desktop spawn
`open_avatar_window` forks `system/avatar_window` (muchi `egg_window` lineage). Child does `setsid` + redirects stdio to `/dev/null` so harness pipes don’t hang.

### Harness
```bash
bash 0.user-pal👤/01.avatar-creation👤/test-harn-same/scenarios/demo_session_character_window.sh
# Proves: guest → logged_in → mint → active_avatar_* → LIVE avatar_window → cleanup
```

### How to audit manually
```bash
LOGIN=0.user-pal👤/00.login-signup
cat "$LOGIN/xyzfs/session.pdl"
# After login: mode=logged_in, non-empty user_uuid
# After mint/open: active_avatar_uuid set
# After logout: mode=guest, empty user fields
```

**Association chain:**
```
login → session.pdl + current_login.txt
     → generate_clone → xyzfs/.../home/avatars/<aid>/ + map_lobby/<aid>/
     → session.pdl active_avatar_*
     → open_avatar_window → GL process + window.pid
```

# Part C — How TTG-tactics is mutaclysm-aligned (pre-handoff design → early build)

This is the interesting architectural contrast: **freeglut clones look flashy; TTG was specified to obey muta law from day one.**

## Mutaclysm signal flow (gold standard)

```
keyboard_input  →  history.txt   (decimal keycodes; humans, AI, harness write THE SAME file)
       →  dispatch / chtpm_parser / interact
       →  ops (+x binaries) mutate state
       →  data/master_ledger.txt  +  entity dirs (pieces/units/*/state.txt)
       →  compose_frame  →  pieces/display/current_frame.txt     [ASCII = truth]
       →  rgb compose    →  rgb_frame.raw
       →  system/renderer (terminal)  +  system/gl_mirror (GL blit only)
```

**Laws (from handoff L1–L10, compressed):** dual ASCII+GL · file-mediated · same input path · master ledger · human-readable maps · entity directories · tick/turn frames · nav-friendly UI · kill hygiene · **no freeglut product brain**.

## How DESIGN.md maps onto those laws

| Muta law | TTG design / early code |
|----------|-------------------------|
| Dual view | Frame **48×22** composed to `current_frame.txt` **and** `rgb_frame.raw`; vendor `gl_mirror` / `renderer` from muta |
| File-mediated | `ttg_loop` polls files; no sockets for core loop |
| Same input path | Append keycodes to history; AI must emit keys only (design); harnesses append keys |
| Master ledger | `data/master_ledger.txt` append on move/attack/end |
| Human-readable board | 12×12 tactics grid in ASCII frame + unit state files |
| Entity dirs | `pieces/units/<id>/state.txt` (side, role, hp, pos, moved/acted flags) |
| Turn / tick | Turn ring + clocks (2/5/10/30); flags `moved`/`acted` |
| Nav-friendly | Cursor + numbered/key path (Enter select/move, arrows, A attack, E end) |
| Kill hygiene | `button.sh kill`, exact names |
| No freeglut product | Explicit non-goal for product path |

## Product shape (still early)
- Community-role pieces (MVP army: King + Soldiers + Wizard + Farmer per side)  
- Wider than chess **12×12** · Chebyshev attack · BFS move · regicide  
- Ante **tablechips** pot · Elo K=32 · AI difficulty tiers (key-only)  
- Modes designed: 1v1 hot-seat MVP; 2v2 / 4-FFA / story later  

## What’s implemented vs design-only
| Layer | Status |
|-------|--------|
| DESIGN.md rev 2 | Approved (0 open review issues) |
| `ttg_loop` + compose dual | Live |
| Unit dirs + ledger | Live |
| Harness 01 move / 02 illegal / 03 regicide | **PASS** |
| Clocks polish, pot settle UI, Elo file, pure key AI | Still open |
| Full roster / story / vehicles | Phase 2 |
