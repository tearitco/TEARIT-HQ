- **Menu order** is now Tao Te Ching, Proverbs 31, TTS, text. It lives in three places (`choices.objects.pdl`, `choices.chtpm`, the `case` in `dispatch.sh`).
- **Root cause of both bugs** is the earlier design `2026-10-30-BOOK-STACK-PROVERBS31-DESIGN.md`, whose snippets use `../` x7; both branch scripts were copied from it. That doc now carries a correction note.

## 3. Target: the reader is one book (MINE)
Vocabulary from `BLUEPRINTZ-DESIGN.md` section 2: book = set of pages, page = desk with events, event = `event_pkg` of command lists (`event.ir.pdl`), commands come from the live registry (`#.ref/menu/event_commands.registry.pdl`, which already has `show_text` and `show_choices`).

**Book `reader`:**
- **Page `menu`**: one event `pick` = `show_choices` over the rows of `sources.pdl`, then a conditional per choice that calls the matching common event. The menu text and order come from the data, so reordering is a one-line data change.
- **Common events** (reused, not per-branch scripts): `show_verse(text)` = `show_text`; `speak(text, voice)` = one op call; `random_chapter(source)`; `daily_by_day(source)`.
- **Data, not code:** `sources.pdl` (`SOURCE | id | label | order | kind | data`), `verses_proverbs31.pdl` (`V | day | en | zh`), `asset_roots.pdl` (`ROOT | machine | key | path`, one resolver replaces the 3 copied path hunts; env override stays first).
- **Ops (C, one job each):** `asset_root_op` (resolve a key to a path, mount the share if needed), `verse_pick_op` (random chapter / by-day / bible verse, prints wrapped text), `speak_op` (forks `pet_tts_local.py` niced, plays with `paplay`). Python stays the existing synthesis drop-in until a C path exists.
- **Adding a source** (say Psalms of the day) = one `SOURCE` row + one data file. No new script, no new menu edit.

## 4. Layouts (MINE, from `IN-GAME-LAYOUTS-PLAN.md`)
- The choices menu and the text popup become **layouts** rendered inside the game window instead of floating windows (the plan's own goal: in-game, minimize with the board, stay inside the viewport). They are `.chtpm` documents generated by the layout studio (`@.apps/layout-studio`), saved by name (`reader-menu`, `reader-text`) and called from the event commands.
- Text wrapping belongs to the layout (a text region with a width in characters), not to `fold` in each branch. This fixes the Chinese wrap bug for good.
- Dependency: the plan marks in-game drawing as proposed; layout studio is built through layers 1-2 only. So the **first cut keeps the existing floating `show_text` / `show_choices`** (they are registry commands already) and swaps in the layouts when the studio can place a text region.

## 6. Risks
- **blueprintz is a shell today** (B0 done, B1 read-only tree partly); R2 can proceed with events-hq alone and only gets the book view when B1 lands. Do not build the reader's own editor.
- **Two event stores** (desk events vs app-local packages): the reader is app-local, which blueprintz must read anyway (design section 2).
- **Asset share** is a mounted partition; the resolver must fail loudly (one visible line), because the old silent skip is what hid the TTS bug.
- **Fire-and-forget `show_text`**: no "wait for dismiss", so a command after it runs at once. Fine for the reader (Show Text is last); needed before using it elsewhere.
