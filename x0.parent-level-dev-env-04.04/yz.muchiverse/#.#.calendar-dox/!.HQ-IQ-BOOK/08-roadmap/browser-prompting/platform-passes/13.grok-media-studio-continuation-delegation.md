## 1. The decision (MADE — do not re-litigate)

**Option B: convert to house spec now.** Real generic `nav_index` /
sidebar+panel, file-backed state, a thin manager process, shared
`khtpm_core_render.+x` for all rendering. This is a *migration of
existing content onto the current standard*, the same class of work as
the network-browser conversion — **not a redesign**.

Why B and not "keep building fast": every out-of-spec app is a future
merge cost AND its own bespoke context doc every time it's handed to a
browser-window AI. House-spec code is exactly what
`1.platform-primer-ALWAYS-ATTACH.md` already describes in one upload,
so future prompts stay small. It is also **Windows-handoff prep**: a
house-spec app rides the shared renderer, so when the renderer gets
its platform seam (`08-roadmap/design-docs/CROSS-PLATFORM-SEAM-AND-
SHARED-INFRA.md` Part 2) these come along for free; an out-of-spec app
needs its own port.

## 3. Target shape per app (house spec)

Copy the **`&.hq-apps/co-lab-hai/`** app verbatim as the structural
template — it is the newest, cleanest full example:

```
<app>/
  button.sh              # launches: khtpm_core_render.+x <house> <app>/<app>.xhtpm
                         #  after spawning the manager (see co-lab-hai/button.sh)
  <app>.xhtpm            # static template: <window><page><sidebar>+<panel>, nav via
  <app>.css             #  generic <item>/<text>/<cli_io> — NO hand-built Elem tree
  ops/<app>_manager.c   # thin manager: parse argv (<house> <pkg> [id]), loop,
                        #  poll <pkg>/state/<app>_action.txt (seq=N / cmd=...),
                        #  publish <pkg>/state/<app>_ui.txt. Business logic ONLY here.
  ops/build_<app>_manager.sh
  ops/<app>_action.sh   # tiny shim: write seq+cmd to the action file
  toy.pdl               # title=<Name>\nlaunch=button.sh   -> makes it appear in HQ toys
```

**Manager reference:** `&.hq-apps/co-lab-hai/colab_hai_manager.c`
(and `&.widgits/palettes/ops/elements_palette_manager.c` for a smaller
one). Use `&.widgits/_shared-lib/kh_plat.h` for sleep / monotonic
clock / mkdir / spawn / terminate-signals so the manager carries no
`#ifdef _WIN32` (see `CROSS-PLATFORM-SEAM-AND-SHARED-INFRA.md` Part 1).

**HQ toys registration:** the toys menu (`khtpm_taskbar_manager.c`
`toys_scan_one_root()`) scans `house_root/`, `@.apps/`, `&.widgits/`
**one level deep** for any dir containing a `toy.pdl`. `103.media-
studio/<app>/` is two levels down, so the converted apps must either
live in `@.apps/` (preferred — that's where `piececraft-hq`,
`aomorai-editor` live) or a 4th scan root for `103.media-studio/` gets
added. **Recommend: move each converted app to `@.apps/media-<name>/`**
and leave a one-line pointer in the old `103.media-studio/<app>/`.
Confirm the placement with the owner in the first prompt.

  review before writing it.
