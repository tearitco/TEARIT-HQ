# 🪟🍎 Grok — Windows/Mac Compatibility Catch-Up — delegation map

**Goal:** bring Windows usability back up to date after heavy Linux-focused refactors drifted it
out of sync. Some shims exist but are UNTESTED since the refactors.

## 🧠 Real, house-standard cross-platform rules to give Grok up front (from TPMOS's own real
standards — these are proven, not aspirational)

- `#ifndef _WIN32` for Linux/macOS blocks, `#ifdef _WIN32` for Windows — NEVER refactor established
  POSIX logic "to clean it up" for Windows compat. Surgical wraps only.
- Linux: `fork()`+`exec()`+`waitpid()`. Windows: `_spawnl()` with `_P_NOWAIT` (shared console) or
  `_P_DETACH` (background daemon).
- Linux orchestrators block on `pthread_join()`. Windows needs a persistent
  `while(!should_exit) { Sleep(100); }` loop instead — detached Windows processes return
  immediately, unlike Linux's join-based lifecycle.
- Path separators: `/` for all internal logic/`fopen()`, only convert to `\\` for native Windows
  `_spawn`/`system()` calls.
- `setpgid` has no Windows equivalent — Windows signal handling needs explicit `taskkill` or
  tracked-PID cleanup to avoid orphaned processes.
- Hardcoded Linux font paths will crash Windows — always provide a `C:/Windows/Fonts/` fallback
  or a graceful no-asset exit.
