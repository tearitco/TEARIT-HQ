## 1. Scope now and later
| | NOW (phone only) | LATER (SAID: "all toys/apps not already included in the install") |
|---|---|---|
| What the repo holds | phone app PACKAGES (`manifest.pdl`, `icon/`, `screens/`, source `ops/*.c`): True Swords Clash, stock+x, later the WSR app | every LyfeDesk toy / HQ app / widget that is NOT part of the base install, same catalog, same checks; the package format for those is not designed yet (they are not `+phone` packages) |
| What ships in the base install | the shell, `settings`, `appstore` (the two base phone apps) | the house's core (taskbar, renderer, rpg-edit, ...) stays in the install; anything optional moves to the repo over time |
| Installed by | the App Store app on the phone (and `phone_op install` for scripts) | a desktop store window / the same verbs, DOC |
The phone code must not assume "phone" in the catalog and trust layers (a `KIND | phone-app` field per entry), so the later toys/apps are new kinds, not a new store.

## 2. What already exists (READ)
`phone_op install <house> <package_dir>` (runs `app_check` first; refuses on any failure; copies beside then renames; republishes every open phone), `phone_op uninstall <house> <id>` (refuses `settings`), `app_check` (format validator), `app-edit` (the IDE whose projects folder is `&.hq-apps/app-edit/projects/<id>/` and whose export installs). Package = a folder named after the app id. `settings` is a show-only app (PIN first). There is NO store UI and NO remote source today.

## 3. The App Store app (DOC)
A normal phone app (`appstore`, `PIN | first`, system app like settings) with one screen: a list of catalog entries, each a button `install <Title>` or `remove <Title> (installed)`, a status line, and the phone's stack (phone bars, app chrome row, phone bottom bar). It has its own projector (the `tsc_op` shape: a module that publishes `ui.txt`, a few UI verbs `ui_install <id>`, `ui_remove <id>`); the verbs call `phone_op install|uninstall` (fork/exec with a watchdog) and write the result line the screen shows. System apps (`settings`, `appstore`) are never offered for removal.
**Catalog sources (data, so a new source is a row):** (a) `LOCAL`: the app-edit projects folder (stage 1, no network, the test bed); (b) `GIT <url> <commit>`: a git repo at a pinned commit (stage 2). `phone_prefs.pdl` rows `STORE_SOURCE | local` and `STORE_SOURCE | git | <url> | <commit>` (a preference, never state).

## 4. The approved-apps repo and the trust model (DOC; this is a supply-chain surface: installing code onto a desktop)
**Repo layout:** `catalog.pdl` at the root (`ENTRY | <id> | KIND | phone-app | VERSION | <n> | SHA256 | <sha256 of the package tree> | NOTE | ...`), one folder per package (`<id>/manifest.pdl`, `icon/`, `screens/`, `ops/*.c`, a build recipe). **No compiled binaries** (the house rule: compiled programs are in no branch).
**Rules the store enforces, in order; any failure installs NOTHING and says which:**
1. **Pinned commit, never HEAD.** The store trusts a source only at the commit written in the local `STORE_SOURCE` row. "Approved" = the owner (or the owner-designated maintainer) merged the app into the repo AND the pin was updated on this machine. A newer remote commit is only a notice ("newer approved commit available"), never auto-applied.
2. **Fetch exactly that commit** over https (`git fetch` of the sha into a capped cache folder, or the tarball of that sha). Read-only: a plain GET, no login, no identity sent. The repo is PUBLIC (owner 2026-11-16, "like the others"), so no token or credential exists anywhere in this design; a private repo is out of scope.
3. **Verify** `SHA256` of the package tree against `catalog.pdl` (the catalog is part of the pinned commit), reject symlinks and paths outside the package folder.
4. **Reject prebuilt binaries** (any file that is ELF/executable in `ops/+x/`); only source is accepted.
5. **`app_check`** (the existing format validator).
6. **Build locally** with the house toolchain through `cpu_gate` (one heavy job at a time, niced), only the recipe in the package (`ops/build_<id>.sh`, same shape as `build_tsc.sh`); the recipe runs only after the owner sees the first install of that app version (a prompt, DOC) because compiling and running a package IS running its code.
7. **Install** with `phone_op install` (atomic), record a ledger row `INSTALL | id | version | commit | sha256 | ts` in the store's own ledger (the ledger is the authority for "what was installed from where"; the folder is a projection).
**Not covered, said plainly:** a malicious but correctly hashed package passes steps 1 to 5 because the owner approved it; the defence is review before pinning, and building/running only what you approved. There is no sandbox for a phone app today (it runs as the user).

## 5. Test plan (harness cases that can fail; pal + case + C ops; NO Python)
`appstore_local`: scratch house, the REAL `phone_op` and `store_op`, a fake projects folder with two packages: the catalog lists both, install makes the app appear in the picker list and its files in `apps/<id>/`, remove deletes them, `settings`/`appstore` are never offered for removal, a package that fails `app_check` is listed as refused with its reason and installs nothing, the screen buttons run the real verbs (control: a direct `phone_op install` gives the same result).
`appstore_git`: a LOCAL git repo built in the scratch folder (`file://` or a path), same flow: a pinned commit installs; a repo whose HEAD moved after the pin still installs the PINNED version (control: the new commit's content is NOT present); a tampered file (hash mismatch) installs nothing; a prebuilt binary in the package is refused; a symlink out of the package is refused; a missing commit is refused with a clear message; the network is never touched by the case.
Live: photographs of the picker with the store tile, the store screen, an install, the new tile; then ONE real fetch from the real GitHub repo once the owner has created it and put its url and commit in the prefs (the owner creates and pushes the repo; I do not).

## 6. Build order
1. (this turn) `appstore` app with the LOCAL catalog; a minimal `stock-x` package so it is listed; cases `appstore_local`.

4. LATER: other kinds (toys, apps) in the same catalog.

## 8. Dependencies ("dep"), owner 2026-11-16 (SAID): "verses is separate but will install dep if needed... a dep in meta .pdl, like a json npm file" (DOC design, not built)
**Why:** True Swords Clash needs a 4.6 MB Bible text that is NOT part of the app (the owner's translated file; whether it is published publicly is his decision, so it is a separate package that can be approved or withheld on its own).
**Manifest:** `manifest.pdl` gets rows `DEP | <dep id> | <minimum version>` (several allowed). `app_check` must accept the key (today an unknown key is an error) and check the id is a word.
**Catalog:** a dependency is a catalog ENTRY of `KIND | phone-dep` (a DATA package: files only, same rules as an app: no binaries, no symlinks, no `+x`, tree hash verified, same pinned commit). It installs to `&.hq-apps/plus-phone/deps/<id>/` (not into `apps/`, so it never shows as a tile) with a `version.txt`.
**Install:** `ui_install <app>` first resolves every `DEP` of the app: already installed at a high enough version = fine; else it must be a VERIFIED entry of the catalog, which is installed first (hash re-checked, ledger row `INSTALL|<dep>|...`); a dep that is not in the catalog = the app is NOT installed and the screen says `needs <dep> (not in the approved catalog)`. **Uninstall** of an app never removes a dep still named by another installed app's manifest.
**App side:** the app reads the dep from `deps/<id>/` (TSC's `load_verses` looks there first, then its own folder, so the owner's local copy still works).
**Tests (when built):** a package with a DEP installs the dep first (control: the dep is absent without the DEP row); a missing dep refuses the app and installs nothing; a dep with a wrong hash/ELF refuses the app; uninstalling one of two apps keeps the shared dep; `app_check` accepts DEP and refuses a bad id.
**Status 2026-11-16 (updated):** the repo `https://github.com/tearitco/lyfedesk-approved-apps` is public. First push was stock-x only (`2343adf`, history rebuilt to ONE commit so nothing was published by accident); after the dependency mechanism was built and the owner said "Yes, publish both", `1204e7e` added true-swords-clash and the `bible-verses` data package (proven by a real https sync + install from GitHub: verified=3, verses byte-identical to the owner's file).

## 9. Operating guide (2026-11-16, what is BUILT and how to use it; section numbers above are the design)
**Status:** BUILT and tested: the App Store base app (catalog, install + local build, remove), the git source at a pinned commit (`sync`, tree hashes, source-only rules, install re-hash, install ledger), dependencies (`DEP` rows, `phone-dep` entries, `deps/<id>/`), the sync and check-for-updates buttons, a shipped default source. Harness cases: `appstore_local` 27, `appstore_git` 53, `appstore_dep` 30 (+ `tsc_rules` 65, `plus_phone` 47, `app_package` 22). **Live repo:** https://github.com/tearitco/lyfedesk-approved-apps (public), pinned in `&.hq-apps/plus-phone/store_sources.default.pdl` at commit `1204e7e` (stock-x, true-swords-clash, and the data dependency bible-verses; published 2026-11-16 with the owner's explicit OK).
**A customer, step by step:** the install ships `apps/appstore` and the default pin; open the phone, open App Store, tap `sync approved apps` (fetches exactly the pinned commit, verifies each package against `catalog.pdl`), tap `install <app>` (dependencies first, then the app, then a LOCAL build with `gcc` through `cpu_gate`), optionally `check for updates` (reports a newer commit, never applies it). Needs `git` and `gcc` on the machine, Linux with the LyfeDesk X11 setup.
**Adding an app to the public repo (owner workflow):**
1. Work in `&.hq-apps/app-edit/projects/<id>/` (manifest, icon, screens, `ops/*.c`, `ops/build_<id>.sh`: the store runs exactly that script name). `app_check` it.
2. Copy the SOURCE to the repo folder (`/home/no/Desktop/github/work/lyfedesk-approved-apps/<id>/`), never `ops/+x/`, never a symlink, never data you do not want public.
3. Hash it: `&.hq-apps/app-edit/projects/appstore/ops/+x/store_op.+x treehash <folder>` and add `ENTRY | <id> | KIND | phone-app | VERSION | <n> | SHA256 | <hash>` to `catalog.pdl` (a data package the apps need: `KIND | phone-dep`, and the app declares `DEP | <dep id> | <min version>`).
4. Check before pushing: point a scratch house's `store_sources.default.pdl` at the local folder and its commit and run `store_op sync <scratch house>`; it must print `verified=N refused=0`.
5. Commit and push the repo, then MOVE THE PIN: put the new full commit id in `store_sources.default.pdl` (a release) and commit that in the house repo. A customer on an older pin keeps the old, verified set until they update.
**A dependency in practice:** True Swords Clash declares `DEP | bible-verses | 1`; its Bible text is a separate data package (`phone-dep`) so the owner can approve or withhold publishing it on its own. TSC and the verses package ARE in the public repo since 2026-11-16 (owner said "Yes, publish both"); the owner's house also has `deps/bible-verses/` (a byte-identical copy of his project file, gitignored) so local installs work.
**Not built / open:** orphan dependency clean-up, a dependency update path, a prebuilt-binary route for customers without a compiler (it would contradict the source-only rule: owner policy), grouping the 237-test harness list, other kinds (toys, apps) in the catalog.
**Pitfalls found while building it (also in the platform guide section 8):** a reinstalled app keeps its OLD projector until closed and reopened; a harness compile step that prints many warnings can fail the case (use `-w`); a case that copies the live `apps` folder breaks when anything is installed (copy fixtures); a harness list cap (menu op 48 rows, window 64 rows) silently emptied the Tools menu; `git commit` history of a repo you are about to publish may hold files you excluded later (rebuild a repo you created yourself; never rewrite one that others hold).
