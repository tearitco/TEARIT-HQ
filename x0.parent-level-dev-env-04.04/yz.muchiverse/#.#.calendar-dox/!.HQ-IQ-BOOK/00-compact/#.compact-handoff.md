The Cli-io text field itself is confirmed working live (direct user
report) - it's now a real inline `<cli_io>` element in every entity's

  `kh_set_default_input_elem()` (`khtpm_core_render.c`) arms it on
  Enter; the badge draw is in `&.widgits/_shared-lib/khtpm_draw_core.c`
  (~line 1107-1153, look for `is_scope`).
- Recipe (small-agent-guide.md §3's relay method): open any entity
  with a Cli-io row, find its PID (`ps aux | grep khtpm_core_render`),
  dump a frame first (`dump_frame_png_op.+x <window-id> <out.png>`) to
  see the real nav numbers, send `KEY_PRESSED: 200/201/202/203` (arrow
  codes) via `#.desktop/entity_menu_history/<pid>.txt` until the field
  is focused (badge should read `[>]`), send `KEY_PRESSED: 13`, dump
  again - badge should now read `[^]`.
- Write the result into `04-bugs/bug_bounty.md`'s existing pals-
  dropdown entry or a new dated entry, whichever fits; don't skip
  documenting it either way (open or closed).

square. Real recipe (already scouted, not guessed):

## 3. If something above looks already fixed, or already broken differently

Don't assume drift is your imagination. Check, in this order:
1. `git log --oneline -20` on `claude` - is there a commit past
   `b0187294` that already touches it?
2. `04-bugs/bug_bounty.md` - newest entries are at the TOP.
3. `12.calendar/2026-09-24/notes.md` - the day log this handoff was
   written from; it may have been updated since.

If you find and fix something new, follow the same pattern every real
fix in this session used: real root-cause comment in the code (with
today's date and what live report prompted it), rebuild, restart,
verify with real evidence (frame dump or direct confirmation - never
just "compiles clean"), commit scoped to ONLY the files you changed
(`git add <path>` per file, never `git add -A` - see AGENTS.md),
update `bug_bounty.md`/the day log, push to `origin/claude`.
