## 3b. Language rule: one voice, the OTHER language as subtitles, never both (SAID 2026-11-18)
The company has English and Japanese customers. A deck is made as a pair: **English voice with Japanese subtitles** (`-en-voice-ja-subs`) and **Japanese voice with English subtitles** (`-ja-voice-en-subs`). Never a voice and subtitles in the SAME language (redundant). The manifest caption is the subtitle text, so a deck needs two manifests (one per subtitle language) and one narration script per voice language; keep the two text sets side by side so they stay the same slides.
PITFALL (2026-11-18, RAN): the caption font is DejaVuSans, which has NO Chinese or Japanese glyphs: a CJK caption renders as empty boxes (seen in the first Teario deck). Japanese subtitles need a CJK font (Noto Sans CJK or WenQuanYi, both searched by the engine glyph code in `bv_cjk_glyph.c`) added as a fallback in the maker before any ja-subs deck.
NOT built or verified: `make_presentation_video.py` has no language option yet, and a Japanese Kokoro voice (needs the Japanese text front end for `kokoro-onnx`) has not been tried here; check it with a recorded level test before promising a Japanese deck. Today the caption strip shows the caption and the narration reads the same caption, which is exactly the redundant case to avoid.

## 5. A deck must show the real thing (house rules)
- Every slide is a real photograph of the running window with the state value next to it (`board_ctl snap` style receipts), not a mock-up. A slide with no picture is a lie by omission.
- Say what is proven and what is not on the last slide (label RAN / DOC).
- Never loop `ffmpeg`/`awk` over pixels (use a C op); heavy renders go through `cpu_gate` and `nice -n 15`.

## 7. ANIMATED game footage (2026-11-18, the Teario deck; `make_presentation_video.py` is STILLS ONLY)
Owner 2026-11-18, about a deck of stills: "VIDEO PRESENTATION SHOULD SHOW FRAMES ANIMATED, SHOW HERO JUMPING, KILLING ENEMY, CURRENTLY IT ALL LOOKS STILL". A game deck shows the game MOVING. RAN, with scratch scripts (they are not in the repo; a C op is the right home if this is repeated):
1. **Record:** play the run through the game's own buttons (`game_core ctl <verb> <games dir>`, inputs at the harness ticks) while a second loop dumps the editor window with `dump_frame_png_op.+x` (about 2.8 frames a second, niced) and appends `<n> <epoch seconds> <game tick>` per frame to a log. At normal speed (100 ms a tick, seen about 7 ticks a second) that is one frame per 3 ticks: choppy; at the SLOW speed button (250 ms a tick) it is about 0.75 frames per tick: smooth enough. 175 frames for the 241-tick Meadow clear.
2. **Cut by game tick, not by clock:** a scene is "the frames with tick a..b"; each frame is held for the real gap to the next frame (divided by a speed factor; the waiting stretch was 4x). A scene is held as long as its narration plus half a second (speed it up to 2.2x at most, then hold the last frame): that is how there is never silence.
3. **Subtitles and voice:** one line per scene, English voice with Japanese subtitles (rule 3b), burned in with ffmpeg `drawtext` and `/usr/share/fonts/opentype/noto/NotoSansCJK-Regular.ttc` on a Tear-it purple strip under the picture (gold text, red rule). Kokoro clips (`pet_tts_local.py --voice en-US-AnaNeural`) padded to each scene length; verify with `volumedetect` per scene (every scene read about -23 dB mean).
4. **Traps that cost runs:** the speed button and the human seat are PREFERENCES that PERSIST between games, so a blind `human_next` or `speed_next` cycles them to the wrong value (seat dropped to a pet, speed to fast): press until the feed label says `you play: p1` and `speed: slow`. The game ends on its own at the goal, so inputs at fixed ticks only work with the right speed and a human seat. A `pkill -f` or `ps | grep` with the pattern in your own command line kills your shell.
5. **The result:** XO nov-18 `11.teario-animated-en-voice-ja-subs/` (52 s: seven scenes of the real run, then the Make stamp bank).
